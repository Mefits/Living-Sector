# Стратегический ИИ: система, а не победитель одного бенча

## Желаемая структура

1. **Faction Head / глобальные приоритеты:** распределяет возможности между экономикой, наукой, экспансией, обороной, поддержанием жизни, дипломатией; держит выбранную стратегию и обязательства достаточно долго, не меняет её без новой информации. Utility — кандидат.
2. **Planner / причинные проекты:** знает каталог 18 ресурсов/29 сооружений/T1–T4, их исследования, реальные входы/выходы, энергию, стройматериалы, транспорт, работников. Для проекта есть предикаты доступности, цепочка зависимостей, несколько путей к одной цели, оценка риска и резервы. HTN, Beam, Telic — кандидаты, не фактические победители.
3. **Local Administrator A1:** распределяет работу реально существующим станционным модулям, формирует Need, не получает отдельный кошелёк.
4. **Dispatch A2 + Native BT:** физические корабли/строители исполняют реальные контракты; фиксируются груз, расходы, люди, ETA, ошибки. Они не изменяются напрямую абстрактным планировщиком.
5. **Memory/feedback:** после каждого завершения/провала учитываются фактическая стоимость, дефицит, неудача снабжения, изменение условий и причины перепланирования. Память должна сохраняться при перезапуске.

## Минимальный общий контракт

```text
WorldView: tick, systems, body deposits, station slots/modules, owners, routes,
           markets, stocks, production recipes, power, technology, research,
           populations, workers, budgets, known threats, commitments.
CandidateAction: stable id, actor/faction/site, native supported?, prerequisites,
           inputs, cost/ticks/labor, effects, expected duration, risk.
Intent: policy/domain, target, urgency, value, commitment deadline, reason.
Plan: stable plan id, subtasks/dependencies, active steps, resource reservations,
           alternatives, cancellation conditions, stable executor references.
Outcome: completed/blocked/partial/rejected, real deltas, transaction receipts,
           prediction errors, retry/rollback options.
```

**Два адаптера:** к реальной C1 ECS/SQLite (исполняемые действия); к Balance/100-system headless (виртуальная физическая симуляция). Планировщик не должен знать устройство UI/EXE, а правду о деньгах/ресурсах сообщает только исполнительная среда.

## Целеполагание

Не делать «построить Сферу Дайсона» глобальной обязательной победой. Система может использовать веса: выживание (жёсткое условие), независимость снабжения, рост знаний, индустрия, население и благополучие, территориальное развитие, оборонная готовность, стабильные финансы и сохранность ресурсов. Вес зависит от характера фракции и реально достигнутых состояний. Нужны штрафы за остановки и потерю населения, а не просто за медленное действие.

**Внешняя оценка соревнования:** за фиксированное ИГРОВОЕ время, а не фиксированные 140 кнопок с разным временем исполнения. Учитывать разные стили развития и не создавать один бесконечный источник «лёгких очков» (солнечные ячейки, искусственные ожидания, продажа активов). В отчёте отдельно показывать planner CPU/wall-time.

## Предварительный выбор по имеющимся данным

Нет обоснованного единственного фаворита. Utility дал локальные полезные решения, но без T2 и с повторением однотипного выпуска; HTN не добился действия в заданном сценарии; Beam, Telic Beam, Cranium+Telic повторили одну трассу. Окончательное решение требует повторного тестирования с исправленной постановкой и одинаковыми исходными мирами.
