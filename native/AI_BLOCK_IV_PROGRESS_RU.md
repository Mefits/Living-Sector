# Living Sector — Блок IV: колонизация и реальные длинные цепочки

**Основа:** `LS-AI-BLOCK-III-SOURCES.zip` (I+II+III). **Дата:** 10 ноября 2026.  
**Статус:** только исходники подготовлены; Cargo, новые серверные бинарники, Node/Python тесты и игровые прогоны НЕ запускались по решению пользователя. Нельзя считать функциональность подтверждённой игровым экспериментом.

## 1. Что добавлено

1. **Послеоснóвное развитие колонии** (`strategy/colony_development.rs`). Мониторинг только настоящих `station` в локациях `*-colony`. Раздельный учёт живого населения, фактически пригодного труда (3/5 жителей), потребности в рабочих для существующих `mining_rig`/`refinery`/`farm`/`factory`, склада воды/еды/электроники и уже оплаченных пассажирских контрактов. Несколько рынков на одном месте не суммируются: неоднозначный склад помечается блокировкой. При отсутствии собственного рынка или жителей готовность не объявляется.
2. **Цели жизнеобеспечения.** Для основанной колонии запасы воды и еды сравниваются с минимальным запасом 20 единиц или двойным текущим окном спроса (что больше). Если запас мал, глава предоставляет HTN/гибриду цель снабжения **конкретного реального колониального склада**; планировщик должен сам обнаружить допустимую доставку/рецепт. Учитываются оба товара: если вода уже заказана, это не запрещает независимую цель по еде. Любой исходящий груз остаётся реальным контрактом Genesis, выпуск — нативной оплаченной производственной сменой. Если план не найден, сохраняется штатное решение главы; фиктивного товара нет.
3. **Миграция именно для рабочих.** Когда уже построенные производственные модули требуют больше работников, чем может предоставить местное население, глава может выбрать `migrate`. Перед заказом проверяются достаточное население в исходной станции (с резервом минимум 10 человек), существующий приёмный household, действительный маршрут, свободный пассажирский корабль с вместимостью и топливом, казна с сохранением резерва, отсутствие другой активной доставки пассажиров в эту колонию. Создаётся реальный `ContractType::Passenger` с уникальным `strategy.colony.workforce.v1`, авансом из казны и обычным `Embark` / `Deliver`; переселение и перенос имущества выполняются только сервером Genesis. Никакого прямого изменения PopDemographics по инициативе главы. Размер одного рейса — до 20 человек, по величине кадрового дефицита.
4. **Следующая производственная ступень.** В существующий `construction::run_cycle` после последовательности шахта → переработка → ферма добавлен `factory` (реальная фабрика). Строительный администратор применяет обычные стройплощадки, Metals, транспорт, труд и деньги; не спавнит объект напрямую. После материализации фабрики и обеспечения воды, еды и работников может появиться цель по Electronics. Общий каталог блока II позволяет её разложить на имеющиеся добычу, переработку, выпуск компонентов и электроники там, где физически существуют соответствующие заводы, рынки, сырьё и транспорт.
5. **API/Observer.** В `/api/strategy` добавлена необязательная коллекция `colonies` с фактическими запасами, целевыми резервами, жителями, рабочей силой, существующими модулями и состоянием пассажирского контракта. Старые ответы без этого поля отображаются как пустой список. В интерфейсе цели/резервы прямо отделены от подтверждённого выпуска.
6. **Совместимость.** Экономические компоненты, контракты, ID, Cargo.lock, БД, стартовые данные и формулы рецептов не менялись. Новых полей в сохранённый `Director` не добавлено; состояние перевозки лежит в существующем сохранённом ContractBoard. Стратегическая память из III продолжает храниться в том же директоре.

## 2. Как связаны модули

`colony_development::observe` → текущие данные о жизни и хозяйстве колонии  
`colony_development::next_supply_goal` → ограниченная цель реальной воды/еды/электроники (без выдачи товаров)  
`strategy::coordination` → глава выбирает приоритет; нативный HTN/гибрид строит/исполняет реальные действия с fallback  
`strategy::construction` → нативное строительство mining_rig/refinery/farm/factory  
`colony_development::migration_proposals` → только проверенный кандидат на физическую перевозку  
`colony_development::commission` → prepaid Passenger contract → существующий серверный BT и операции embark/deliver → `PopDemographics`  
`sim_server::snapshot` → read-only показатели Observer

## 3. Реальная технологическая цепь и соответствия

См. `AI_BLOCK_IV_NATIVE_CHAIN_MAPPING_RU.md`. Используется существующий `economy/recipes.rs`, а не предложение T1–T4 как якобы готовые правила. Целевой промышленный товар — электроника: Ore + Ice/Gas → Metals/Fuel/Polymers → Components → Electronics. Научный директор сможет тратить такую электронику на настоящие research shifts по прежним правилам. Это НЕ реализация 92 технологий или прямое строительство мегаструктур.

## 4. Что намеренно НЕ сделано

- Не добавлены строительство отсутствующих фабрик в единый HTN как `Construct`: этой операцией по-прежнему управляет **нативный** строительный администратор. Гибрид начинает производственный поиск только после физической материализации фабрики.
- Нет универсального автоматического транзита через несколько систем с перевалкой, автоматической покупки дополнительных кораблей и нового производства топлива. Прогноз действия не подменяет проверку реального маршрута и ship BT.
- Владелец фракции может поддерживать только **один** активный нативный производственный план; срочная цель колонии не прерывает уже оплаченный план, по правилу Астры. Полноценная очередь приоритетов/безопасная пауза остаётся будущей задачей.
- Пассажирский контракт без свободного корабля, получателя, средств или живого маршрута не создаётся. Отсутствующая механика не заменена ростом населения из воздуха.
- Не менялись стартовые 50 колонистов, баланс, потребление, фабричные рецепты, уровни T1–T4 и дипломатия.
- Формулы планового спроса/миграции — консервативные технические пороги, **не проверенные игровым балансом**.

## 5. Отложенная проверка после согласования блока IV

**Сначала компиляция:** `cargo check -p sim_core -p sim_server -p sim_db --locked`, затем адресные unit и новая сборка именно изменённых исходников. Дальше короткие игровые сценарии: одна реально основанная колония с нулевым запасом воды; две независимые потребности воды/еды; груз воды в пути при нехватке еды; физическое прибытие мигрантов; повторный стратегический цикл без повторного пассажирского аванса; сохранение/рестарт при пассажирах в пути; переход к factory и выпуску Electronics на нативной экономике. Нужна проверка рабочих мест и рынка после реальной материализации фабрики, а также при отсутствии подходящего корабля и недоступном источнике сырья. Все статусы до этих проверок **непроверены**.
