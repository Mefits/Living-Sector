- **Cargo/Rust в этой среде отсутствует**. Новое Rust-изменение **не компилировалось** и не исполнялось. Все прогоны относятся к исходному Linux-бинарнику Galaxy 0.2.
- B2 пока неполный: нет общего native ActionCatalog, baseline-адаптера, исполнения через общий dispatch, shadow-трассировки, сохранения активных планов; `PlanningSnapshot::capture` ещё не вызывается из игрового цикла.
- HTN/GOAP/Beam ещё не интегрированы, поведение реальных фракций исходной сборки не изменено.
- B1 (цикл отклонённых контрактов) отложен до интеграционной проверки, если он не блокирует подключение планировщика. Проверки escrow и backoff не сделаны.
- Исправность Windows EXE после нового Rust-кода не подтверждена; новая Windows-сборка не создана.

## Следующая проверка для окружения с Rust/Cargo

Из корня проекта (не из `reference/ai-bench-v1.3-source`):

```bash
cargo check -p sim_core -p sim_server -p sim_db --locked
cargo test -p sim_core strategy::planning --locked
cargo test -p sim_core strategy --locked
```

При ошибках: сохранить полный лог сборки, исправлять минимально, не обновлять автоматически `Cargo.lock`. После успешной компиляции можно перейти к завершению B2: получение `PlanningSnapshot` в координаторе, общий каталог нативных действий, baseline/shadow, связка `ExecutionReceipt` с жизненным циклом нативного приказа. Ни один прогноз не равен фактическому исполнению.

## Принципы следующих блоков

Сохранить производственную/логистическую логику Genesis; Utility выбирает цель с учётом личности; HTN/GOAP могут строить альтернативные пути; Beam сравнивает отдельные дорогие альтернативы. Гибрид — итоговая задача, а не автоматическое подключение всех библиотек. Прогнозируемые ресурсы не поступают на реальные склады, контракт не создаётся без повторной live-проверки, закончившийся контракт не считается доставкой. Весь benchmark-код — справочник до тех пор, пока реальный адаптер не собран и не проверен.
