# Stage 03 — память исполнения плана (исходники без компиляции)

Основа: `Living-Sector-Galaxy-0.2-AI-Stage02-SOURCE.zip`. Этот этап подготовлен **во время установки Cargo у пользователя**; никаких новых Rust-бинарников не получено. Существующие EXE и Linux-сервер в архиве относятся к Galaxy 0.2.

## Сделано в исходниках

- `crates/sim_core/src/strategy/planning/ledger.rs`: `PlanLedger` с сериализацией и стабильными идентификаторами шагов и заказов.
- Последовательность статусов: `Planned → Prepared → Submitted → Running → Succeeded / Failed / Cancelled`.
- `Prepared` намеренно **не превращается автоматически в новую отправку** после перезапуска: возможен краш после создания заказа, но до записи подтверждения. Требуется сверить `dispatch_key` с нативными контрактами перед повтором.
- Успех принимается только по подтверждённому `ExecutionReceipt` от нативного заказа; прогноз и событие «заказ отправлен» не являются успехом.
- Дубли с тем же нативным ID разрешены идемпотентно; конфликтующий ID или неверная последовательность статусов блокируются.
- В `planning/mod.rs` подключён новый модуль и публичные типы; **в главном цикле стратегия не менялась**, новых приказов не выдаётся.
- Подготовлены три целевых Rust unit-теста, **не запускались**.

## Граница реализованного

Это **не интегрированный HTN** и **не завершённое исполнение планов**. Модуль описывает устойчивое состояние, но сейчас не вызывается координатором, не привязан к сохранению `Director`/SQLite и не управляет контрактами. Изменение Rust без компиляции может содержать ошибки. Не считать новый код проверенным.

## Обязательные действия после установки Rust/Cargo

Из корня проекта запустить `VERIFY-AI-STAGE.cmd` и передать журнал, если есть ошибки. Скрипт проверяет и ранее не скомпилированный Stage 02, и Stage 03. **Не запускать старый бинарник в качестве доказательства нового кода.** После успешной сборки проверить:

```bash
cargo test -p sim_core strategy::planning --locked
```

## Ближайший шаг после прохождения gate

1. Привязать `PlanLedger` к сохранению/восстановлению директора с совместимостью старых SQLite кадров.
2. Сделать native reconciliation по idempotency key и live validation перед отправкой; пока этого нет, dispatch запрещён.
3. Подключить **настоящий** HTN (`htn` 0.2.1 из AI Bench), сначала в shadow на общем каталоге игровых действий. Cargo.lock обновить с Cargo, не вручную. Затем GOAP, Beam и контролируемое гибридное сравнение.
4. Проверить физический результат в Genesis; рецепты и деньги должны расходоваться только через действующий ECS.

Не добавлять новые ресурсы, здания и баланс ради этого этапа.
