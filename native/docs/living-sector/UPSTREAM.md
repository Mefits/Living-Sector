## Ветки

- `main`: по возможности чистый upstream без наших игровых изменений.
- `living-sector-dev`: документация, эксперименты и интеграция наших изменений.
- Отдельные короткие `feature/*` ветки от dev — под конкретную задачу.

**Это политика для нашей работы, а не гарантия автоматической синхронизации.** GitHub Fork позволяет смотреть, какие upstream-коммиты впереди, и выполнять синхронизацию. Конфликты возможны.

## Если клонировать локально

```bash
git clone https://github.com/Mefits/Living-Sector.git
cd Living-Sector
git remote add upstream https://github.com/Kalcode/spaceprojectsim.git
git fetch upstream
git switch living-sector-dev
```

Проверить `git remote -v`. Добавление `upstream` — локальная настройка клона, она не изменяет настройки GitHub на сервере.

## Перенос обновлений автора (когда есть изменения)

```bash
git fetch upstream
git switch main
git merge --ff-only upstream/main
git push origin main

git switch living-sector-dev
git merge main
# разрешить конфликты, проверить код и tests, затем push
git push origin living-sector-dev
```

Указанная последовательность предполагает отсутствие собственных коммитов на `main`. Если `--ff-only` не проходит — **остановиться** и разобраться в расхождении; не применять `reset --hard` или `push --force` автоматически. Перед обновлением dev нужна резервная копия и отдельная ветка при крупных изменениях.

## Принципы совместимости

1. Не менять upstream-механику «для красоты», если цель достигается расширением.
2. Свои модули помечать понятным пространством имён/директориями и документировать точки интеграции.
3. При получении чужой дипломатии/войн проверять, нет ли в ней уже функционала, который мы собирались писать.
4. До объединения проверять `cargo check -p sim_core`, целевые тесты, save/load и релевантную сцену клиента; фактически выполненные проверки записывать в STATUS.
5. Не переносить upstream-обновления вслепую и не обещать бесконфликтные merge.
6. Публичный форк означает публичную историю коммитов и наши документы. Не добавлять приватные данные.

## Источник изменений

Оригинал — независимый экспериментальный проект. Его README/roadmap могут устаревать; подтверждать реализованное состоянием кода и тестами, а не только описанием или планом автора.
