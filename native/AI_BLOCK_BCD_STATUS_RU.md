# Living Sector: единый checkpoint блоков B+C+D

Дата: 10.11.2026. Этот архив включает все исходники предыдущих Stage 01–05, блока A, блока B (Telic/GOAP и Beam), блока C (гибрид) и нового блока D (проверяемая история реального исполнения).

**Главная цель:** подтверждать не существование кода или ответ сервера, а реальное движение планов через оплату нативных контрактов, выполнение производства и завершение планов. Директор Genesis остаётся контрольным baseline.

## Сделано в D

- API `/api/strategy` показывает реальное сохраняемое `ai_execution`, включая активный план, нативные ID заказов и фазы выполнения; игровой мир и кошелёк не меняются этой диагностикой.
- В сохранении `Director.ai_execution.history` появились последние 64 конечных исхода планов с квитанциями, включая после рестарта. Формат старых сохранений совместим благодаря default.
- Отдельный read-only аудит `scripts/ai_runtime_audit.py` запускает настоящий сервер на свежих БД в трёх режимах и фиксирует фактические состояния.
- 5 Python unit-тестов для классификации доказательств. Проверка на исходном Linux-сервере прошла (только проверка раннера, не гибрида).

## Текущая граница подтверждений

- **Block A:** пользователь ранее подтвердил компиляцию, 27+6+7 целевых тестов, сборку сервера.
- **Block B+C:** Rust-код ещё НЕ подтверждён компиляцией, запуском или поведением.
- **Block D:** новый Rust-код ещё НЕ компилировался. Это исходники, а не готовая исполняемая версия.
- `runtime audit` без обнаруженных доставок возвращает **inconclusive**, а не выдаёт ложный PASS ИИ.
- Результат baseline/HTN/hybrid сравним только описательно: RNG между отдельными запусками не доказан одинаковым.
- Полное доказательство цепочки «лёд → груз → refinery → вода» в живой игре пока отсутствует; обычный старт не гарантирует достижение такой цели в коротком прогоне.

## Одна контрольная проверка для пользователя — в удобное время

Распаковать ZIP отдельно и запустить **`VERIFY-AI-BLOCK-BCD.cmd`**. Это заменяет индивидуальные проверки B и C. Инструмент собирает ядро и сервер, запускает тесты и, если установлен Python, короткое наблюдение за baseline/HTN/hybrid на отдельной базе. Складывает логи и JSON (без SQLite-файлов) в `AI-BLOCK-BCD-RESULTS.zip`.

Если Python отсутствует, скрипт не просит устанавливать его, а честно отмечает пропущенную runtime-проверку. При ошибке компиляции дальнейшие эксперименты автоматически не проводятся.

**Следующая инженерная задача после исправления возможных ошибок компиляции:** провести управляемый runtime-сценарий с настоящим рынком, кораблём, маршрутом и доказанной цепью снабжения. Не добавлять технологии или новые ресурсы до подтверждения этой интеграции.
