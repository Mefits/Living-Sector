# Living Sector: контракт переноса Rust -> Godot

## Источник истины

Эталон: `archive/rust-galaxy-067-reference`, интегрированная PR #83,
последняя полностью собранная Windows-версия до миграции.
Выполненная пользователем компиляция: SHA256 исполняемого файла
`C98A5FBAB974D911933B2DC5519CBF9D92CA38449236D9C631A9911ABBB4DBF6`.
Пользовательский runtime отработал 8 систем, 3 фракции, нативный API/Observer;
экономическое POST-поручение дало HTTP 404. Последняя проблема **не закрыта**.

**Переносим функции, данные, формулы и ограничения, а не только дизайн.**
Реализация Godot должна проходить те же короткие сценарии и сохранять
причинно-следственную связь: контракт -> оплата -> реальный груз -> склад,
строительство -> материалы -> оплаченный труд -> выпуск, без виртуальных товаров.

## Модульная карта (не перечень новой игровой механики)

| Источник в native/crates/sim_core/src | Целевой слой Godot |
|---|---|
| `economy/commodities.rs`, `economy/recipes.rs` | `scripts/sim/economy/`: ID товаров и **те же** рецепты |
| `economy/contracts.rs` | `scripts/sim/economy/contracts.gd`: нативный жизненный цикл и оплата |
| `agents/facility/` | `scripts/sim/facilities/`: ресурсы, работники, выпуск |
| `agents/ship/` | `scripts/sim/ships/`: поведение, груз, физическая доставка |
| `agents/faction.rs` | `scripts/sim/factions/`: казна, бюджет, отношения |
| `strategy/director.rs`, `coordination.rs`, `options.rs` | `scripts/sim/strategy/`: Глава, выбор и причины |
| `strategy/station.rs`, `construction.rs` | `scripts/sim/strategy/`: администраторы, стройки |
| `strategy/production_chain.rs`, `long_term.rs` | `scripts/sim/strategy/`: реальные этапы и память целей |

| `native/observer` | Godot `Control` сцены: инспекторы, графики, шкалы |

## Жёсткие требования

- Симуляция — фиксированные тики, отделена от кадров; ускорение мира
  не должно случайно ускорять физические расчёты или повторно платить.
- Данные кораблей хранятся в компактной модели, не тысячи тяжёлых Nodes.
  Узлы Godot отвечают за представление и ввод, а не за экономическую истину.
- Одно событие оплаты = одна фактическая квитанция с ID договора.
- Нет автоматического делегирования полномочий вместо игрока.
- Блокировки, неизвестная статистика и пустые значения не превращаются в 0.
- Каждый перенесённый модуль получает простую проверку фактического
  соответствия старому Rust-поведению; тесты батчами, без длительных прогонов.
- Результат должен запускаться в Godot Editor **без перекомпиляции Rust**.
- Исторические JSON/SQLite не изменяются в исходной ветке.

## Фазы

**P0 (сейчас):** реальный нативный датасет, 2D карта восьми систем,
контроль редактора, без вымышленной экономики.

**P1:** товары, склады, рецепты, фиксированный тик, сохранение состояния;
проверка конкретных норм потребления и продукции против Rust.

**P2:** нативные контракты/корабли/доставка, экономические причинные цепочки.

**P3:** фракции/Главы/администраторы/поручения, долгосрочные цели,
исследования, интерфейс наблюдателя.

**P4:** 1000-летняя прогрессия, T1-T4, войны, планетарная визуализация
после функционального соответствия текущей Galaxy.

**Не объявлять перенос готовым до P3.** Этот документ сохраняет старое
состояние как эталон; не является разрешением выбросить работающие механики.
