# Living Sector — Большой стресс-тест планировщиков (рус.)

**Изолированная ветка**: experiment/simulation-architecture-20261114. Основной PR #249 не меняется. Используется единый мир и реальные функции преобразования товара N73 (native_recipes.gd) и физической перевалки N9 (inventory_store.gd).

## Запуск

После GitHub Desktop **Fetch origin → Pull origin** выберите ветку эксперимента, откройте папку godot и запустите **RUN-SIM-STRESS.cmd** двойным щелчком. Godot.exe у пользователя уже находится рядом с предыдущим скриптом, поэтому новый запускатель сначала проверяет эту папку.

По умолчанию: **profile=stress, seeds=2, repeats=3**.

Три планировщика для каждого набора параметров: Tick, Event и Hybrid. Порядок переключается между повторами, каждый прогон создаёт новый мир с одинаковыми для всех моделей запасами, маршрутами и кораблями. При различии конечного физического состояния конкретный случай завершается с FAIL.

Запуск из командной строки с собственными параметрами:

    RUN-SIM-STRESS.cmd --profile=quick --seeds=1 --repeats=1
    RUN-SIM-STRESS.cmd --profile=stress --seeds=2 --repeats=3
    RUN-SIM-STRESS.cmd --profile=extreme --seeds=2 --repeats=3

"quick" нужен лишь для проверки скрипта. "stress" — основной выбор. "extreme" может оказаться тяжёлым и занимать много CPU/памяти; для остановки — Ctrl+C. Файл stress.json сохраняет частичные результаты ПОСЛЕ КАЖДОГО измерения, но последнее неполное измерение не сохранится.

### Сценарии STRESS по умолчанию

| Сценарий | Производств | Кораблей | Игровых дней | Начальные запасы |
| --- | ---: | ---: | ---: | --- |
| dense_1000 | 1 000 | 250 | 730 | много сырья, активные производства |
| scarce_5000 | 5 000 | 1 000 | 3 650 | дефицитные колонии, остановки |
| freight_5000 | 5 000 | 2 000 | 730 | обычные склады, много рейсов |
| dense_5000 | 5 000 | 1 000 | 730 | много сырья, активные производства |
| marathon_1000 | 1 000 | 200 | 3 650 | обычные склады, длительная история |

Это 5 × 2 × 3 × 3 = **90 запусков симуляционного ядра** в одном автоматическом сеансе. Единица времени тестовая (условно «день»), не реальный календарь исходной игры.

### Сценарии EXTREME

- dense_20000: 20 000 производств, 4 000 кораблей, 365 дней, много сырья.
- scarce_20000: 20 000 производств, 4 000 кораблей, 3 650 дней, дефицит.
- marathon_5000: 5 000 производств, 1 000 кораблей, 36 500 дней, обычные склады.

**Не запускать extreme как первую проверку нового кода**. Он может быть крайне затратным; при проблемах с RAM используйте stress и его отчёт.

## Результаты

В папке godot/experiments/simulation_architecture/results:

- **stress.log**: текущие сценарии, все измерения, паритет, ошибки — обновляется в реальном времени.
- **stress.json**: срединные значения, отдельные измерения, чексума, отчёт по каждому сценарию, статус PASS/FAIL/RUNNING. Перезаписывается после каждого измерения.
- **stress.csv**: удобная таблица медианных времён всех успешно завершённых сценариев; открывается в Excel. Одна строка на сценарий.

В таблице **event_over_tick** и **hybrid_over_tick**: число 0.6 означает на 40% быстрее, 2.0 — вдвое медленнее; но это только стоимость описанного стенда.

Проверяется полное совпадение физического состояния мира, сохранность грузов в трюмах и отсутствие отрицательных запасов. При разных checksum или сбое N9 — FAIL, результаты не объявляются успешными.

Обязательный контроль при интерпретации: количество выполненных партий (batches) и прибытий (arrivals), число попыток производства и доля активных мощностей. Если большая часть предприятий стоит, тест не подтверждает скорость активной экономики.

В stress.json есть имя версии Godot и модель процессора. Счётчики OS static memory доступны только в отладочной сборке Godot и показывают накопленный пик всего процесса, а не максимальную RAM каждого планировщика. Нельзя сравнивать память моделей по их порядку запуска; для реального анализа RSS используйте внешний системный профилировщик Windows.

## Ограничения исследования

Важно: **это стресс-тест архитектуры обновлений N73/N9, НЕ полный Living Sector**.

В нём нет настоящих N39 зарплат/рабочих, N14 корабельного AI-навигационного расчёта, N104 escrow-контрактов, N100 Head/Admin, строительства, роста населения и дипломатии. Логистика физических грузов исполняется оригинальным N9, но рейсы и сроки заданы фикстурой. Модель STRESS использует конечные стартовые ресурсы без новых месторождений и регулярной добычи; "supplied" означает большой начальный склад, а не производство бесплатной руды по ходу истории.

Поэтому даже однозначная победа Tick/Event/Hybrid в этом тесте **не повод менять архитектуру игры немедленно**. Это большая проверка конкретных затрат на планирование и корректность при 1 000–20 000 производств и 200–4 000 транспортов.

После успешного стресс-прогона отдельный этап должен использовать ОБЯЗАТЕЛЬНЫЕ действующие N39/N104/N14/N100 семантики. Не заменять полную экономику упрощённым тестовым миром. Не переносить эксперимент в PR #249 без отдельного решения.
