# Living Sector — Tick / Event / Hybrid

**Экспериментальная ветка, не часть PR #249.** Этот стенд не меняет игру, баланс и текущую интеграцию Rust → Godot. Не сливать его в P2 до полного переноса и отдельного решения.

## Что реально реализовано

- Единственное начальное состояние: несколько рынков, производства, физические корабли, грузы и маршруты (логистическое время задано тестовым сценарием).
- Для ВСЕХ трёх моделей используются существующие Rust-derived N73 рецепты из scripts/sim/economy/native_recipes.gd, включая функцию Recipes.execute(), и N9 Inventory.transfer_to_ship() / Inventory.transfer().
- Интервал производства взят из N39: 5 базовых тиков. Один тик здесь условно соответствует игровому дню. Это **не утверждение о настоящем календаре игры**.
- Tick: обычный цикл, сканирующий активные и неактивные объекты на каждом шаге.
- Event: стабильная приоритетная очередь отправлений, прибытий и рецептов.
- Hybrid: события для кораблей, расчёт производства только по сроку и пробуждение уснувших производств при фактическом изменении склада.
- Результаты должны иметь одинаковые склады, корабельные грузы, положение кораблей в рейсах и количество произведённых партий. Отдельно проверяются N9 инварианты складов и целочисленные грузовые отсеки.
- Headless JSON-отчёт фиксирует время работы, количество проверок, событий и пиковый размер очереди.

**Это ещё не полная модель игры.** В стенде отсутствуют N39 рабочие/оплата, N104 контракты и escrow, N100 автономный ИИ, N14 настоящие маршруты, население, рынки/цены и кризисы. Поэтому измерения нельзя называть ускорением полного Living Sector. Мы проверяем только цену планировщика на общей физической модели.

## Как запустить на Windows

Из папки godot запустить RUN-SIM-BENCHMARK.cmd двойным щелчком.

Если портативный Godot не добавлен в PATH, откройте CMD и укажите его консольный исполняемый файл, например:

    set "GODOT_EXE=C:\Godot\Godot_v4.x-stable_win64_console.exe"
    RUN-SIM-BENCHMARK.cmd

Режим с настройками:

    RUN-SIM-BENCHMARK.cmd --plants=100 --ships=20 --years=10 --seed=42

Тот же запуск из корня репозитория:

    godot --headless --path godot --script res://experiments/simulation_architecture/benchmark.gd -- --plants=100 --ships=20 --years=1 --seed=42

Файл отчёта: godot/experiments/simulation_architecture/results/latest.json

В случае расхождения состояния или нарушения правил N9 программа завершится с ошибкой. Если всё совпадает, выводит SIM_BENCH_PASS. Никаких скрытых «успешных» игнорирований различий.

## Как читать результаты

- milliseconds — измерение времени стенда в данном процессе, а не FPS полноценной игры.
- checks — сколько проверок совершено (у Tick включаются все пустые сканирования).
- events — сколько событий обработано из очереди.
- queue_peak — максимальная длина очереди.
- production_attempts — число реальных попыток применить N73, в том числе неудачных.
- batches / arrivals — полезные действия.
- sha256 — контрольный отпечаток окончательного экономического состояния, который должен совпадать.

Начальные размеры: 100 производств, 20 транспортов, 1 игровой год. Для оценки масштабирования прогонять 100 / 1000 / 5000 производств при нескольких количествах транспортов, нескольких seed, повторять измерения на одном компьютере. Один запуск не доказывает преимущество.

## Ограничения и следующий блок

1. Тиковая модель пока нарочно проста и не оптимизирована. Не сравнивать с ней как с лучшим возможным Tick engine.
2. Событийный и гибридный варианты используют те же дискретные моменты производства, что и Tick. Это проверка *планирования*, а не окончательный отказ от временной дискретности.
3. Ожидание груза и изменение склада — ключевые тесты на неправильную оптимизацию. При одинаковом времени событий надо соблюдать приоритет: прибытие, отправка, производство; предприятия обрабатываются по ID.
4. Следующий исследовательский блок — изолированные адаптеры к N39/N104/N14/N100 с рабочими, реальными контрактами, оплаченной доставкой, сохранениями и автономными решениями. Не имитировать их упрощёнными формулами.
5. Пока нет реального Godot headless run, это **CODE-WIRED / NOT RUNTIME VERIFIED**, не реальный PASS производительности.
