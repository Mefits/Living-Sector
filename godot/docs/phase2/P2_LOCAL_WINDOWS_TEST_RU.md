# Living Sector — тестирование без GitHub Actions (Windows)

## Какой способ выбрать

**Рекомендуемый:** один раз поставить [GitHub Desktop](https://desktop.github.com/) и официальный Godot **4.7.2 Standard для Windows**. Далее ты тестируешь обычный **исходный Godot-проект**, обновлённый через GitHub. F5 запускает игру без компиляции Rust, GitHub Actions, скачивания EXE и ожидания cloud CI. Это самый быстрый способ увидеть изменения UI/планет/кода.

Старый скачанный `LivingSector.exe` обновляться от GitHub Desktop **не будет**: это самостоятельная упакованная сборка. Он нужен для чистых релизных проверок, а не ежедневной разработки.

### Первый раз (один раз, не после каждого обновления)

1. Установи GitHub Desktop. **File → Clone repository → URL**: `https://github.com/Mefits/Living-Sector.git`, выбери папку на диске, например `D:\GamesDev\Living-Sector`. Репозиторий может занять заметное место; полный clone содержит и архив Rust.
2. В GitHub Desktop выбери **Current Branch** → `integration/godot-phase2-unified-20261113`. Не `main`, не старую `feature/godot-nightshift-20261112`.
3. Установи Godot 4.7.2 Standard Windows (не Mono/.NET — проект GDScript). В Godot Project Manager нажми **Import**, выбери файл `D:\GamesDev\Living-Sector\godot\project.godot`.
4. Убедись, что рядом с папкой `godot` существует `native\priv\galaxy\data\factions.json` и `native\priv\galaxy\data\worlds\sol.json`. Они уже есть в Git; копировать из ZIP ничего не нужно.
5. Открой импортированный проект в Godot; после завершения первичного импорта ресурсов нажми **F5** (Run Project, «Запустить проект»). При первом запуске не требуется экспортировать EXE.

Если появилась ошибка «Не найден именно Galaxy 0.6.7», скорее всего открыт не полный репозиторий или нет соседней папки `native`. Открой `godot/project.godot` именно из полного клона, а не одиночную папку `godot`, скопированную отдельно.

### При каждом следующем тестировании

1. Закрой запущенную игру. В GitHub Desktop нажми **Fetch origin**, затем **Pull origin** при появлении изменений. Открывай только выбранные точки готовности: общая интеграционная ветка между коммитами может быть временно сломана.
2. Перейди в Godot — он увидит изменённые скрипты. После крупных обновлений или конфликта ресурсов закрой/открой редактор проекта, дождись импорта и запусти **F5**.
3. Минимальная полезная проверка: карта сектора → двойной клик Sol → клик Земля → ресурсы/станции/экономика → «К сектору» → x8 + несколько тиков → пауза → сохранение → закрытие игры → F5 → загрузка; затем наблюдать за производством/рынком. Меню внутренней карты ещё требует реальной проверки Godot. Дополнить проверку кораблей/контрактов по мере интеграции.
4. Если ошибка: скриншот экрана **и** вкладка Godot **Debugger → Errors** / **Output**, дай название ветки или короткий SHA (GitHub Desktop → History). Укажи «что нажал → что ожидал → что увидел» и тик симуляции. Это намного эффективнее прогона GitHub Actions ради каждой ошибки.

### Важная безопасность

- Перед проверкой новой ветки сделай копию сохранений: новые домены могут менять структуру checkpoint. Старые сейвы автоматически мигрируются **только когда это реально реализовано**. Никогда не считать сохранение совместимым по умолчанию.
- В Godot генерируемая папка `godot/.godot/` уже находится в `.gitignore`; не добавляй её в Git.
- Экспериментальные изменения `native/priv/galaxy/data/worlds/*.json` (например, расположение систем) НЕ надо отправлять в общий Git: это часть эталона Rust. Для экспериментов сохраняй резервные копии, меняй только у себя или пользуйся отдельным overlay, когда мы его реализуем.
- Программы синхронизации (GitHub Desktop) не запускают тесты автоматически. Никакие персональные данные не нужны. Не публикуй user:// save и скриншоты со случайными личными путями, если это нежелательно.

### Когда нужен Windows ZIP

Только когда есть завершённая видимая вертикаль для отдельной контрольной проверки или когда пользователь просит экспорт. CI GitHub Actions допустим единожды на согласованный release checkpoint; не нужен при F5. ZIP должен включать `LivingSector.exe`, `LivingSector.pck`, и `data/galaxy/factions.json` плюс `data/galaxy/worlds/*.json`. После выгрузки проверять наличие всех этих файлов. Не путать автоматическую проверку Linux Godot headless с пользовательской проверкой настоящего Windows GUI.

### Если GitHub Desktop не подходит

С обычным установленным Git эквивалентно:
```powershell
git clone https://github.com/Mefits/Living-Sector.git
cd Living-Sector
git switch integration/godot-phase2-unified-20261113
# В следующие дни, находясь в этой же ветке:
git pull --ff-only
```
После чего Godot Editor → Import `godot/project.godot` → F5. `git pull --ff-only` откажется от опасного автослияния, если история локально изменена. При незакоммиченных правках не принуждай обновление, сохрани резервную копию.

### Для разработчиков/автоматических смен

Из полного клона, если есть локальный `godot.exe` в PATH (или использовать полный путь):
```powershell
godot --headless --path godot --editor --import --quit
godot --headless --path godot --script res://tests/p2_unified_script_compile_check.gd
godot --headless --path godot --script res://tests/p2_n158_live_production_check.gd
godot --headless --path godot -- --p2-boot-check
```
Не писать `VERIFIED`, если реального Godot локально нет. Не запускать облачные тесты ради подтверждения только что написанной маленькой функции.
