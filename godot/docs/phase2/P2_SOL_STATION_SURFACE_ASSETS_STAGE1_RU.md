# Living Sector — Sol: орбитальная станция и предприятия планеты (этап 1)

**Дата:** 17 ноября 2026. **Ветка:** `feature/SystemBalance` («Баланс Системы»).
Работа строго ограничена `system-sol`. Ветка «5 рабочих с Астрой»
остаётся приоритетной по производительности; ни одно её
экономическое правило, тик или N39 World не заменялись.

## Что действительно существует в исходной модели

В замороженном `native/priv/galaxy/data/worlds/sol.json`
на Земле **пять разных** исходных N39-объектов:
- `facility-earth-station`, `type=station`, орбитальная
  Genesis Initiative · Столица, 12 стыковочных мест,
  службы `market`, `repair`, `refuel`;
- `facility-earth-mine-module`, `type=mining_rig`;
- `facility-earth-refinery-module`, `type=refinery`;
- `facility-earth-station-farm-module`, `type=farm`;
- `facility-earth-station-factory`, `type=factory`.

**Важно:** у всех пяти в оригинальной экономике
`location=earth-station`, даже если `type` другой и
`facility.id` отдельный. Нельзя просто разнести их по разным
физическим адресам без обновления N39, N150, N14, N21,
рынков, контрактов, семей/рабочих и сохранений.

## Сделано в этом рабочем этапе

1. `sol_physical_assets_projection.gd`: read-only spatial
   projection только **реальных** source IDs. `station/shipyard`
   классифицируются как orbital; `mining_rig/refinery/farm/factory`
   как surface. Не создаём новые фракции, фабрики, запасы или
   ненастоящие станционные модули. Неизвестные типы не угадываем.
2. `StarSystemView`: орбитальная станция — отдельный
   узнаваемый индустриальный объект с корпусом, доковыми
   балками и панелями; обращается вокруг Земли. Угол
   `N43.initial_facility_angle(location)` +
   **реальное** `calendar.native_time_units` /
   `N43.FACILITY_ORBIT_PERIOD`. В default F5 worker для этого
   передаётся один read-only scalar, без отдельного календаря.
   Промежуточные кадры интерполируются только визуально.
3. Добывающий комплекс, переработка, ферма, завод
   отрисовываются **отдельными кликабельными индустриальными
   объектами на увеличенном глобусе Земли**. Их позиции
   намеренно схематические (предварительная художественная
   планировка суши), **не** физическая долгота/широта.
   Вопрос расположения наземных логистических узлов и
   реальных координат строительства ещё предстоит решать.
4. Клик по каждому ID открывает **реальную** N39-информацию:
   собственный `credits`, `assigned_workers`,
   `work_shift`, `module_stock.stock` (если доступны)
   и фракцию из источника. Для орбитальной станции также
   показываются доступные службы, стыковочная ёмкость,
   число кораблей в общей исходной локации.
   Не выдумывать выпуск, если N39-снимок его не предоставил.
5. Пристыкованные корабли на карте относятся теперь к
   значку **станции**, а не изображаются в центре планеты.
   Клик по группам кораблей и цикл выбора судов сохраняется.
   Никакого нового N14-движения и обхода экономики UI не создаёт.
6. Для разного масштаба карты пиктограмма станции
   визуально вынесена за границу **схематически увеличенного**
   диска планеты. Её настоящий физический радиус по-прежнему
   определяется N43 (земная станция: радиус Земли + 400 км),
   и вектор направления/фаза тот же. Это не физически
   точный размер значка; сжатие пространства неизменно.
7. `p2_sol_physical_assets_check.gd`: подтверждает 1 реальную
   орбитальную станцию + 4 реальных наземных предприятия,
   ID, owner, capacity, общий legacy-адрес, реальную фазу N43,
   пять кликабельных экранных объектов, N39 read-only inspector,
   неприкосновенность Rust-источника.

## Что НЕ завершено — следующий шаг

**Теперь нужно физически разделить логистику.** Пять независимых
предприятий должны получить устойчивые наземные site IDs,
станция — орбитальный docking-port ID, а отдельные
внутрипланетные грузовые/пассажирские перевозки должны
связывать production ↔ surface depot ↔ orbit. Только после
этого изменять адреса, транзакции и договоры в N39/N150/N9
и новую схему N38 с миграцией сохранений. Не допускаются
бесплатная доставка сырья через планету, производство на
орбите без заводских площадей или привязка колонии к
несуществующему доку.

**Финальная стыковка всё ещё дискретная.** Новые физические
маркеры и визуальная интерполяция станционной фазы сами по
себе не создают последнюю фазу подхода к доку (N14/N21).
При первом большом шаге N14 корабль может сместиться
значительно дальше реального радиуса станции. Требуется
локальный режим ограниченной скорости/докового подхода,
при этом позиции объекта и судна должны совпадать
при `transit={} / docked`, не маскируясь бесплатной
анимацией. После этого — настоящая связь с поверхностью.

## Производительность

Не создаются новые Node2D/Area2D/отдельные SceneTree
объекты на каждый завод или корабль; все пиктограммы
рисуются в том же `CanvasItem` из небольшого детерминированного
набора исходных Sol-фабрик. Текущие N39 tick paths,
N158 worker и пять оптимизационных веток не меняют
своих дорогих структур данных из-за изображения.
`set_live_facilities` собирает ограниченные скаляры только
для пяти UI-объектов, а не создаёт второй World.
