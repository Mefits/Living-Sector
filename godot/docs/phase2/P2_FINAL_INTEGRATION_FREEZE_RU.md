# Living Sector — закрытие интеграции Rust Galaxy 0.6.7 → Godot 4

**УТОЧНЕНИЕ пользователя 14.11.2026:** сначала ПОЛНОСТЬЮ закончить ПЕРЕНОС ВСЕГО существующего Rust 0.6.7 и связанных систем в один Godot-проект. До переноса ПОСЛЕДНЕГО блока никакой макрогейт нельзя объявлять проверенным/закрытым, не требовать от пользователя промежуточных тестов. Только ПОСЛЕ окончания интеграции пользователь начнёт проверять результат, менять баланс и механики. Пользователь уже собрал отдельный пакет важных правок за два дня, **не включать его в текущую фазу**, не запрашивать и не реализовывать частями. Этот документ выше прежних необязательных UI/балансных задач, пока не закрыта интеграция.

**Рабочая ветка:** `integration/godot-phase2-unified-20261113`, PR #249.
**Эталон:** неизменённый Rust Galaxy 0.6.7; использовать уже перенесённые source-механики и физические связи, не переписывать с нуля.

## Заморозка области работ (P2 integration-only)

**Разрешены:** соединение ранее перенесённого Rust-поведения с ОДНИМ N158 TickRunner / N39 World / N9 Ledger / N104 ContractBoard / N38 SaveState, устранение логических/парсерных ошибок, расхождений с Rust/дублирующих исполнителей, потерянных данных/сохранений, необходимый минимальный Observer для подтверждения реального исполнения.

**Не делать в P2:** ребаланс Food/Energy/топлива/расхода, новые корабли/технологии/планеты/победные условия, редизайн графики и меню, экспериментальные сценарные ассисты, стартовые бонусы, подмена порогов спроса ради анимации полётов. Не создавать второй World/кошелёк/параллельный tick, не плодить без необходимости тесты/промежуточные PR. Пользовательские правки — **после** P2 в отдельном следующем этапе.

**Наблюдение пользователя, clean seed tick 652:** N104 contracts=0, N153 accepted=0, N14 flights=0, source N135 reports consumption below stock. Это не доказательство поломки N14; это доказательство, что **автономная вертикаль clean start пока не подтверждена**. Нельзя считать «флот работает автономно» только потому, что скрипт принимает контракт в искусственном fixture. НЕ менять текущий баланс без источника Rust.

## Четыре крупных блока, а не 100 микротикетов

### А. Торговля + флот: настоящий сквозной рейс
**Уже в коде:** N135 paid demand, N104 escrow/board, N153/N80/N81/N84/N146, N21/N97/N15, N14/N4 (исправлена двусторонняя SQLite seed topology), N38 save. **Но не подтверждено в Godot в одном непрерывном прогоне.**
**Закрытие:** реальный контракт на исходных товарах/счетах (недостаток может быть создан ТОЛЬКО в изолированном интеграционном fixture, без изменения clean seed или игровых параметров) → N153 сам назначает реальный корабль → физическое N14 прибытие → N21 docking → N15 stock/hold → N9/N104 payout → N38 сохранение/восстановление посреди рейса и после. Без переноса корабля между локациями прямо в тесте.

### Б. Расширение мира: N134/N144/N151/N147 + строительство
**Уже в коде:** N134/N111 разрешение на часть N154 строительства, N91 инженер, N141 оплаченный труд, N143 исследование, N151 источник пустой колониальной площадки и N147 read-only эмиграционная оценка.
**Нужно соединить:** оригинальное создание N142 колониальной локации и её физической доступности (исходная база не содержит `*-colony` — не приписывать из JSON недостающий маршрут); реальное решение главы на создание, N104 пассажирский контракт+посадка+высадка, N151 household/станция/рынок только после оплаченной доставки и строительства; N154 завершение нового объекта с реальными материалами/сменами.
**Закрытие:** один прошедший путь «причина/цель фракции → заказ → настоящие корабли/товары/поселенцы → реальный объект» без бесплатных людей/денег.

### В. Управление фракциями + системные механики Rust
**Уже в коде:** большой исходный N100 Hybrid Planner, N134/N155 Director/мандаты/администраторы, N156 lifecycle, N143 research, N151 население, экономический рынок. **Наличие отдельного source-скрипта не доказывает исполнение.**
**Закрытие:** source head/admin/N100 видят живой N39 World и выбирают полезную цель, выдавая ограниченные команды через единый Apply. Фаза не должна сводиться к read-only preview. Сверить неисполненные source-составляющие: производственные зависимости, судостроение, отношения/угрозы, кризисы, condition/morale, исследования/экономика. Не менять смысл формул; отсутствующие механики либо интегрировать, либо явно зафиксировать как блокер полного Rust parity.

### Г. Один Godot + N38 + выпуск
**Обязательно:** парсинг всех активных GDScript в фактическом Godot 4, реальное F5 без ошибки, окно/карты без критических поломок; контроль 10/100/1000+ тиков без повторной выдачи денег/ресурсов; save/load во время исполнения и после; тот же детерминированный результат без параллельных миров; один согласованный headless прогон и Windows ZIP с Galaxy data после кода. UI — лишь возможность наблюдать подтверждённые события.
**Закрытие:** один Windows/Godot кандидат и отчёт **PASS/FAIL** по А–Г с прямыми доказательствами; пустые поля не заменять «примерно 90%».

## Порядок выполнения
1. Закрывать блоки А → Б → В → Г; параллелить только реально независимые файловые области и проверять leases.
2. Каждая итерация делает один существенный целостный участок существующего P2, фиксирует source-референс, код, проверенный/непроверенный результат, и освобождает lease. Не расходовать Actions на каждый коммит.
3. Когда все А–Г подтверждены, зафиксировать стабильную Godot integration baseline/tag; только **тогда** открыть новый этап пользовательского пакета правок, отдельной веткой.
4. На промежуточных сообщениях сообщать не абстрактный «процент порта», а число **закрытых сквозных блоков из 4** и конкретные ещё не закрытые результаты.

**Текущая оценка на 14.11.2026:** нет оснований ставить PASS на A, Б, В или Г как целое. Частичная работа в коде есть во всех четырёх. Скриншоты пользователя подтверждают запуск на Windows и статус на тике 652, а не end-to-end автономии. Следующий свободный исполнитель начинает с А (continuous paid freight route) — только source integration, без нового баланса.
