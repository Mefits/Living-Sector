# Living Sector — автономия прежде индивидуального управления

Решение пользователя: 13 ноября 2026. Текущая стадия — **автономный 2D космический сектор + режим наблюдения**. Управление отдельными кораблями, добычей, грузами и доками — **законсервированная потенциальная механика**, не основной геймплей. Режим игрока «Фракция» с приказами высокого уровня вернётся после жизнеспособного автоматического мира. Никаких новых игровых кнопок для 24 кораблей.

## Что сохраняем / что отключаем

- В коде остаются оригинальные ручные методы `request_ship_departure`, `request_ship_dock`, `request_ship_undock`, `request_ship_cargo`, N14/N21/N15 и тесты. Они нужны ИИ и отладке, их **не удалять**.
- В обычном F5 GUI **не показывать** корабельный приказной тулбар, ручную стыковку и ввод товарного количества. Единственный разрешенный переключатель в `main.gd`: `ENABLE_DEBUG_MANUAL_FLEET_UI = false`; когда понадобится разработчику, вернуть true локально.
- У игрока остаются обзор сектора/солнечных систем, инспектор, управление **временем**, save/load и диагностика. Отсутствие AI не скрывать.

## Ближайший путь до настоящей автономии

1. **Автономные заявки**: из реально оплаченной экономики N39/N151/N150 выявлять нужды предприятий, Food/Water/Tools/Fuel, нехватку ресурсов; создавать заявки по оригинальной логике станции и фракции. Не выдавать «план» за реальный заказ. Не подменять действующие балансные параметры.
2. **Единственная ContractBoard**: N152/N104 lifecycles, финансирование/escrow, контракты с товарами и назначением. N135 диспетчер получает только достоверные и оплаченные заявки. Нет второго кошелька или склада.
3. **Реальный автономный флот**: N153 ship behavior, N80 utility, N81 GOAP, N84 BT, N146 ordered command buffer → единственный P2 Apply. Родные 24 корабля сами выбирают доступные цели, обслуживают реальные контракты, летят по N14, стыкуются N21, перемещают физический груз N15/N97, затем оплачиваются через N104. Сначала один сквозной рейс без ручного вмешательства; не создавать рейсы ради анимации.
4. **Администраторы + глава**: N134/N100/N155/мандаты видят реальный World, заявки, сроки, риски, счета и дают цели с подтвержденным исполнением. Сложную координацию включить после рабочего исполнения шагов 1–3.
5. **Наблюдение и непрерывность**: показать трассу «причина → кто принял решение → заявка/команда → физическое действие → деньги/товар → итог/ошибка». Save/reload и детерминированный прогон без повторной оплаты; реальное подтверждение через Godot/Windows. Пауза не должна менять симуляцию.

## Как проверять

- Новый старт → 0 ручных корабельных кликов → после достаточного количества тиков агент **сам** замечает дефицит и создаёт реальное задание.
- После назначения корабль сам выполняет маршрут, стыковку, загрузку, доставку и расчёт; запасы и деньги сходятся без дублирования.
- Сохранить в середине рейса, перезапустить: ровно одно продолжение задачи, ноль повторных платежей. Повторить при отказах (нет топлива, дока, денег/товара, маршрута).
- ИИ должен иметь видимые причины отказа/бездействия и не печатать «автономия готова», если ContractBoard/Apply не подключены.
- Периодические тесты не должны тратить GitHub Actions без нужды; локальный Godot 4.7.2/F5 — основная проверка.

## Статус на момент решения

Рабочая экономика, орбиты и тики, физический базовый флот, ручное N14/N21/N15 ядро — **частично интегрированы**; N153/N135/N104 и директор пока **не исполняют** реальную самостоятельную последовательность в общем мире. В UI это прямо помечено. Источники портированы, но source coverage != autonomy. До первого достоверного автономного рейса нельзя говорить, что флот автономен.

Разработчикам: не создавать параллельные runner или деньги/ContractBoard; править `integration/godot-phase2-unified-20261113` и PR #249, делать один крупный связанный участок за смену, сначала взять lease, в handoff указать фактически исполненное и статус тестирования.
