# Living Sector — живая колония на глобусе (UI MVP, 17.11.2026)

## Что добавлено
- При открытии глобуса используются существующие N39 `facilities` для выбранного `body_id` (не стартовые неподвижные seed-списки).
- Наземные предприятия — квадраты на схематичной суше; реальные станции — рядом с глобусом, без отдельного режима орбиты.
- От центрального транспортного узла рисуются дороги ко всем наземным зданиям. Узел — **только графическое начало дорог**, не новое здание АЦ, пока его нет в World.
- Производственные связи mining_rig → refinery → factory между объектами одной реальной рыночной локации изображаются как дополнительные возможные линии взаимодействия. Это **не** подтверждённые рейсы/поставки.
- По дорогам движутся простые программно нарисованные точки; их число растёт с числом работников **недавней оплаченной смены** (N39 `work_shift.workers/tick`). При устаревшей смене или заброшенном предприятии движение затихает.
- Нажатие на квадрат/орбитальную станцию показывает в правом инспекторе тип, текущие кредиты, число работников последней смены и визуальную активность.
- Позиции узлов детерминированы ID и **не** становятся игровыми координатами. Статичные дороги отображаются только на крупном глобусе. Время декоративных точек не зависит от симуляционного времени.
- Встроен лимит 48 наземных, 12 орбитальных объектов, 24 дополнительных связей, не более 6 точек на ребро. Перерисовка активного крупного глобуса ограничена 30 Гц.
- Нет записей в World, N9, N38, сохранения, строительство или AI. Не запускается дополнительный `world_snapshot()`.

## Запуск
1. Открой Godot-проект в ветке `feature/colony-live-globe-ui-20261117`.
2. Запусти игру и открой систему Sol.
3. Дважды щёлкни Землю (или увеличь масштаб до глобуса).
4. На глобусе увидишь реальные предприятия и орбитальную станцию. При появлении оплаченных смен будут двигаться точки; в начале игры они могут стоять.
5. Выбери предприятие или станцию. Правый инспектор переключится с обзора колонии на выбранный объект.

## Быстрая проверка (без тяжёлых Actions)
```shell
godot --headless --path godot --script res://tests/colony_globe_projection_check.gd
```
Проверка создаёт небольшие **вымышленные данные только внутри теста** и доказывает фильтрацию по планете, отсутствие ложной активности старых смен, детерминизм проекции и связи предприятие→предприятие.

## Ограничения MVP
- Отдельный игровой АЦ как физическая сущность пока не добавлен: дорожный узел временно привязан к колонии с реальной станцией.
- Дороги не имеют стоимости, пропускной способности или физического грузопотока.
- Положение зданий стилизовано; маршруты могут пересекать рисунок воды. Для географически корректных дорог понадобится поверхность с реальными наземными координатами.
- Кружочки обозначают **занятость предприятий**, не реальный cargo receipt. Сверять реальные перевозки надо в N97/N104/N9.
- Стоимость визуализации необходимо профилировать на Windows с включённым и выключенным глобусом. Не утверждать об улучшении FPS без измерений.

### Если локальный Windows Godot показывает Could not resolve script на N121State
Выполнить из корня репозитория PowerShell (сначала закрыть редактор Godot):
```powershell
git switch feature/colony-live-globe-ui-20261117
git fetch origin
git pull --ff-only origin feature/colony-live-globe-ui-20261117
Test-Path .\godot\scripts\port\n121_native_execution_state.gd
git status --short
```
Если `Test-Path` возвращает False, при чистом Git checkout восстановить отсутствующий отслеживаемый файл:
```powershell
git restore --source=HEAD -- godot/scripts/port/n121_native_execution_state.gd
```
После закрытия редактора удалить **только временный кэш проекта** `godot/.godot` и открыть проект заново. Он пересоздаётся автоматически; сохранения `user://` не трогать. Если код локально изменён (см. `git status`), не применять reset/clean с удалением пользовательских правок.

Режим без удаления кэша: запустить `godot --headless --path godot --editor --import --quit` и проверить полный вывод ошибки. CI не доказывает состояние пользовательской локальной копии.
