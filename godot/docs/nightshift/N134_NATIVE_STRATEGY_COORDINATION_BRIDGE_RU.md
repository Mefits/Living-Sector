## Explicit Rust semantics and limitations

- `strategy/coordination.rs` starts in Shadow, gathers non-mutating Genesis baseline/construction previews, orders decisions deterministically and uses one temporary `Grants` resource to restrict legacy authorization. This isolated port returns authorization grants; full phase-2 integration must control original order of production and contract commit.
- A fundable project tag includes `strategy.logistics.v1`, `strategy.construction.v1`, `strategy.colony.v1`, `strategy.colony.workforce.v1`. Exact tick and faction guard detect same-tick replays. Existing funded orders remain distinct from already-posted-*today* guards.
- All market sourcing, real option scoring, Rust `director::retain_or_switch`, planner native goals, paid migration, production, treasury, construction, ship charter and economic mandate approval are dependencies, **not silently reimplemented**. Phase-2 needs shared canonical data adapters and transaction locks; no integrated, live Godot behavior is claimed.
- Rust uses fixed `f32` market prices, `f64` director scores, signed `i64` credits and `u64` ticks. Godot float/int precision, overflow and old checkpoint serialization need phase-2 parity review. No real parser or engine run performed.
- `goal_reviews`, `shadow_portfolio`, `planning_shadow`, `native_chain_probe` are copied from actual diagnostic providers without fake completion or synthetic production. `horizon_ticks` defaults to Rust `1200 × max(mult,1)`.
- Safeguards are stronger than permissive legacy paths when fields are missing: empty goal identifiers/locations never authorize a fake player grant; missing paid receipts cannot imply cash or completed production.
