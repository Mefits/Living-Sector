# N40: корабли из Galaxy 0.6.7 и единый Godot tick (12.11.2026)

Статус: **CODE_UNVERIFIED**. Отдельная ветка от PR #128, не объединена с P1/main/stable. Блок N39 производство зарезервирован другим агентом; его модули здесь не редактировались.

## Что написано

1. `sim/ships/native_ship_roster.gd` использует идентификаторы N4: у нативных кораблей в JSON **нет постоянного ID**, поэтому key = `@system-id/source-index`; сверяет class/faction/system/location, требует узел N4 directed graph. Читает именно настоящий frozen seed.
2. `sim/ship_tick_runner.gd` — **opt-in** адаптер поверх базового `TickRunner`, выполняющий N14 ship transit в настоящей фазе `ships`, после `bodies` и до следующих событий; события N3 и календарь сохраняются. Список кораблей сортируется по key. Пауза и world_speed остаются владельцами базового clock.
3. Строгое подключение: в native seed **нет значений топлива, груза и достаточных world-space координат**, поэтому требуется отдельный подлинный источник `ShipState` + `fuel_sources` + `cargo_sources` + `positions`. Без этих значений движок **не включает движение**, не создаёт полный бак/пустой трюм как якобы исходные данные. В тесте числа координат и топлива явно являются контролируемыми **test fixtures**.
4. `depart_ship` использует существующий N14 directed route / world-space coordinate resolver, не travel_routes.distance, не offset карты, не телепортацию. Не создаёт грузы/деньги и не запускает AI, торговлю, добычу, контракты или автоматическое планирование маршрутов.
5. `checkpoint()` при включённом флоте возвращает пустой объект и `restore_checkpoint()` fail-closed: базовый P1 snapshot не умеет сохранять полный транспортный, денежный и грузовой state. До появления объединённой атомарной модели сохранение нельзя объявлять работающим.
6. `tests/n40_ship_tick_worldbridge_check.gd`: проверяет первую нативную запись корабля Sol, запрет guessed fuel/cargo, отказ несуществующим маршрутам, fuel consumption, последовательность ships/orbits/events, защита от двойного движения, прибытие и отказ небезопасному сохранению.

## Rust-механика

Сверено с `native/crates/sim_core/src/agents/ship/mod.rs` frozen: `SHIP_BASE_VELOCITY=0.05`, `SHIP_ARRIVAL_THRESHOLD=0.01`; transit выполняется после orbital/LOD, fuel consumption в действительной фазе движения, без платы за финальный arrival branch. Используется уже существующий N14 адаптер; source geometry должна предоставляться реальным Rust-style location resolver, а не графикой.

## Что НЕ готово

- Нет настоящего источника топлива/груза/динамических точек местоположения из живого мира; N40 не активируется в P1 интерфейсе автоматически.
- Не подключена совместная работа N39 production, N35 contracts, docking / Cargo / Ship AI / атомарный world-save.
- Сами GDScript-файлы и тест **не исполнены в Godot 4.7**, движок в агентской среде отсутствует. Не считать `VERIFIED` или parity только по GitHub/static.
- Для следующего интеграционного блока требуется **один** авторитетный корабельный world state/position resolver, затем общий (не два отдельных наследника TickRunner) исполнитель фаз ships+facilities+apply2, и общий snapshot/restore. Права на редактирование `tick_runner.gd` согласовать с владельцем N39.

## Для приёмки

Не просить пользователя о запуске N40 отдельно. Включить тест в следующую пакетную интеграционную проверку, и после ~20–30 блоков передать полный ZIP c единым launcher.
