# N13 — классы и состояние кораблей

Источник истины: замороженный Rust `native/crates/sim_core/src/simulation/config.rs` (`ShipSize`, `SHIP_CLASSES`), `agents/ship/components.rs`, `agents/ship/snapshot.rs`.

Реализованы все **6** классов (colonizer, courier, freighter, hauler, tanker, miner), 6 tier размеров, родные грузоподъёмности, пассажирские лимиты, топливо, скорость, базовый расход, состав экипажа. Размер **не** является классом. Скорость класса × коэффициент размера, например hauler/huge = 0.6 × 0.8 = 0.48.

`ship_state.gd` — компактный словарь без SceneTree Nodes; ID уникальны, snapshot сортируется, restore атомарен, некорректный груз/топливо отвергается. Начальный груз пуст, начальное топливо полное **только при явном создании корабля**, не на каждом restore. `can_hold` лишь проверяет вместимость и не создаёт товар. N15 должен применить подтверждённые операции склада и контракта; N14 — перемещение и расход топлива. Изменения fitting могут менять эффективную грузоподъёмность, поэтому restore принимает сохранённую capacity, но не разрешает отрицательные значения.

Вместо Godot Nodes на каждый корабль используется data-oriented RefCounted + Dictionary, аналог разделения Rust ECS-компонентов по паттерну доступа. Возможные варианты: Godot Resource (удобно для статических каталожных данных), MultiMeshInstance2D (только рендер), GDExtension/ECS-плагин (преждевременная зависимость). Нативные типы Godot достаточны до измерений профайлера.

Проверка на Windows: `godot --headless --path godot --script res://tests/n13_ship_catalog_check.gd`.
