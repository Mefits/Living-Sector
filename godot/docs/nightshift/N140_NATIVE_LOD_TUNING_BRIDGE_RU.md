## Точная native семантика и Phase-2 контракт

**LOD счётчики:** `AgentLod::try_fire(tick)` пропускает агент при `tick < next_tick`; при запуске возвращает `max(1, tick - saturating_sub(next_tick, max(1,divisor)))` как Rust u32, затем `next_tick=tick+divisor`. Первый вызов при t=0 возвращает 1, а не divisor. У изменения divisor: если старый `next_tick <= tick`, следующий t = текущий tick; иначе `tick+новый divisor`. Это не перезапуск симуляции и не начисление ресурсов — лишь вызов для будущего системного tick runner.

**LOD tier:** radius clamp min 0.01; расстояние квадратами, границы включительные; если наблюдателей нет, divisor 1 везде. Из нескольких камер сначала берётся наблюдатель с минимальным **абсолютным** квадратом дистанции (не «с наибольшим охватом»), затем его radius. Это тонкая деталь оригинального Rust. При перемещении камеры recompute может вернуть отдалённый корабль к divisor 1; `next_tick` должен восстановиться как native.

**LOD usage:** `simulation/lod.rs` позволяет носить LOD и объектам facilities/populations для просмотра чисел, но **оригинальный ship pass должен продвигать курсор ТОЛЬКО кораблей**. Иначе дублируется advancement других подсистем. Рынки **не ограничиваются LOD** — они общий единый ledger, разная частота нарушила бы порядок транзакций. Реальный scheduler определяет cadence recompute; `RECOMPUTE_INTERVAL_BASE=50` и helper `should_recompute` рассчитан для native `TickConfig.tick_multiplier`. На Фазе 2 внешний адаптер обязан проверить точный cadence вызова в серверном Rust, не назначать его без источника. `effective_tick_scale` при обновлении корабля = `tick_scale * skipped_ticks`, с остальными фазами `transit → price memory → crew → AI`. `N112` уже переносит только сам transit: не копировать его в LOD.

**Вход и выход:** `Lod.ship_gate(agents, ship_ids, tick)` возвращает `{ok,reason,agents,fires}`, где `fires` есть `ship_id -> skipped_ticks`; неактивные отсутствуют. `agents` — `Dictionary[id -> {lod:{divisor,next_tick}|null, position: Vector2?}]`; список `ship_ids` должен формироваться из реальных `ShipIdentity`, не из всех entities. Duplicate IDs / повреждённый cursor => **fail closed** без частичной записи. `Lod.recompute(agents, observers, tick)` получает наблюдателей `[{position:Vector2,radius:float},...]`; строит новый snapshot + диагностические buckets. `Vector2` соответствует Rust `(f32,f32)`; точность Rust f32 относительно Godot float отдельно сверяется только на фазе 2.

**WorldTuning:** один объект на действительный World, при загрузке JSON использовать `install_once` или `set_from_json_once` **до** первого `current()`, который иначе защёлкнет default, как Rust OnceLock. Нет актуальной Rust реализации live editing tuning после запуска: не придумывать UI/динамические модификации. Для настоящих экономических и ИИ систем эти настройки читает **их** авторитетный owner; N140 сам не применяет ни docking tax, ни replan, ни crisis, ни auto-respawn. `serde(default)` сохраняет незаполненные поля и игнорирует неизвестные; поля `replan_*` Rust u64 > signed i64 не поддерживаются текущим Godot int, так что нужна специальная сериализация, без silent wrap.

**Безопасность экономики и повторов:** никаких `World` mutation, inventory, artificial resources, cash credits, ship lifecycle changes, research grants. На фазе 2 state must atomically commit with original world tick/checkpoint, once per ship per tick; not `Lod.ship_gate` twice.

**Непроверено:** Godot 4 parser/runtime/headless, Rust-vs-GDScript boundary and precision parity, actual total 223+ ship performance, external tick-source adapter, exact serialization/large tick handling. Статический GitHub readback и баланс скобок не позволяют назвать код VERIFIED. Нет merges.
