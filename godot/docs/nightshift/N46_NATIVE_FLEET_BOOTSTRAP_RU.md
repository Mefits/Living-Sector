# N46 — честный начальный флот Rust Galaxy 0.6.7 → Godot 4.7

**Дата:** 12.11.2026. **Статус:** `CODE_UNVERIFIED` до реального Godot headless. Отдельная ветка, наследует N43/N40; `main`, стабильная контрольная P1 и чужой N39 production не изменялись.

## Реальный источник и уточнение N40

Замороженный Rust `native/crates/sim_db/src/seeder.rs` при **первичном создании записей** кораблей извлекает `ShipClass` из `native/crates/sim_core/src/simulation/config.rs`. Он записывает `fuel = fuel_capacity` и `fuel_capacity = fuel_capacity`, включая `cargo_capacity` из класса; поле cargo в этом INSERT отсутствует и на первом запуске остаётся пустым по схеме DB. `native/crates/sim_db/src/spawner.rs` при загрузке из **реальной базы** читает `fuel`, `fuel_capacity`, `cargo`, `credits` и `resume_json`, то есть **никогда не пополняет уже использованный бак**. Отличать эти два режима обязательно.

Первый раз N40 отказался выдумывать fuel/cargo потому, что сами world JSON не содержат этих полей. N46 устраняет эту конкретную неопределённость через чтение **правила Rust seeder**, а не подстановку неподтверждённых значений.

### Зафиксировано по frozen seed

- Восьмерка ship-сценария каждой из трёх фракций: miner, freighter ×2, courier, hauler, tanker, colonizer ×2.
- Всего **24 стартовых корабля** в `sol.json`, `alpha_centauri.json`, `nadir.json`; остальные пять систем без стартовых кораблей.
- У кораблей JSON есть `class`, `location`, `credits=40000`, `faction_id`, `fitting={"comms":"comms_t2"}`; нет `id`, `size`, `fuel`, `cargo`, `transit`.
- Сумма **стартового топлива 4200 единиц**, **общая вместимость пустых трюмов 17 250**, **начальные деньги 960 000** (24×40 000). Это **сверка справочника и seed**, не увеличение игровых запасов/денег.
- Rust сшивает конкретный ship ID через DB при спавне, тогда как Godot N4 временно применяет `@system-id/source-index` для неизменяемого стартового seed. Не считать эти ключи Rust-native persistent IDs.
- Стартовое `comms_t2` не изменяет грузовую вместимость и движение. Другие fitting overrides могли бы изменять speed/cargo; пока **fail-closed**, не делать вид, что поддерживаются.

## Изменения

- `scripts/sim/ships/native_fleet_bootstrap.gd` проверяет все стартовые записи N4, создаёт data-only `ShipState` с точными class default size/capacity/crew, полными баками и пустыми грузовыми трюмами по Rust seeder. Сохраняет отдельные `credit_sources`, но не проводит финансовые операции и не дублирует ledger.
- Отказы на `fuel`, `cargo`, `transit`, `resume_json` и другие признаки состояния уже запущенной игры; неизвестный fitting/size и неверные кредиты; работа атомарная, без изменения входного seed.
- `ship_tick_runner.gd` получает отдельный `bootstrap_new_game_native_fleet(seed)`, доступный **только при tick=0, единожды**, и передаёт валидированное состояние в N40/N43. Положение тела/станции берётся из N43, движение N14, питание/рынок/контракты в этом модуле не подделываются. Ручное `configure_fleet` для runtime состояния остаётся доступным.
- `tests/n46_native_fleet_bootstrap_check.gd` читает настоящий frozen seed, проверяет 24 класса, 4200 топлива, 17 250 грузовой ёмкости, 960 000 исходных кредитов, строгие отказы, запуск N43/N40 ships-phase, запрет двойного старта и дозаправки, fail-closed неполный checkpoint.

## Ограничения и следующий интеграционный шаг

- Подключение к P1 UI остаётся явным opt-in: исходные корабли не выводятся как «работающие торговцы» автоматически. Нет решений корабельного AI, N15 экономических грузовых переводов, refuel purchase, docking, реального кредитного ledger и атомарного fleet save; все эти связи потребуют дальнейшего этапа.
- Не вызывать `bootstrap_new_game_native_fleet` при загрузке save; Rust DB/resume загрузка нужна отдельная, чтобы топливо/товары/деньги нельзя было создать повторно.
- Флот при включении делает P1 checkpoint пустым намеренно — прежний P1 save не покрывает новые mutating domains. Не использовать для пользовательских сохранений до общей схемы.
- N39 занят независимым агентом. Для объединения с N39 production нужен **один авторитетный TickRunner**, без конкурирующих наследников и двойных запусков фаз.
- Тесты на конкретной Windows сборке пользователю не назначаются. Реальное подтверждение Godot ожидает большой общий ZIP после 20–30 связанных блоков.

**Фактические проверки этой итерации:** исходный Rust `seeder.rs`, `spawner.rs`, `config.rs`, `ship/components.rs` прочитаны; все восемь world JSON проинспектированы; отдельный Godot headless-тест написан, но **не исполнялся** в агентской среде.

## Дополнительная защита и статическая сверка

- `ShipTickRunner.restore_checkpoint()` после **успешной** загрузки любого P1 checkpoint (включая тик 0) отключает режим нового корабельного старта; нельзя пополнить топливо через загрузку и `bootstrap_new_game_native_fleet()`. При некорректном checkpoint мутации не происходит.
- Headless N46 дополнен регрессией: корректно сохранить и загрузить checkpoint на тике 0, затем убедиться в отказе повторной инициализации.
- Статически сопоставлены **все 6** классов Rust `simulation/config.rs` с Godot `ship_catalog.gd`, 0 несовпадений по cargo/fuel. Прочитаны все 8 JSON: 24 корабля, 4200 топлива, 17250 вместимость, 960000 исходных кредитов, 0 неизвестных классов; `001_initial.sql` подтверждает `cargo DEFAULT '{}'`.
