# N64 — тик маршрутов и полный checkpoint intent + fleet

Статус **CODE_UNVERIFIED**. N64 над N63/#152 → N61/#150. Godot пользователем не тестируется до окончания переноса.

- `native_itinerary_runtime.gd` — opt-in контроллер N57 с N63 intent. `assign_route` проверяет настоящий граф, `dispatch_current_tick` допускает **не более одной отправки каждого корабля на тик**, а `advance_native_tick` сначала делает обычный N14/N21 native tick, затем подтверждает физическое прибытие и только потом пытается выполнить следующий участок. Недостаток топлива оставляет intent в ready без телепортации и начислений.
- В отличие от N63 data-only, активный N64 сохраняет **единый scope**: N54 in-memory world/fleet/credits/dock плюс все active intents и `last_dispatch_tick` с SHA-256 целостности. `restore_new` создаёт новый N57 и Registry, повторно проверяя физическое положение/транзит/маршрут. Нельзя восстановить активный runtime «поверх себя», обойти сохранение intents или повторить приказ в том же тике.
- Реализация не меняет `main.gd`, P1 save path и Rust. Не интегрирует N39 производство, пассажирские миграции, рынок или автономные решения Главы; при наличии внешнего AI система принимает лишь явно назначенный маршрут.
- `tests/n64_itinerary_runtime_check.gd` подготовлен с реальными native мирами, отправлением Sol→lane-epsilon, snapshot/reload на первом участке и отказами повтору или подделанному intent/денежному балансу. Godot test не запускался, никакого runtime PASS.
