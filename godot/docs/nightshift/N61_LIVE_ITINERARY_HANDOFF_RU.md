# N61 — направленные многошаговые маршруты в живом корабельном движке Godot

**Дата:** 12 ноября 2026. **Статус:** `CODE_UNVERIFIED`. Новая ветка `feature/godot-n61-live-itinerary-admission-20261112` поверх N57 / PR #149. N39 производство находится у другого разработчика, поэтому N61 не меняет производство и общий production TickRunner. Проверенная Windows P1 не затронута.

## Что интегрировано

- Перенесены **без изменений** скрипты `route_graph_audit.gd` (N58 / PR #146), `directed_route_planner.gd` (N59 / PR #147), `route_itinerary_admission.gd` (N60 / PR #148). PR остаётся стековым, отдельные оригинальные PR не изменялись.
- `native_itinerary_bridge.gd` принимает настоящий frozen seed Galaxy 0.6.7, сверяет граф с оригинальными `travel_routes` через N58 и преобразует только **целочисленные положительные** веса не выше Rust `u32` в формат N59. Никакие screen coordinates, fuel, velocity или time не выводятся из route weight. `gate_pairs = {}` намеренно: реальный gate transfer пока не перенесён, нельзя моделировать его как обычный полёт.
- N59 находит детерминированный кратчайший путь **по направленным рёбрам**. N61 проверяет каждый шаг через N60 `admit`, прежде чем отдавать открытый read-only план. Текущий планировщик не строит обратных путей, если в замороженном источнике их нет.
- `live_native_fleet_engine.gd` (N57) получает `plan_ship_itinerary(ship_id, destination)` — только чтение, и `depart_itinerary_hop(ship_id, itinerary)` — **ровно один физический N14 перелёт** из текущего местонахождения корабля. Перед отправлением N60 повторно проверяет весь путь/стоимость/начальную точку; N57 затем применяет прежний N21 docking admission и реальное движение на динамических координатах N43, с расходом топлива.
- После первого перелёта возвращается `remaining_itinerary`, который может быть выдан **отдельной командой после прибытия** в промежуточную точку. Никакого скрытого autopilot и мгновенной телепортации нет. Это сознательное ограничение: N54 snapshot пока не хранит **очередь автономных намерений маршрута**, поэтому автоматическая цепочка без сохранения состояния могла бы потеряться на reload.
- При восстановлении N57 в новый экземпляр движка маршрутный граф заново валидируется из исходного frozen seed; отправления в полёте остаются физически в полёте, «продолжение» нельзя выдать до прилёта.

## Регрессия

`tests/n61_live_itinerary_admission_check.gd` читает настоящий seed (8 миров) и проверяет путь:
`earth-station → lane-epsilon → lane-tau → lane-barnard`, стоимость **465** единиц маршрутного веса (115 + 150 + 200), три перехода; вариант через alpha-station стоит 475. Отвергаются: изменённая стоимость, иной промежуточный узел со старой стоимостью, повторный узел, устаревший origin, неизвестная цель, повторный приказ после начала полёта. После первой команды корабль летит только до `lane-epsilon`, доки помечают его `in_transit`. Восстановление из N54 in-memory snapshot не перелетает сразу на следующий участок и не пополняет топливо.

## Ограничения

- Тест написан, **не выполнялся** в Godot 4.7 (бинарник в агентской среде отсутствует). Файл и PR не являются доказательством runtime-паритета.
- N61 не добавляет реальную очередь долгосрочных заданий ИИ, расходы на переход через ворота, грузовые сделки, производство, контрактный диспетчер, исследование или player UI.
- Это улучшение отдельного opt-in N57 engine; пользовательский интерфейс P1 и P1 save path по-прежнему не изменены. Сначала нужен headless запуск и общая согласованная integration c N39, затем одна пакетная Windows сборка.
