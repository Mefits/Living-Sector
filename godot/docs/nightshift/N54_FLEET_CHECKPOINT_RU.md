# N54 — атомарный снимок текущего корабельного среза мира

**Статус: CODE_UNVERIFIED.** Касается **только** реализованных и действительно изменяемых доменов N40/N43/N46: Bodies/Orbits, Ships/Transit, N11 Ledger, N21 Docking. Все дополнительные фазы (N39 production, N35 contracts, AI, research, population, station stocks) **не включены** и сохранение такого мира должно отклоняться до обновления формата. В P1 сохраняем старую версию независимо.

## Обнаруженная проблема

В прежнем `ShipTickRunner` метод `checkpoint()` намеренно возвращал пустой Dictionary при включённом флоте: orbital-only P1 snapshot не хранит корабли, cargo, fuel и nonce движений. Это безопасно, но мешало даже тестовому точному snapshot корабельного среза. Просто убрать запрет нельзя: сохранение корабля на полпути без cursor приведёт к replay/дозаправке и неверным событиям.

## Реализовано

1. `ship_transit.gd`: счётчик уникальных токенов переходов теперь доступен для включения в **N54 envelope**. При восстановлении `restore_next_token` требует значение строго больше любого активного token. Token не должен повториться после reload.
2. `ship_tick_runner.gd`: отдельный метод `orbital_checkpoint_for_fleet_envelope()` получает P1-фазу через `super.checkpoint()`, но прежний `checkpoint()` по-прежнему не сохраняет неполный мир. `attach_restored_native_fleet` умеет восстановить весь динамический состав **только после валидации** staged orbital checkpoint и исходного frozen seed, N43 координат, маршрутов, fuel/cargo и транзитных nonce. Не вызывает N46 new-game seed, не перезаправляет корабли.
3. `native_fleet_checkpoint.gd`: захват и верификация единого набора орбиты+корабли+средства+докование, строгий `scope`, `schema_version`, SHA-256 canonical JSON (контроль случайной порчи, НЕ криптографическая аутентификация). Согласованность N11/N21/N40 проверяется до захвата и после восстановления.
4. `stage_restore` создаёт **новый** TickRunner, ShipState, Ledger, Docking. Если любой домен неверен, возвращает `ok=false`, не меняя ни одной ссылки старого мира. Приложение должно отдельно **одной атомарной операцией** заменить указатель общего авторитетного состояния после `ok=true`.
5. Godot JSON может превратить integer-поля в float: после checksum отдельно восстанавливаются только безопасные целочисленные ledger balances/receipts, cargo qty, transit token, docking capacity. Числа за границами точного IEEE754 диапазона отвергаются вместо округления.

## Тест

`tests/n54_native_fleet_checkpoint_check.gd` — frozen seed, 24 корабля, деньги из источника N46, N21 docking, один **явный тестовый** facility-account; снимок на тике 0 и после начала полёта; сериализация JSON в памяти; восстановление текущего топлива и transit cursor; защита от повторной начальной заправки, неправильной синхронизации dock/fleet, изменённого payload/sha, неподвижность старого мира при неудаче.

## Ограничения и следующие задачи

- **Не добавлен никакой FileAccess/сохранение на диск и не использован пользовательский путь** `user://saves/galaxy-067-p1.json`. N38 checksum-патч остаётся в своём PR; позже нужен отдельный файловый адаптер с правилом безопасных backup и проверкой Rust parity.
- Snapshot запирается на список фаз `["bodies","ships"]`. Как только интеграция включает `facilities`, `contracts` или `research`, N54 обязан перейти на расширенную схему и пока должен возвращать отказ.
- N50 crew и N51 fitting пока живут отдельными opt-in модулями, их мутации в N54 не сохранены; нельзя подключать runtime crew/fitting до соответствующего расширения schema.
- Не сохраняется отдельное состояние прибывающих кораблей, порождённых после seed; идентичность временная N4. До внедрения настоящих динамических ID такой snapshot должен отказать.
- **Godot 4.7 runtime отсутствует**, headless smoke не выполнялся. Это Draft код, не готовая пользовательская save система. Когда будут интеграционные блоки, тесты гоняются автоматически в одной сборке, не по 11 файлов на Windows пользователя.
