# N152 — макро №5 «Контракты / физическая логистика»: исходное покрытие закрыто, исполнение Godot НЕ проверено

**Исходная ветка:** frozen Rust Galaxy 0.6.7 `archive/rust-galaxy-067-reference`, `economy/contracts.rs` (1669 строк), `strategy/orders.rs` (380), `sim_server/engine/transactions.rs` (686+), `engine/contract_funding.rs` и `engine/apply.rs::commit_contract_delivery`. **Резервация N152** создана атомарно до кода: commit `76fb1fac` в `feature/godot-nightshift-20261112`, рабочая ветка `feature/godot-n152-contract-board-lifecycle-index-cleanup-20261113`.

**Вывод аудита:** собственные исходные алгоритмы контрактов и физической логистики представлены самостоятельными GDScript-компонентами нескольких PR. Последним крупным пробелом был персистентный `ContractBoard`: счётчик ID, `insert_loaded`, status/destination/faction rep-tier индексы, `post_kind_with_faction`, строгий `accept/release/mark_picked_up/mark_delivered`, очистка `drop_ship_holdings/cancel_for_facility`. **N152 покрывает этот source slice полностью, без второй финансовой системы**.

Godot parser/headless остаются работой Phase2.

### Обязательная граница N152 / N104

- N152 принимает только `before ContractBoard` и выдаёт `after ContractBoard`. **Ни одной монеты, товара или человека не перемещает.**
- `accept_after_funding`, `mark_picked_up_after_physical_receipt`, `mark_delivered_after_physical_receipt` требуют внутренние authoritative receipt fields, но **сам флаг `trusted_internal_apply` не доказывает оплату**. Только приватный движок после реального успешного N104/N97 выполнения вправе вызывать их; UI/сеть могут прислать поддельный словарь и НИКОГДА не должны обращаться к ним напрямую.
- Уничтожение судна: настоящий admin удаляет ship/DB и очищает оплаченные контрактные связи; `drop_ship_holdings` переставляет только Board row/indices, **никогда** не возвращает escrow самостоятельно. Нужен единый transaction boundary с N104 `refund_closed`. Если корабль погиб с грузом, прежний договор не переоткрывать.
- Удаление facility: `cancel_for_facility` только после реального подтверждения удаления, а source/destination location передавать **лишь если удалялся последний объект на этой локации**. Иначе отменится чужая реальная торговля.
- Сохранение: `insert_loaded` не создаёт вновь деньги, а загружает ранее существующий ContractFunding. Его ID cursor и индексы должны быть проверены против сохранённого board/ledger. Повреждённый дубликат ID в N152 fail-closed (Rust оригинал мог перезаписать строку и оставить старые ссылки, это опасное отклонение от source-parity).
- Системы N16, N26, N27, N31 были ранними scaffolding. Нельзя в Phase2 запускать N16 Ledger-проводку одновременно с N104. Если N145 создаёт полный новый индексный board snapshot, нужен ровно **один** authoritative commit и reconcile N152.check_indices, не два независимых обновления.

### Статус и ограничения

**SOURCE-COVERED макро №5** — закрыто покрытие оригинальных алгоритмов контрактов и физической логистики по отдельным исходным функциям (N15/16/25–31/N90/N97/N104/N108/N135/N145/N152); **НЕ** полная играбельная реализация. В самом N152 есть намеренно fail-closed и детерминизирующие отличия для повреждённого state и порядка HashMap; это зафиксировано, не назвать побитовое воспроизведение `Rust↔GDScript`. `CODE_UNVERIFIED`: Godot 4 parser/headless/runtime, реальный ECS/ContractBoard+money atomicity, Rust-executable parity, SAVE/LOAD replay **не запускались**. Все PR раздельны и не слиты. Сценарии написаны, но не исполнялись, структурную состоятельность проверяют только статические readback/quotes/brackets.
