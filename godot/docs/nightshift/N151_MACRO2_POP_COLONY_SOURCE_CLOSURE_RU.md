**Статус:** `MACRO2_SOURCE_COVERED / CODE_UNVERIFIED`. Полное *компонентное* покрытие существующих механик замороженной Rust Galaxy 0.6.7 теперь отражено в самостоятельных GDScript PR, но это **не означает** объединённый и работающий Godot-мир. ## Почему понадобился большой N151, а не очередная микроправка

Аудит `native/crates/sim_core/src/agents/population.rs` (769 строк), `strategy/colony.rs` (452), `strategy/colony_development.rs` (361) и ранее созданных N71/N92/N114/N118/N123/N125/N126/N127/N144/N147 показал: большая часть алгоритмов покрыта частями, но нет **единого** `tick_populations` с одной реальной оплатой каждого купленного товара и с правильным порядком всех стадий. Кроме того, N118 не учёл создание сайта через `BodyOrbit::universe_position + facility_offset_position` и различие срока контракта при наличии native Director.

## Фаза 2 — обязательный единый владелец

`native ECS World` предоставляет:
- `PopIdentity` / demographics / economy / sentiment + настоящий `AgentLod`, метку реальной локации и owner facility;
- `MarketIdentity` / `MarketPricing`/ `MarketFlow`/ `MarketHistory` и `FacilityOperations.credits`;
- `ContractBoard` единственной версии, `WorldRegistry` физические маршруты, реальные BodyOrbit coordinates и original `facility_offset_position`.

`N151.tick_populations` **не** исполняет транзакции, а возвращает staged version of all touched Pop/Market/Facility plus `population_purchase` event intentions and due flags. Phase2 exclusive engine verifies original state and **однократно** commits physical wallet/supply/market flow/ECS within one authority. N71 direct purchase, N127 production grants, N126 passenger posts and individual N114/N125/N145 tick functions НЕЛЬЗЯ запускать одновременно со staged N151 tick; N114/N125/N145 are **single downstream owners** invoked *only when due* and after real snapshot revalidation, with no double pay.

**Существенные тонкости оригинала:**
1. `tick_populations` first checks `tick % (5×mult)`; if no production/consumption due, it returns **before** migration/contract sweep. N151 preserves that early-return.
2. `AgentLod.try_fire` только допускает активную популяцию, не масштабирует consumption на skipped ticks (на Frozen Rust далекие колонии действительно «ленятся»; это legacy баланс).
3. Любой из запросов `Food, Water, EmergencyWater` — отдельная физическая попытка покупки, затем **любой** частичный/неудачный запрос вызывает one shortage flag для sentiment этого Pop.
4. Прямой `Population::post_passenger_contracts` в замороженном Rust фактически не публикует контракт; нельзя ошибочно включить исторический N126 и придумать миграцию.
5. Исходник не реализует прямой `growth_rate` в цикле — `PopDemographics.growth_rate` есть, но **нет** population growth logic в frozen tick. Новое размножение/уровни населения — Фаза 3 отдельным решением.
6. Нехватка богатства — не «самоисправляемая» бесплатная еда. Функция purchase уменьшает реальные деньги домохозяйства, начисляет ровно эту сумму настоящему владельцу станции и записывает реальное сокращение складских запасов.
7. Из-за `f32` в Rust и `f64` в GDScript настоящая долгосрочная precision parity потребует отдельной Godot-Rust проверки. Для материального `purchase_consumption` N151 явно конвертирует к f32 и при кассовом оверране снижает на один f32 ULP. Для `migration` исходник считает деньги через i128: N151 допускает точные целочисленные значения, а аномальные миллиарды, где нет безопасной i64-арифметики, отмечает `native_i128_proportional_transfer_required`; не округляет несуществующие кредиты.
8. N151 `colony.rs::commission` ожидает реальную внешнюю callback к `facility_offset_position`, не генерирует видимые позиции сам, и не создаёт бесплатные корабли. Проверка наличия существующего site жёстче исходного, чтобы физически не публиковать контракт для несуществующего объекта. Источник Rust может использовать `Plan.site_id` напрямую и не проверять здесь ещё раз.

## Реальный статус

Пять source GDScript files + source-derived check fixture + этот отчёт; все сохранены в отдельной рабочей ветке. Готовы для настоящего source-to-Godot integration audit. **`SOURCE-COVERED` означает, что все названные функции физического населения и колонизационной стратегии имеют исходные компоненты**. Не гарантирует идентичную исполнения при невалидных/f32/U32/i128 крайних данных и **не является VERIFIED**. Проверены GitHub readback и статическая структура строк/скобок, но **не запускался Godot 4**, не выполнялся headless parse, не сравнивались реальный Rust и GDScript, не сливались раздельные Draft PR. Физическое построение колонии, население, контракты и кошельки начнут работать только после Phase2.
