# N23 — производственная фаза игрового тика

Статус: **CODE_UNVERIFIED**. Godot Runtime не запускался.

## Срез

Новый `scripts/sim/production_tick_runner.gd` наследует P1 `tick_runner.gd` и подключает N8 `production_coordinator.gd` только после явной загрузки реальных счетов и складов. Порядок двух **реализованных** фаз: `bodies` → `facilities` → `tick_completed`. Отсутствующие фазы Rust не выдаются за работающие. Счётчик тиков и пауза/step остаются у базового SimClock. N8 отвечает за единичную выплату зарплаты, складской расход, выпуск, конкуренцию за работников и запрет повтора тика.

Семантика сверена с замороженным `native/crates/sim_server/src/engine.rs` (facilities после drains и до construction_labor), `workforce.rs`, N6/N8. Прямые вызовы `run_tick` не нужны UI; фабрики не создаются из seed автоматически. Нет новых товаров/денег или мгновенной доставки. `checkpoint` включает N8 ledger, производство и инвентарь; restore валидирует экономику до замены орбитального состояния.

## Выбор инструмента

Штатный GDScript RefCounted/наследование и существующий Coordinator: не нужен SceneTree Node на фабрику, ECS, внешний scheduler или новый ledger. Для большого количества фабрик следует измерить стоимость сортировки ID и копирования snapshot в Godot Profiler, прежде чем оптимизировать.

## Ограничения

- Это opt-in слой поверх N8, а не автоматически включённая экономика существующей P1-сцены.
- Нет подключения N3 cadence/events, населения N7, глобального рынка и транспорта. При объединении N3 потребуется перенос facilities внутрь полного фазового цикла, не второй параллельный тик.
- Нет синхронизации `tick_completed` при restore: базовый P1 испускает сигнал до завершения подстановки staged экономики. Не подключать UI к этому сигналу при restore без дополнительного post-restore уведомления.
- N8 `run_tick` пока выполняет одну смену на каждый тик; периодичность Rust должна быть отдельно проверена перед балансировкой.
