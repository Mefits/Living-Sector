# N63 — сохраняемые намерения многошаговых маршрутов

**CODE_UNVERIFIED.** Стек поверх N61 / PR #150. Ветка N63 не меняет проверенный Windows P1, main/stable, Rust-эталон или чужой N39 production.

## Что добавлено

- `scripts/sim/ships/itinerary_intent_registry.gd`: один независимый `RefCounted` с явными intent-записями `ship_id`, `operation_id`, исходный направленный маршрут, `index` и фазой `ready/flying/done`.
- Путь принимается только после повторной проверки настоящего графа через N60 `RouteItineraryAdmission`; повтор операции с тем же ID и тем же путём идемпотентен, с новым содержимым/вторым active intent — отказ.
- `confirm_departure` допускается только **после настоящего N14 depart** и сверяет from/to физического транзита; `confirm_arrival` допускается только при фактическом прибытии на следующую точку. Реестр сам корабль не перемещает, топливо/деньги не списывает и маршруты не «пропускает».
- `snapshot/restore` стабильно сортируют записи и проверяют каждый маршрут, индекс, статус, местоположение и действующий транзит против текущего `ShipState` и directed-graph. Восстановление — атомарное, без частичного применения записей.
- Headless `tests/n63_itinerary_intent_check.gd` готов: исходный маршрут Sol→Barnard, повторы ID, запрет второго intent, отказ преждевременному arrival, валидный ready/flying snapshot и отказ подменённому state без изменения старого реестра.

**Важная граница:** этот реестр — самостоятельный data-only слой, **пока не включён в N54 checkpoint и не даёт скрытого автопилота**. Активировать N64 dispatch/автоматическое продолжение маршрута нельзя, пока не будет сохранения intent вместе с остальными mutable domains. Это избежит потерянных приказов после reload. Прямые пользовательские тесты Godot до завершения всего переноса не назначаются. Runtime проверки в Godot отсутствуют.
