# N90 — экономические ShipAction и транзакционные подтверждения Rust

**Этап:** фаза 1, компонентный перенос замороженной Rust Galaxy 0.6.7. **Статус:** `CODE_UNVERIFIED`, отдельный Draft PR. **Без запуска Godot, без слияния в P1 и без комплексных тестов** по согласованному плану пользователя.

**Источники:**
- `native/crates/sim_core/src/agents/ship/actions.rs`: `execute_ship_action`, `poll_transaction`, `request_transaction`, `affordable_quantity`.
- `native/crates/sim_core/src/agents/ship/transactions.rs`: `ShipTransaction` (Accept, Buy, Sell, Refuel, Mine, Embark, Deliver), `TransactionSlot`, `PendingTransaction`.
- `native/crates/sim_core/src/economy/commodities.rs`: 17 исходных Commodity (включая RareOre, CrystalOre и QuantumCores).
- `native/crates/sim_core/src/simulation/commands.rs`: `RequestShipTransaction`, `RequestRefit`, `RequestGateJump`.
- Для допусков покупателей: `agents/faction_relations.rs` и реальная память цен `ShipMemory.price_knowledge` (их авторитетные значения обязан предоставить общий контекст, N90 не генерирует рынок).

## Файлы и компоненты

1. `godot/scripts/simulation/ai/native_ship_transaction_slot.gd`: **одна** незавершённая операция на корабль, номер `checked_add`, запрос `RequestShipTransaction(request_id)`, подтверждение результата от Apply-фазы, опрос в BT. `None` → `Running`, `Ok` → `Success`, `Err` → `Failure`. Неподходящая к текущему листу транзакция снимается и даёт `Failure`. Перепланирование очищает pending, сохраняя sequence. В Rust mailbox **временный**, а не реестр долговременных receipts — N66 занимается отдельной проблемой повторов при reload.
2. `godot/scripts/simulation/ai/native_ship_economic_actions.gd`: чистое выполнение экономических листьев BT, при котором команды формируются, но **не применяются к игровому миру**. Вход: физическое состояние ship, цена из наблюдений памяти, репутация/отношения и множитель цены от авторитетных систем, ephemeral transaction state и tick.

### Поведение листьев из замороженного Rust

- **Refuel**: ожидает ответ Apply, при подтверждённой заправке сверяет фактическое состояние бака; если бак ещё не полный, отправляет следующий chunk. Готовность: `fuel >= capacity - 0.001`. Отсутствие местонахождения даёт Failure. Сам лист не заполняет бак и не выдумывает топливо продавца.
- **Buy**: при отсутствии pending требует известную цену на месте, разрешение `commerce_allowed` с учётом договора/эмбарго, подтверждённый `market_buy_multiplier` исходной системы отношений и реально доступные кредиты/ёмкость трюма. Количество `min(qty, cargo_free, floor(credits/adjusted_price))`. В Apply снова проверяются реальные деньги, stock и текущая цена.
- **Sell**: подтверждение проверяется **до** анализа груза — Apply мог убрать последнюю единицу. `qty=0` означает весь остаток конкретного товара; иначе `min(qty, available)`. Используется `min_unit_price` с multiplier; авторитетный рынок обязан проверить платежеспособность покупателя.
- **SellAll**: после успешного подтверждения возвращает Running, пока вообще остался груз, даже если часть товара не имеет текущей цены. На следующем тике выбирает первый **лексикографически** доступный Commodity, для которого известна цена; отсутствие продаваемого товара даёт Success. Не продаёт более одного товара за одну PendingTransaction.
- **Mine**: первоначально проверяет подходящий ответ PendingTransaction. Физический корабль должен стоять у точного тела `location/body_id`, не быть в полёте/доке и иметь место в трюме. Продолжительность смены: **3 × tick_multiplier** игровых тиков, хранится в `dock_dwell_start_tick`; после ожидания отправляет Mine-запрос, `quantity=min(planned, free)`. Реальное извлечение ресурсов и расход месторождения принадлежат Apply.
- **AcceptContract / EmbarkPassengers / DeliverCargo**: создают ровно один запрос и ждут Apply. **PickupCargo** — настоящий Rust no-op Success (в сохранённом коде покупка уже выполняет pickup).
- **Refit**: только если физически docked; `RequestRefit(slot,slug)` и немедленный BT Success. Проверка stock, цены, retrofit_points и перестановка модулей в Apply.
- **GateJump**: исходное правило `current_location == src_gate` и `ship_credits >= 50` (это **не** расчёт истинной платы за ворота). Публикуется `RequestGateJump`, Success и **отдельное значение намерения локального speculative position patch**, поскольку оригинальный Rust до Apply временно меняет ship position. В N90 безопасный pure адаптер этот patch только возвращает, **не телепортирует сам**. Исключительная Apply-фаза должна проверять реальную цену/ворота и исходное состояние; незаслуженное перемещение предотвращается на этапе единой сборки.

## Контракт границ

- **Не дублируем N88** — Idle, Dock, DockAtShipyard, Undock, DockDwell, Rest, Construct остаются в `native_ship_action_lifecycle.gd`; Travel — отдельный транспортный модуль. N90 покрывает оставшиеся **экономические и физические листья**.
- **Не меняем N39**: никакой реализации фактического списания денег, добычи, заправки, производства или склада продавца без единого мира и оригинального Rust apply.
- **Не заменяем N66**: числовые запросы в Rust transaction slot — не устойчивая защита от дубликатов после сохранения; требуется другая долговременная схема идемпотентности.
- `step` возвращает `status`, обновлённый **только копированный локальный mailbox/timer state**, `commands` и `flags`. Шип/рынок/реестр не мутируются; идентификатор actor-entity должен добавить исполнитель.
- При отсутствующих источниках treaty/цены/отношений отказ, а не придуманная нейтральность. Команды исполнять **только** после эксклюзивного Admit+Apply при сборке второй фазы.
- Rust допускает некоторые неидеальные крайние случаи (например, GateJump оптимистически переставляет локальную позицию), они задокументированы, а не спрятаны под обещанием гарантированной транзакции.

## Быстрая статическая сверка

Формулы/ветвления сверены с Rust-источниками, файлы и `res://` пути проверяются. Никаких многократных headless/Godot прогонов и пользовательских ZIP на этой стадии.

## Следующий крупный неизбежный остаток Rust → GDScript

Глобальный `apply_ship_transaction` с фактическим балансом маркетов, подтверждённой оплатой/перемещением груза и месторождений; полноценный контрактный escrow/доставка, gate fee, shipyard refit и crew XP после фактического Apply. Эти операции должны быть отдельными блоками без перекрытия активного N39; N90 только **портирует BT-границу + транзакционный mailbox**.
