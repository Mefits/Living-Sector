# P1 — статический аудит границ модели

**Статус: CODE_UNVERIFIED.** В ночной среде Godot Runtime отсутствует; этот документ не является зачётом runtime-приёмки.

## Что исправлено

1. Импортёр Galaxy проверяет, что каждое тело имеет конечные числовые `orbit_period > 0` и `0 <= current_angle < 360`. Это соответствует данным замороженного Galaxy 0.6.7 и не создаёт запасов, кораблей или денег.
2. `WorldModel.load_seed()` проверяет форму входных массивов/объектов и орбитальные значения до публикации изменяемого состояния. Модель продолжает работать на глубокой копии, поэтому P1-орбиты не мутируют данные импортёра.
3. `queue_control()` больше не принимает значение у команд `pause`/`resume`; правило совпадает с `restore_checkpoint()`, поэтому некорректная живая команда не может стать несовместимым сохранённым событием.
4. Добавлен `tests/p1_audit_check.gd`: проверяет границы seed, изоляцию копии, дубли ID, диапазон орбиты и симметрию live/save command validation.
5. `RUN-P1-SMOKE.cmd` запускает три коротких headless-проверки и сохраняет отдельный `logs/p1-audit-smoke.log`.

## Почему так

Для P1 не нужен плагин: штатные `Dictionary`, `Array`, `is_finite`, `JSON` и headless CLI Godot покрывают валидацию и локальную диагностику. У проверяемой модели всего 47 тел, а обязательная копия уже отделяет симуляцию от UI/импортёра; добавление Node на тело или сторонней схемы валидации здесь только увеличило бы цену переноса.

Исходная формула остаётся прежней: `(angle + 360 / orbit_period * tick_scale) mod 360`, где `tick_scale = world_speed / TPS` по Rust `simulation/config.rs` и `BodyOrbit::advance`. Никаких единиц «игровой час» этот аудит не вводит.

## Утренний запуск

В Windows из каталога `godot`:

```bat
RUN-P1-SMOKE.cmd
```

Ожидаются строки `P0_SEED_PASS`, `P1_PARITY_PASS` и `P1_AUDIT_PASS`. До такого запуска все изменения данного блока остаются `CODE_UNVERIFIED`.
