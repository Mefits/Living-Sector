# P1 — реально перенесённое время, орбиты и первый checkpoint

**Источник истинных правил:** Rust commit `6e40615be95cc6ddbabe21c3b94def5c52f8622d`.

- `native/crates/sim_core/src/simulation/config.rs`: `TickConfig`, базовые `TPS=8`, `world_speed=0.25`, `tick_scale = world_speed / ticks_per_second`, `tick_multiplier = round(TPS / world_speed)`.
- `native/crates/sim_core/src/agents/celestial_body.rs`: `BodyOrbit::advance`, `current_angle = (angle + 360 / orbit_period * tick_scale) mod 360`.
- `native/crates/sim_server/src/engine.rs`: команды управления принимаются до игрового тика, разрешён паузный `Step`, порядок фаз; на P1 работает **только фаза орбит небесных тел**. Важно: оригинальный Rust также крутит орбиты станций с собственным временем; **они ещё не перенесены**.

## Реализованные GDScript файлы

| Файл | Что делает | Ограничение |
|---|---|---|
| `scripts/sim/clock.gd` | Накопитель времени для фиксированных 8 TPS, пауза, пошаговая отладка, ×0.25–×16, bounded catch-up | До 16 шагов за кадр, после долгого лага не пытаемся моментально догонять весь пропущенный реальный интервал; это безопасное отличие от серверного планировщика |
| `scripts/sim/world_model.gd` | Единственная writable модель P1; точное обновление 47 углов небесных тел | Корабли, станции, экономика и рабочая сила пока неизменны |
| `scripts/sim/tick_runner.gd` | Очередь команд, один исполнитель тиков, снимки; запрещает неподдерживаемые экономические команды | Порядок всех native-фаз задокументирован; выполнена только `bodies` |
| `scripts/sim/save_state.gd` | Godot `FileAccess`, JSON v1, запись через `.pending`, возврат к `.bak` на ошибке; сохраняется `user://saves/galaxy-067-p1.json` | **В checkpoint P1 находятся только тик, часы, очередь управления и углы орбит**. Не объявлять сохранёнными контракты, счета, перелёты, колонизацию и ИИ, их нет в Godot |
| `scripts/main.gd` | Кнопки паузы, шагов, скорости, сохранения и загрузки + угол тела в инспекторе | Явно отображает P1, а не «полную игровую симуляцию» |

## Инварианты

- **Одна модель мира** и её экранная проекция. Ни одна UI-анимация сама не создаёт реальный контракт или ресурс.
- При загрузке checkpoint должен совпасть с текущим замороженным seed-фингерпринтом, идентификатором сценария `galaxy-067` и схемой v1. Иначе загрузка отклоняется до изменения текущего мира.
- Орбитальный checkpoint сохраняет углы **каждого** из 47 тел и сначала проверяет весь набор на конечные значения внутри `[0,360)`. Частичный/повреждённый файл не применяем.
- Очередь управления не умеет выдавать деньги, строить фабрики или назначать полёты. Такие команды отвергаются до P2/P3/P5.
- Пауза и `Step 1/8` не умножают количество списаний: на данном этапе никаких списаний **нет**.
- При ×16 ровно `world_speed/TPS=2` игровых единицы на тик. **×16 ускоряет движение по формулам, а не автоматически создаёт 16 запусков производственной фазы за кадр.**
- `Clock.tick_multiplier()` намеренно повторяет округление Rust, включая 0 при TPS=8 и world_speed=16. Перед переносом нативных интервалов P2/P3 нужно явно проверить обработку нулевого значения у каждого потребителя; нельзя делать `tick % 0`.

## Короткая локальная проверка (без Rust и стороннего плагина)

Из папки репозитория, с установленным стандартным Godot 4:

```powershell
Godot.exe --headless --path godot --script res://tests/p0_seed_check.gd
Godot.exe --headless --path godot --script res://tests/p1_tick_save_check.gd
```

Второй сценарий должен напечатать `P1_PARITY_PASS`. Он проверяет: значения времени Rust, отсутствие тиков на паузе, ровно 8 ручных шагов, угол Earth по формуле, отсутствие изменений запасов/кораблей/станций, отклонение неверного fingerprint, save/reload, и один шаг при ×16. Файл теста временный в `user://tests/`, удаляется после успешной проверки.

**Эти сценарии ещё НЕ запускались в Godot**: в доступной среде нет исполняемого Godot. Статусы в трекере остаются `CODE_UNVERIFIED` либо `IN_REVIEW`, никогда `VERIFIED` на основании исходного текста.
