# Living Sector — Figma UI baseline / SystemBalance

Основа: https://www.figma.com/make/ecvrssCEMaMqUObXlDkLzN/Living-Sector-Game-Interface

Рабочая ветка: `feature/SystemBalance`. Не заводить другую UI-ветку без решения пользователя.

## Зафиксированные решения

- Figma Make — визуальный эталон: сдержанный industrial sci-fi, `#0B171E`, `#31505A`, `#53B5AC`, компактный top HUD / left rail / right outliner, карта остаётся главным рабочим пространством.
- **Нельзя делать Windows XP-подобную раскладку из стандартных кнопок:** воспроизводить цвета, типографику, состояния, границы, плотность и компоновку.
- Большие окна — только по запросу, не постоянные 50% экрана.
- Первый перенос Godot: `godot/scripts/view/strategy_ui.gd`, запущен внутри уже существующей карты и N158/N39 мира, без второго симулятора.
- Должна быть **явная область учёта**: «Сектор — все рынки и все фракции» или «Выбранная колония». Не смешивать с бухгалтерией конкретной фракции. В обозревателе нет автоматически выбранной «игровой» фракции.
- Верхние закреплённые показатели — население, еда, руда, металлы, Energy Cells, вода. Это запасы рынков (кроме населения), а не залежи или приток в тик. Не рисовать фальшивые `+38` и `−8` без истории.
- «—» означает неизвестное значение; нулевое значение допустимо только из подтверждённого источника.
- Карта, планеты, корабли, работа предприятий и оплаченные смены должны использовать реальные ID и источник N39; никаких вымышленных построек/товаров/перевозок.
- Временно `--p2-legacy-ui` позволяет вернуть прежнюю широкую панель для диагностики.

## ОБЯЗАТЕЛЬНО ДЛЯ СЛЕДУЮЩЕЙ ИТЕРАЦИИ FIGMA

Пользователь просил **наглядные экономические графики**; не забыть при возвращении к Figma. Проработать несколько графиков в окнах колонии и экономики: запасы ресурсов по тикам, выпуск/потребление, население, расходы/доходы. Показывать историю только если она действительно накоплена; не добавлять фиктивные значения и не копировать N39 World каждый кадр. Сначала выбрать интервалы и малый буфер наблюдений, оценить FPS.

## Объединено непосредственно в SystemBalance (17.11.2026)

С выборочным переносом из draft PR #270 `feature/SystemBalance-colony-roads-20261117`:

- `godot/scripts/star_system_view.gd` — прежняя схема Сол, непрерывная камера, реальные N43 станции/корабли; поверх исходных четырёх объектов Земли — схематические дороги и до 5 точек рабочей активности на связь. Это **не поставки груза**.
- `sol_physical_assets_projection.gd` — read-only `shift_workers` из подтверждённых `work_shift.workers`.
- `colony_roads_projection.gd` — детерминированные связи только объектов одного source `body/location`, окно последних 12 тиков, перерисовка 30 Гц только на открытом глобусе.
- `facility_labels_ru.gd`, `colony_quick_projection.gd`, `colony_context_projection.gd` — исходные реальные данные предприятия/колонии/корабля; старые классы `colony_context_cards.gd` и `colony_quick_strip.gd` сохранены как совместимые UI-модули, но их широкую компоновку не включали.
- `strategy_ui.gd` — новый стиль Figma: постоянный верхний HUD, компактный левый навигатор, правый список реальных объектов, контекстная карточка выбора на карте, большие окна только по запросу, вкладки колонии/предприятия/корабля, реальная физическая стройплощадка, локальные склады и рыночные товары.
- `main.gd` — входные события карты/кораблей, один уже завершённый N39 frame, native worker tick для дорожных точек, смена глобального UI 100/115/125/140%. `StarSystemView.set_ui_viewport_scale` компенсирует **только графическое** уменьшение логического viewport на больших UI scale (профиль Earth→Luna остаётся оригинальным).
- Пауза, скорости, сохранение, загрузка, центрирование и переключение сектора/системы доступны в новом интерфейсе. `--p2-legacy-ui` оставляет старый внешний вид для диагностики.
- Нельзя смешивать статусы из отдельных фракций с ресурсами одного игрока; пока игрок наблюдатель, закреплённая строка имеет явно объявленную область — весь сектор или выбранную колонию. Руда и металлы присутствуют, неизвестный показатель «—», не выдумываем темп потребления или «дни еды».

## Не завершено

- Визуальное сравнение Windows 1920×1080 и 1366×768 с оригиналом Figma. Godot headless проверяет дерево UI, но не гарантирует визуальное совпадение в Windows.
- Вне этих экранов некоторые Figma страницы (ИИ-управление, research, сложные контрактные переходы) — будущие задачи, не подменять отсутствующие игровые механики примерами.
- Нельзя принимать дорогие графики за готовые: при возврате к Figma разработать историю запасов/выпуска/населения и отдельный компактный буфер наблюдений. **Напоминание пользователя про графики сохраняется как обязательная задача.**
- Отдельные экономические локации наземных предприятий, реальная перевозка по дорогам и новая механика АЦ — не включались.

## Проверка флота после Windows-скриншота (17.11.2026)

- Пользователь видит тик 3354, карту Земли/Луны, статус 24 кораблей и жалуется, что рейсы не видны. Это **не тот же World/N38**, что тестовое начальное состояние; не утверждать, что причина на тике 3354 доказана без чтения соответствующего checkpoint.
- Источник истины: реальный N39 `ships[id].transit`. В стартовом прогоне `godot/tests/p2_real_ship_activity_probe.gd` (96 оплаченных тиков) работают N140, N84, N146 и N14: по 3 активных `mine_ice`, на тике 64 три в полёте, на тике 96 два, включая шахту `mine-near-earth` в Sol; отсутствуют фиктивные анимации.
- Остальные 21 корабль (6 colonizer, 6 freighter, 3 courier, 3 hauler, 3 tanker) в этом коротком окне не получили заданий: все 24 имеют `memory.price_knowledge` только для **одного** рынка. `unified_n83_trade_route_planner.gd` отсекает `known.size()<2`, поэтому N83 `trade_plans=0`. N153 `accepted=0`, так как в начальных 96 тиках `contract_board.contracts` пуст.
- Это означает **ограничение автономного запуска торгового/контрактного флота**, а не отсутствие N14 физики. Следующая системная задача — дать N83 легитимные физически приобретённые сведения хотя бы о двух рынках или создать реальный экономический спрос/контракты, не обходя комм-систему N51, N9 оплату, физические N14/N21/N97 и не создавая рейсы «для красоты». Особенно важно для T1, где наземные Earth предприятия ещё имеют общий `earth-station` адрес.
- В `strategy_ui.gd` исправлена контекстная ошибка «КОРАБЛЬ → ДАННЫЕ о Земле», отделён общий технический дамп от предметных окон, добавлены видимые статусы N14 «в полёте/в доке/без рейса» и фактические N153/N83/N84 счётчики. Исправлен UX: выбор объекта открывает компактную карточку, а большое окно — только по «Подробнее». Размеры шрифтов увеличены.
- В Windows-сохранении пользователя из тика 3354 при следующем скриншоте проверить «ФЛТ» в левом меню: действительное число flying и число судов с `price_knowledge.size()≥2`, последнее отклонение N153, наличие N83 торгового плана; только после этого искать точную причину долгосрочного простоя.

Обязательные тесты: `p2_strategy_ui_layout_scene_check.gd` и `p2_real_ship_activity_probe.gd`; GitHub short gate выполняет их без искусственных полётов.


## Три замечания Windows UI — выполнено (17.11.2026)

1. **FPS/производительность:** постоянная верхняя компактная строка `FPS / SIM / UI p95 / PING —`. Все показатели берутся из уже существующего `UIFrameProfiler` и N158 worker timing; никаких повторных снимков N39. В локальной игре network ping неприменим, `—` не маскирует сетевую задержку. Наведение раскрывает подробные CPU p95/худшие кадры.
2. **Суда в окне планеты:** `ship_body_projection.gd` связывает реальные `N39 ships[id].location` с идентификатором тела исключительно через `world.facilities` или `world.nav_sites` N43. Полётный `transit` исключён из списка прибывших; `docked_at` показывается отдельно, поэтому «в локации планеты» не выдается за несуществующую физическую посадку. В контекстной карточке планеты счётчик + первое судно, в окне «Обзор» сводка, «Логистика» задачи, реальные локации, стыковка, контракты и кликабельные переходы к судам.
3. **Правый список → карта:** при выборе корабля из аутлайнера `main.gd` вызывает `StarSystemView.select_ship` на том же source ship ID, `reveal_ship` центрирует текущую real N14 позицию либо фокусируется на теле, к которому по N43 относится неизлетевший корабль. Физику и навигацию не подменяет фиктивной анимацией.

Regression: `godot/tests/p2_strategy_ui_layout_scene_check.gd` покрывает реальную Control-иерархию и источниковые N43 nav_sites/планету/два местных корабля, исключает судно в пути, проверяет FPS и переходы. `_worker_gui_smoke_pump` через настоящий N158 worker теперь нажимает на корабль в новом outliner и убеждается, что выделен тот же источник `StarSystemView._selected_ship_id`.
