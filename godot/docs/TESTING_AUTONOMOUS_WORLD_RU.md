# Living Sector — GUT и автономная проверка мира (без игрока)

**Контракт:** Godot 4.7.2 Standard; оригинальная Rust Galaxy 0.6.7 стартовая галактика; единый `N158/N39/N9`. Без мандатов, без изменения баланса, без тестовых бесплатных товаров и ручного управления кораблями.

## 1. GUT 9.7.1

**Основание выбора:** `godot/docs/GODOT_TOOLING_DECISIONS_RU.md` уже выбрал [GUT](https://github.com/bitwes/Gut) как основной unit-test framework. Официальная таблица совместимости: ветка `godot_4_7`, релиз `v9.7.1` для Godot 4.7.x. Upstream закреплён **точным commit** `aeb5d4f3f7f0a6c9b5e178876d6c99b791fda605` (MIT).

Почему не добавлены 259 сторонних файлов: это готовый внешний плагин (~2,5 МБ), а не игровые исходники. Установщики скачивают **целиком оригинальный `addons/gut` из фиксированного commit**, включая его LICENSE, без изменения других файлов upstream. `godot/addons/gut/` находится в `.gitignore`. Библиотека намеренно не является обязательной зависимостью обычного запуска игры.

Тестовые исходники хранятся в `godot/testing/gut/specs/test_*.gd.txt`. Это **полные GDScript-сценарии, а не заглушки**, но с суффиксом `.txt`, пока GUT не установлен. Иначе главный Godot parser проверял бы `extends GutTest` до установки плагина и ломал бы обычную F5/сборку. Установщик копирует их в `godot/tests/gut/test_*.gd` для настоящего исполнения, не меняя шаблоны.

### Windows (одна команда)

1. Обновить рабочую ветку через GitHub Desktop.
2. Открыть `godot/testing/gut/run-gut.cmd` с путём к своему Godot 4.7.2 EXE в аргументе, например:

```bat
godot\testing\gut\run-gut.cmd "D:\Godot\Godot_v4.7.2-stable_win64.exe"
```

При первом запуске скрипт скачивает pinned GUT, материализует тесты, запускает editor import, затем выполняет GUT CLI. При желании UI-панель можно включить в Godot: Project → Project Settings → Plugins → Gut. Для самого CLI это не нужно. Важно: нужен доступ к GitHub **только при первой установке**.

### Linux / CI

```bash
bash godot/testing/gut/install-gut.sh
godot --headless --path godot --editor --import --quit
godot --headless --path godot --script res://addons/gut/gut_cmdln.gd -gdir=res://tests/gut -gexit
```

Если плагин уже установлен, установщики обновляют локальные тесты без повторной загрузки.

Первые unit-тесты: N84 BehaviorTree (один leaf за тик, сериализуемый cursor, отказ от ложных команд), N9 Ledger (двухсторонняя оплата, replay guard, insufficient funds), N38 guard (точность денег и физического склада).

**Не мигрировать все ~132 legacy-теста сразу.** Оригинальные `extends SceneTree` тесты нужны для сквозных проверок и продолжают работать отдельно.

## 2. Autonomous World Test — честный clean seed

Запуск на Windows:

```bat
godot\testing\gut\run-autonomy.cmd "D:\Godot\Godot_v4.7.2-stable_win64.exe" 420
```

На Linux/CI:

```bash
LS_AUTONOMY_TICKS=420 \
LS_AUTONOMY_REPORT="$PWD/godot/logs/autonomy/report.json" \
godot --headless --path godot --script res://tests/p2_autonomous_world_observer_check.gd
```

В `LS_AUTONOMY_TICKS` можно указать от 1 до 30 000. По умолчанию 420; замеры 1000, 10000 и 30000 — **отдельные длинные прогоны**, не включать в быстрый push-CI.

Этот тест **не устанавливает искусственную нехватку и не выдаёт игровых команд**. Каждые 25–250 тиков делает один N38 checkpoint и сверяет источник N39 Schema, фактические счета N9, историю квитанций, запасы и количество объектов. Он записывает `report.json` с наблюдениями: полёты, N104 status, N15/N21 квитанции, новые станции и население, исследовательские квитанции, TPS, время и память.

**Условия базового PASS:** реальный N158 продвинул каждый тик без отказа фаз; N39/N9 совпадали; рынок и записи N9 действительно менялись. Если за 420 тиков в clean seed не было спроса и перелётов, это **честный 0 и НЕ доказательство исправности автономного грузового рейса**. Отчёт различает `observed_any_flight=false` и настоящий PASS модели.

## 3. Дополнительные обязательные приёмки (уже существуют)

- `res://tests/p2_autonomous_multitick_delivery_restart_check.gd`: контролируемый **реальный** N135 дефицит, источники и оплаченные N104/N153/N14/N21/N15 рейсы со спасением/возобновлением; без телепорта и фальшивых кораблей. Запускать отдельно, поскольку он может занять до 6000 тиков.
- `res://tests/p2_unattended_autonomous_flight_check.gd`: альтернативная строгая 12 000-тиковая автономная перевозка.
- `res://tests/p2_stage2_clean_seed_420_tick_acceptance.gd`: реальная интеграция clean seed, N38 сохранение на 360-м тике и повторное выполнение. Этот файл **закреплён за другим исполнителем**, не изменять его из блока GUT.
- N143 paid research, B1–B4 colony, N134/N91 construction: продолжить отдельные сквозные приёмки, не считать успешный unit-test доказательством целой системы.

## 4. CI — только по запросу / одноразовая проверка интеграции

Новый отдельный workflow `.github/workflows/godot-autonomy-gut.yml` запускается вручную с параметрами `ticks` (420) и `strict_delivery` (выключено). Единственный автоматический push-триггер предусмотрен **только для первоначального добавления самого workflow**, чтобы проверить установку GUT. После него регулярные push не должны гонять экономику и скачивать Godot каждый раз. Результаты и JSON публикуются как артефакт `living-sector-autonomy-evidence`.

**Внимание:** успешный Linux headless/CI не подтверждает FPS, UI и Windows export. Для Windows после Stage2 всё равно нужен обычный F5 и проверка долгой партии. Тесты не меняют баланс, архитектуру и смысл Rust-механик.
