# Living Sector → Godot: генеральный план переноса (редакция 1)

**Цель:** перенести **существующую игру по исходному коду и данным**, а не создать похожую игру по описанию. Упростить технологический стек, но сохранить игровые механики, их ограничения и подтверждённые исправления. Внутри Godot использовать GDScript сначала; тяжёлые вычисления выносить в C# / GDExtension **только после измерений**.

## 0. Что заморожено и что является истиной

- **Rust-эталон:** [`archive/rust-galaxy-067-reference`](https://github.com/Mefits/Living-Sector/tree/archive/rust-galaxy-067-reference), commit `6e40615be95cc6ddbabe21c3b94def5c52f8622d`.
- **Разрабатываем Godot** в `feature/godot-port-phase-0` и следующих ветках переноса; старые stable/main и архив не переписываем.
- **Исчерпывающий реестр замороженных файлов:** [`SOURCE_INVENTORY.json`](SOURCE_INVENTORY.json), **793 файла**, каждый с исходным путём, git-blob-хешем и предварительным решением. *Ни один файл не считается молча выброшенным.* Если цель файла непонятна — статус «проверить», не «удалить».
- **Источник текущего мира:** `native/priv/galaxy/data/` — 8 JSON систем, `factions.json` (3 фракции), `tuning.json`, `resource_grades.json`. Не смешивать без проверки с `native/priv/genesis/data/`, `native/priv/data/` или исторической `priv/`.
- **Важное открытие аудита:** в репозитории есть отдельное дерево **`crates/` (224 файла)**, отличное от `native/crates/`. Из 224 корневых файлов: **91 отсутствует** в native (прежде всего ассеты Bevy), **41 существует, но имеет другой git-хеш**, **92 совпадают**. Сначала классифицируем уникальные функции, исходные SVG, шейдеры, аудио и лицензии; затем решаем, использовать ли их.
- Пользовательская Windows-компиляция Rust успешно завершилась, краткий запуск подтвердил 8 систем/3 фракции, но **HTTP 404 при попытке экономического мандата не устранён**. Не выдавать это за полную приёмку экономики.
- Базовая договорённость: **сомнительное сохраняем в реестре**, не переписываем всё в активную игру без необходимости. Отложенное — это не забытое.

## 1. Порядок и дисциплина

1. Одно направление за итерацию, обычно **3–5 связанных задач**, одна ветка/PR на блок. В каждом PR обновляются [`MIGRATION_TRACKER_RU.md`](MIGRATION_TRACKER_RU.md) и при необходимости исходный реестр.
2. У каждого пункта есть ID, источник Rust, предполагаемый Godot-файл/слой, **один критерий приёмки**, статус и ссылка на доказательство. Статусы: `TODO`, `CODE_UNVERIFIED`, `IN_REVIEW`, `VERIFIED`, `DEFERRED_PRESERVED`. «Файл написан» ≠ «игра работает».
3. Паритет проверяется по **результату и неизменности инвариантов**: входы, выходы, реальные расходы/остатки, порядок событий, ID и причины блокировки. Не требуется повторять классы Rust один к одному.
4. Не менять одновременно правила баланса и язык; сначала воспроизвести **известные значения**. Изменения баланса/геймдизайна — отдельный PR после сравнения.
5. Вместо больших прогонов: минимальный статический тест + 1 короткий воспроизводимый сценарий на важный блок. Длинные стресс-тесты только для конкретной проблемы. **Без платных GitHub Actions**.
6. До P6 можно считать Godot новой игрой-в-разработке, но **нельзя называть её полной заменой Rust**, пока не пройдена приёмка P8. Исходный Rust-архив и отчёты не удалять.

## 2. Архитектурный контракт Godot

```
res://data/galaxy/            # проверенная копия исходных JSON с манифестом
res://scripts/sim/            # независимо от SceneTree: SimWorld + fixed TickRunner
  entities/                  # корабли, станции, рынки, население, фракции, небесные тела
  economy/                   # товары, цены, рецепты, транзакции, контракты
  logistics/                 # маршруты, грузы, докинг, погрузка/выгрузка
  production/                # предприятия, работники, зарплаты, стройки
  strategy/                  # Главы, администраторы, проекты, исследования, AI adapters
  saves/                     # версии схем, сериализация и восстановление
res://scenes/                 # карта, панель станции, инспекторы, интерфейс управления
res://scripts/view/           # выбор, камера, шкалы, отображение; не владение ресурсами
res://tests/                  # короткие headless parity-сценарии
res://debug/                  # лог событий + компактный ZIP диагностики
```

**Одна модель мира владеет цифрами.** Интерфейс только читает снимки и отправляет команду. Корабли не обязаны быть Nodes: они хранятся компактно и отрисовываются пакетно; камера и UI используют родной Godot `Control` / `CanvasItem`. Тики симуляции отделены от FPS, ускорение ×1–×16 не означает умножение скорости передвижения дважды или двойную оплату. Потоки/производительность оптимизируются позднее.

**Правило расчётов:** 1 расход денег → 1 квитанция → 1 фактическое исполнение. Нельзя рисовать выполненную перевозку, строительство, исследование или рост склада только из намерения ИИ. Неизвестная статистика остаётся «—», не нулём. Не создавать параллельный рынок для удобства UI.

## 3. Этапы с точкой приёмки

### P0 — инвентаризация, эталон и Godot-каркас
Сохранить каждую ветку данных и код, распределить источники по ролям. Запустить проект Godot и прочитать без модификации 8 миров и 3 фракции; показать выбор системы и тела. Отдельно проанализировать расхождения `crates/` vs `native/crates/`. Проверить лицензию аудио/графики, не пересылать сторонние шрифты. **Gate:** редактор Godot реально запускает P0 на Windows, в логе 8/3, выбор системы работает. Сейчас код P0 есть, **запуск Godot не подтверждён**.

### P1 — чистая модель, время, сохранение и импортер данных
ID объектов, координаты/орбиты/маршруты, данные систем, экономика без графических узлов; единый `TickRunner` и очередность фаз по `native/crates/sim_server/src/engine.rs`; начальный мир из точных JSON. События, детерминированные снимки и **Godot save → load → продолжение тиков**. Миграция старой SQLite — отдельный поздний пункт, SQLx не переносить. **Gate:** одинаковый мир и счёт объектов после save/load, без самопроизвольной смены ресурсов.

### P2 — экономика, производство и население без транспорта
Все товары и tier'ы (`commodities.rs`), реальные рецепты/побочные продукты, производственные блокировки, цены/спред/ордера, склады/лимиты, состояние предприятий, экипажи/работники и зарплаты, еда/вода/потребление, ремонт/износ, денежный ledger и фракционные финансы. Отдельно учесть два слота модулей предприятия. **Gate:** одна смена фермы/переработки: входы точно списаны, выходы появились, доходы/зарплаты не возникли из воздуха; недостаток входов честно останавливает выпуск. UI показывает склад и причину.

### P3 — корабли, физические маршруты и договоры
Модели кораблей, роли/автономность, физический транзит, топливо, докинг, грузовые лимиты, экипаж (голод/усталость/мораль/зарплата), местные и межсистемные пути, корабельные модули T1–T3 (5 слотов), сканирование/добыча/торговля, репутация, враждебность, контракты всех существующих типов, финансирование и escrow, возвраты/истечение/повтор, восстановление после сейва. **Gate:** реальный физический путь *снабжение → контракт → принял корабль → погрузка → полёт → разгрузка → оплата → склад*. Отсутствие второй выплаты и перевозки 200 единиц при трюме 50.

### P4 — строительство, станции и колонизация
Нативные площадки, стройматериалы, оплаченный труд, создание объекта только после выполнения условий, станционные модули и 4/5/6 слотов по T1/T2/T3, производственный ввод, верфи, заказы, пассажирская миграция, транспорт колонистов, конкуренция за место; орбиты станций и привязка их интерфейса к станции. **Gate:** площадка без материалов остаётся площадкой, доставка и работа реальны, после оплаченного завершения новый объект существует и производит только с входами.

### P5 — ИИ Глав, станционных администраторов и агентские решения
Перенести существующую автономную логику, личности фракций, правила выживания/приоритеты, station staff allocation, долгосрочную память, осмысленную смену направления, объяснимые альтернативы. Базовый автономный планировщик остаётся базой. HTN/GOAP/Beam/гибрид — **реальные сохранённые кандидаты**, но не включать все одновременно без проверки того, что они используют только настоящие возможности мира. Агенты/BT кораблей из `agents/ship/behavior.rs` входят в P3/P5. **Gate:** минимум одна фракция сама закрывает дефицит через реальный контракт и возвращается к сохранённой цели после кризиса.

### P6 — управление игроком, исследования, прогрессия
Делегирование/советы/удержание, уставы фракций, одобрение конкретных предложений и квитанции; реальная наука (ресурсы+работники+деньги), доступные технологии и условия, улучшения T1–T3, модули кораблей/фабрик; колонизационные требования. Учитывать, что часть `strategy/progression.rs` — **чистые проектные правила, а не исполняемый прогресс**. **Gate:** политики реально меняют выбранную работу, Hold не тратит деньги, исследование потребляет настоящие ресурсы; T2 не открывается только от красивого значка.

### P7 — полный Observer и игровой интерфейс
Перенести выбранный стиль Yiotro/Shapez: минималистичная карта систем, глобусы планет, корабли и модульные станции, выбор/следование камеры, пауза/ускорение, окна станции/экономики/контрактов/кораблей/фракций/исследований, шкалы и причины простоев. Просмотреть **оба** источника UI: `native/observer/` и `native/crates/client_bevy/`, плюс уникальные ассеты `crates/client_bevy/`. **Gate:** все ключевые действия и причины видны без обращения к JSON/HTTP, без фальшивых графиков. UI развивать параллельно P1–P6, P7 — итоговая проверка полноты.

### P8 — сохранения, сравнение поведения и первая самостоятельная сборка
Новый формат Godot с версиями, восстановление всех незавершённых контрактов/строек/перелётов, цели ИИ, деньги, тики; проверить отсутствие двойных расчётов. Для старой SQLite (18 SQL-миграций) оставить **возможность одноразового импортера** без переписывания старых файлов. Несколько одинаковых коротких сценариев Rust/Godot; потребление/производство/снабжение/строительство/автономное решение. Автообновление с GitHub, локальная диагностика и Windows-пакет. **Gate:** одна играбельная сборка Godot с работающим автономным миром и кратким отчётом об известных несовпадениях.

### P9 — резерв сохранения уникальных механик и активов
Постатейно просмотреть уникальные/изменённые файлы корневого `crates/`, опыт Bevy-клиента, старые сценарии C1/Genesis, заготовки ИИ, архивы референсов, а также исследование/корабельное оснащение, рынки и экзотические контракты, не вошедшие в P1–P8. Выявить пропуски, добавить задачи переноса или явное документированное решение `PRESERVED_REFERENCE`. **Gate:** у **каждого из 793 исходных файлов** есть смысловое решение, ни один важный механизм не пропал из контроля.

### P10 — будущие механики (НЕ обязательство паритета)
Полное тысячелетнее дерево, T4 мегаструктуры (Сфера Дайсона/военная ветка), масштабная дипломатия, война, планетарная игра, управление фракцией как отдельный 4X режим, альтернативные игровые начала. Это **отдельный дизайн-бэклог**, не путать с уже исполняемой частью Rust. Не тормозить P0–P9 ради нового функционала.

## 4. Срезы удобной приёмки

- **Первая запускаемая Godot:** после P0 — только карта и чтение исходных данных.
- **Первая экономическая:** P1+P2 — реальные запасы и производственные смены, без притворных грузовиков.
- **Первая действительно живая:** P3+P4 — товары едут на кораблях, работают станции, строятся объекты.
- **Первая автономная игровая:** P5+P6 — решения Глав/админов, политика игрока и исследование.
- **Полный кандидат заменить Rust:** P7–P9 с явным списком допустимых расхождений.

## 5. Локальный процесс без Rust-компиляций и платного GitHub

Изменения `*.gd`, `*.tscn`, `*.tres` доступны после `git pull`/скрипта обновления: Godot Editor → F5. Раз в блок — 1 быстрый `godot --headless --path godot --quit` (если доступен исполняемый Godot) и 1 короткий игровой сценарий на ПК. При ошибке — `SAVE_DIAGNOSTICS.cmd` собирает `logs/`, `checkpoint-summary.json` (без пользовательских личных файлов), `manifest.json` (ветка/commit/версия) в ZIP для передачи сюда или через GitHub Issue. Скрипты обновления и диагностики — отдельные задачи P0/P8; пока **не обещаем, что они уже существуют**.

## 6. Что НЕЛЬЗЯ считать автоматически перенесённым

Отрисованный корабль не доказывает перевозку. Значение на складе не доказывает завершённый контракт. Опубликованная ветка технологий не доказывает возможность исследования. Сохранённый JSON не доказывает корректный рестарт мира. Наличие кода HTN не доказывает, что он активен. Отображаемые слоты T2/T3 не доказывают, что их можно построить. Проектный документ T4 — не работающая мегаструктура.

**Работа закончена не тогда, когда папки Rust получили аналоги `.gd`, а когда аналогичные реальные действия воспроизводимы.**

## Дополнение 12.11 — правило использования готовых средств Godot

**До написания кода каждой задачи P0–P10** открываем [каталог инструментов](GODOT_TOOLING_DECISIONS_RU.md) и [базу геймдев-решений](GAMEDEV_KNOWLEDGE_BASE_RU.md). Проверяем: (а) не существует ли штатного класса Godot; (б) нет ли зрелого лицензированного плагина; (в) чем такое решение отличается от нашей Rust-семантики; (г) как одна короткая проверка покажет паритет/нагрузку.

Пример: плавность кораблей = не новая система движения, а [интерполяция снимков для presenter](SMOOTH_MOTION_RU.md); огромное дерево технологий = стандартный GraphEdit, но unlock-условия вычисляет SimWorld; тысячи кораблей = пакетная отрисовка, но не тысячи PhysicsBody/Nodes. Экономика/ИИ/склады/контракты сохраняют точные нативные правила, нет «подходящего плагина» для замены их логики.

**Внешние плагины — только кандидаты.** Не устанавливать в основную ветку без проверки Godot 4.7/Windows-export, лицензии, демо и отчёта о размере/скорости. Результат исследования не увеличивает число VERFIED задач по переносимой игровой функциональности.
