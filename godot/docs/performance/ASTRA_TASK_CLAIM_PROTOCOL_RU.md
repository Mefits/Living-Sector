## Каждый почасовой запуск — настоящий цикл «ВЗЯЛ → КОД → СДЕЛАЛ»

1. Прочитать свежий [список Астры](ASTRA_FIVE_SHIFTS_RU.md), этот протокол и свои прошлые записи `claims/`. Найти **следующий свободный, ещё не реализованный** пункт своего направления. Просмотреть свежие коммиты/PR и соседние claims, чтобы не дублировать уже сделанное. Одна задача = один завершённый проверяемый смысловой блок; если она большая, брать чётко обозначенную самостоятельную часть. Отсутствие локального Godot или прежнего позднего профиля — не запрет писать безопасный экспериментальный код.
2. **Первое изменение в GitHub, ДО чтения/правки рабочих исходников:** создать уникальный файл `godot/docs/performance/claims/<task-id>-<role>.md` в общей ветке с `STATUS: IN_PROGRESS`, ролью, конкретным названием и ID задачи из списка Астры, ссылкой на пункт, стартовым SHA/временем, запланированными файлами и ожидаемым результатом. Успешный create_file — атомарное резервирование; если файл существует/другой владелец работает с задачей, выбрать следующую свободную. Не создавать пустых «в работе» для уже закрытых задач. Вести список задач по состоянию таких файлов и GitHub HEAD.
3. После claim сразу менять реальный код через подключённый GitHub-коннектор, с актуальным blob SHA/CAS, и подготовить targeted negative/regression test. Не завершать запуск одним анализом, правками документации или маленьким handoff при доступном GitHub и свободной задаче. Не плодить бессмысленные микрокоммиты: существенный связанный патч, несколько связанных исправлений если нужны, в границах одного блока.
4. **Сразу после кода:** обновить ТЕ ЖЕ `claims/<task-id>-<role>.md` с `STATUS: CODE_DONE_TEST_UNVERIFIED` либо `VERIFIED` (только после реального теста), SHA кодового коммита, перечнем изменённых файлов, что конкретно исправлено, test PASS/FAIL/NOT_RUN, исходный риск, следующей свободной задачей. При реальном блокере обновить `STATUS: BLOCKED` и точную техническую причину. Не объявлять изменение скорости без измерения. Не оставлять завершённую работу под `IN_PROGRESS`.
5. Короткий отчёт пользователю: «взял ID/название → сделал код SHA → тест / не запущен → следующий ID». Если успеваешь, продолжать следующую свободную подзадачу, начиная с нового claim. Повторяй цикл **каждый час**, не жди VERIFY для написания кода. CI не запускать на каждом коммите: тяжёлые GitHub Actions исключены, до отдельного прямого согласования не запускать никакие Actions. Проверка накопленного кода — утром.
