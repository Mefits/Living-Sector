# Продолжение исправлений накопительного замедления — 17 ноября

По прямому указанию пользователя: без тяжёлых проверок и запуска GitHub Actions. Этот пакет проверен чтением изменений; Godot и профилирование текущей версии НЕ запускались. Среда исполнения сейчас недоступна. Новое ускорение в процентах не заявляется.

## Изменения

1. **N9: устранено удержание цепочки предков.** В новой версии ветки `fork()` сохранял родителя в `_fork_source: RefCounted`. Последовательные применения могли удерживать старые Ledger вместе с их заголовками, балансами и кешами. Теперь хранится WeakRef. Проверка живого родителя и поколения сохранена, общий полный путь проверки истории сохранён. Дочерний Ledger по-прежнему владеет ссылками на свои COW-разделы. Это обнаруженный дефект текущего кода, не доказанная причина исходных Windows-замеров.
2. **N152: пустые тики без экспорта/восстановления всей N9-истории.** Внутренняя стадия использует отдельную COW-ветку. Старение предложений, продление, истечение и возвраты исполняются теми же функциями в прежнем порядке. При реальном изменении выполняется прежний полный commit с аудитом всех кошельков, старых/новых квитанций, ContractBoard и Schema. Внешний `stage(world, snapshot, tick)` сохраняет строгий restore и прежний формат результата.
3. **N91: адресные доказательства финансирования.** Планировщику передаются копии существующих N9-квитанций, на которые ссылаются поставки текущих стройплощадок, вместо полной истории N9. Отсутствующие квитанции не создаются. Исходный `physical_site_funded` и его проверки N15, контрактов и количества не менялись. При применении пачки назначений доказательства собираются один раз.
4. **N39: назначение инженеров без глубокого копирования World.** Копируется заголовок мира, заголовок ships и только изменяемые корабли. Полные завершающие Schema/accounts остаются. При отказе изменения кораблей остаются в отдельной стадии. Уже внесённый другим чатом выход для пустой пачки сохранён.

Сохранены свежие изменения других работников: отсутствие пустых 1024 разделов при fork, поколение происхождения, отслеживание изменённых разделов и ранний выход пустого N91. UI, интерполяция, частоты, баланс и сериализуемые поля не менялись.
