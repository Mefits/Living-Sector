## Обязательные правила

1. **Нет подтверждённого профиля — нет исправления.** Если замер не получен, следующая итерация продолжает измерение или указывает конкретную блокировку; никаких случайных cache/UI/Worker improvements.
2. **Один содержательный пакет — один коммит с кодом, тестом и короткой записью результата**, по возможности. Не делать отдельно commit под тест, commit под handoff, commit под каждую строку. Работать блоками из 5–10 связанных изменений, когда это оправдано зависимостями.
3. Каждый пакет содержит `before SHA / after SHA`, одинаковый seed и тик, `baseline vs candidate ms/tick`, результаты негативных тестов, риски. `[skip ci]` или `TEST_ADDED_NOT_RUN` **не** означает DONE.
4. **Главная метрика:** изменение wall-стоимости *оплаченного игрового тика* по окнам 100/300/600/900/1200+, отсутствие взрывного роста с возрастом мира, exact state parity. FPS Windows, UI freeze — отдельные измерения, не подменять ими скорость симуляции.
5. Изменения не принимаются без измеримого выигрыша в bottleneck либо если ломают физическую экономику и воспроизводимость. Нет ощутимого выигрыша — откатить или не включать в итоговую ветку.
6. Нельзя автоматически перезапускать прежние пять автомаций, менять формулы/баланс/ИИ cadence, отключать Schema/N9/N38 проверки, импортировать `main` без разрешения.
7. **Максимум три активные роли.** Проверяющий создаёт реальный baseline и сообщает пользователю только существенный результат, а не каждый коммит. Ежедневный статус: закрытые measured bottlenecks, сравнительные цифры, какие изменения приняты/отклонены, что дальше.
8. Свежие правки PR262 после проверенного 5829 HEAD — **непроверенные** до отдельного прогона; их нельзя использовать как уже доказанное ускорение.
9. Исходные крупные фиксы 99ab25e9 (N9 parent WeakRef, N152 no-op N9) и 1676db61 (8 N158 world read projections) уже есть. Не дублировать; новый N152 ContractBoard no-op deep copy — отдельно измерить.
