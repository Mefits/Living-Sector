# Living Sector — T1 EnergyCells и разделение газовой цепочки
**Статус:** технический эскиз и отдельный A/B. Не миграция сохранений и не принятый баланс.

## 1. Подтверждённое устройство 0.6.2
- На самом деле `Gas` конкурирует между `crack_fuel: Gas ×6 → Fuel ×4` и `refine_polymers: Gas ×6 → Polymers ×5`.
- При этом уже существует самостоятельный путь `process_ice: Ice ×8 → Water ×10 + Fuel ×5`. Таким образом топливо не обязано производиться из газа.
- В большой симуляции газовые заказы были 50/100 при настоящем трюме Hauler 2000. Испытание совместного изменения 6→5 + крупных заказов [run 43045539397](https://github.com/Mefits/Living-Sector/actions/runs/43045539397) доставило 400 против 200, но не сохранило газ на Земле. Нельзя внедрять пакетную правку без изоляции эффектов.
- Текущее `Commodity::tier()` означает **ступень обработки** (сырьё 1, переработка 2, изделия 3, потребительские 4), а не технологический уровень доступности T1–T3 станции. Энергоячейки могут быть доступны уже на T1, хотя формально являются изготовленным продуктом.

## 2. Малый реальный эксперимент сейчас
**Только одна правка production recipes:** убрать `crack_fuel`, оставить `refine_polymers` на прежних Gas ×6 и `process_ice` без изменений. Уменьшение Gas 6→5 из PR #70 сюда НЕ перенесено; увеличенные заявки 400 тоже НЕ перенесены.

Обязательное требование: если теперь промышленности не хватает Fuel, нельзя выдавать улучшение Gas за победу. Нужно сравнить с baseline оба ресурса, Water, Food, Polymers, Metals, Components, число контрактов и причину простоев. Исходный мир, пользовательские сейвы, тарифы, добыча, числа кораблей и скорость не меняются.

Целевой контроль: real Windows run x16 до ~1250 на той же выбрасываемой физической копии S2 против уже сохранённого baseline 43038799967; результат однократного запуска — диагностический, не приёмка на исходных звёздных расстояниях.

## 3. Как добавить EnergyCells без второго «системного электричества»
Энергоячейки — **перевозимый, хранимый и покупаемый T1-доступный ресурс**, не отдельная абстрактная электросеть. Это сохраняет ограничение 4/5/6 строительных слотов станции и не требует строить отдельный генератор на каждой станции: существующий T1 refinery может иметь энергоячейковую рецептуру, а доставку выполняют реальные корабли.

**Предлагаемый стартовый технологический граф (ЧЕРНОВИК, не текущий код):**

```text
Лёд ──[refinery: без EnergyCells]──► Вода + Топливо
                   │                         │
                   │                         └─► EnergyCells
                   │                             [T1 переработчик, Fuel ×2 → Cells ×8;
                   │                              эта рецептура НЕ требует Cells]
                   └─► Вода ─► Ферма (+ Cells) ─► Еда

Руда ──[добыча без Cells]──► Руда
Руда + Топливо + Cells ─► Металлы
Газ ──[добыча без Cells]──► Газ + Cells ─► Полимеры
Металлы + Полимеры + Cells ─► Компоненты
Компоненты + ... + Cells ─► Электроника / Инструменты
```

Числа `Fuel ×2 → Cells ×8` и новая стоимость металлов/фермы **только тестовые гипотезы**; перед реализацией нужно подобрать их по работающей экономике. Газ и энергия будут разными ресурсами: газ для химии, Fuel для энергии и полётов, EnergyCells для производств.

**Нельзя допускать:**
1. `Fuel → Cells` требует Cells, в результате генератор невозможен без запасов.
2. Добыча льда/руды и рецепт `Ice → Fuel` требуют Cells: после расхода последнего источника мощности цивилизация уже не восстановится (без внешней торговли).
3. `EnergyCells` создаются только на отдельном здании, не помещающемся в 4 слота стартовой T1 станции.
4. Все производства блокируются немедленно при первом дефиците: нужен отдельный механизм приоритета административных потребителей (жизнеобеспечение/вода/питание выше роскоши), иначе авария энергии вызывает цепной коллапс.
5. Нефизические EnergyCells как «множитель без складского списания». Они должны реально появляться и расходоваться через `MarketPricing.supply`, с оплатой смены, учётом спроса, заказами и трассой событий.
6. `Commodity::tier()` трактуется как tech-unlock T1. Для нового ресурса нужна отдельная явная `unlock_tier` или правило прогрессии, не меняющее значения старых категорий.

## 4. Итерационный план (после S2 A/B)
1. **Минимальный каталог:** добавить `EnergyCells` в commodity enum, parser/serializer, базовые цены, сохранив старые строковые идентификаторы и SQLite. Не требовать её в рабочих рецептах сразу. Проверить JSON и migration paths, boot новой/старой базы.
2. **Замкнутость цепочки:** добавить генерацию `Fuel → EnergyCells` с реальным расходованием, не требующую энергоячеек; открыть её на T1 через существующий тип предприятия, без дополнительного обязательного слота. Сначала только один реальный промпт-контракт и короткая доставка.
3. **Поэтапное потребление:** энергетический вход в промышленное производство, затем в фермы и T2–T3. Ввести приоритеты в администраторе на случай дефицита. Исключить базовую добычу и энергогенерацию; прогонять regression на отсутствие deadlock, деньги/товары, устойчивость после depletion.
4. **Балансировка:** один контрольный seed с короткой физикой, затем исходная топология, несколько кризисов. Сравнить EnergyCells/Gas/Fuel/Water/Food, загрузку перевозчиков, реальные издержки и причины блокировок. Пока нельзя делать массовые правки уровня 1000 игровых лет.

**Century Lab:** исходники или доступ к симуляции по предоставленному URL в текущей среде не получены; использовать его можно только после проверки математического совпадения с native Genesis (отдельные market stock, рецептурные циклы, реальные контракты, funding/credits, физическое ETA и T1 ограничения). До этого фактический native-лог — основной источник истины.

## 5. Результат настоящего native Windows A/B — производственная цепочка сама по себе НЕ лечит дефицит

[Windows A/B CI #43054908400](https://github.com/Mefits/Living-Sector/actions/runs/43054908400) SUCCESS: 8 Rust recipe tests, Windows Genesis build, native ~1250-tick runtime, сравнение с архивом базового Golden #43038799967 и downstream stock audit. Этот "success" означает корректное исполнение и анализ теста, а **не успешное лечение** экономики.

| Показатель | Baseline | Gas только в Polymers |
|---|---:|---:|
| Последний тик | 1250 | 1271 |
| Доставлено газа на Землю (native receipts) | 200 | 325 |
| Запас газа Земли в конце | 0 | 0 |
| Gas shortage_ticks Земля | 384 | 489 |
| Газ Alpha в конце | 456 | 408 |
| Fuel Alpha в конце | 10789 | 7902 |
| Polymers Alpha в конце | 2851 | 7735 |
| Fuel Earth в конце | 523 | 445 |

Итог: на фоне немного разной продолжительности отрезка **не подтверждено** улучшение снабжения. На Alpha произошло большое смещение из выпуска Fuel в выпуск Polymers; избыток Polymers при этом не гарантирует снабжения других миров. Это чистые остатки, не изолированные показатели темпа производства, поэтому причинная атрибуция ограничена; однако направление риска очевидно.

**Решение:** PR #71 оставить draft, в main/stable НЕ переносить. Отмена одного рецепта не является оправданной production-правкой до настройки правил объёма производства. И PR #70 (уменьшить gas input и поднять заказы) отдельно не доказал устойчивость. Обе экспериментальные версии — данные для дизайна, а не готовый фикс.

## 6. Что делать вместо глобального снижения добычи

**Приоритет нового шага: спрос-ориентированная регулировка выпуска на заводах.**

Сейчас рецепт выполняется на основе доступных входов, прибыльности и max_batches, но без универсального лимита склада на Fuel/Polymers. Для Food есть отдельный output cap, а для остальных нет. Поэтому простое удаление одного рецепта может перенаправить всю доступную перерабатывающую мощность на другой продукт — наблюдаемое Alpha Polymers ~7735. Это риск ещё до добавления EnergyCells.

Проверить вариант с контролируемым запасом выходного товара: не выпускать Polymers безгранично, когда доступного запаса уже хватает для реального спроса/резерва и контрактных обязательств. Если оно нужно для поставки, резерв и долговые контракты учитываются; нельзя блокировать жизненно необходимое Fuel/Water. Для новых EnergyCells аналогично нужно выделить минимальные запасы для снабжения и приоритетов, а не максимизировать выпуск одного ресурса.

Начать с **одной производственной линии и коротких тестов** на отсутствие бесплатных материалов, корректный спрос/резерв и восстановление выпуска после снижения запасов; затем сравнить stock, реальные доставки и отсутствие простоя нужных заводов. Отдельно, уже после проверки, подключать T1 EnergyCells. Слепое уменьшение MINING_YIELD_PER_CYCLE остаётся отложенным.
