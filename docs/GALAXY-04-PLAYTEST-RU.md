# Galaxy 0.4 — приёмка на ПК (после зелёного CI)

> Экспериментальная версия. Стабильная сборка и старая БД не заменяются.
> Данные Observer Export Diagnostics — снимки API плюс только последние
> 1000 событий браузера; они не являются полным журналом игры.

## До запуска
- Использовать **последний успешный** workflow из ветки Block D,
  а не старый артефакт первого запуска D1/D2.
- Распаковать архив целиком; запускать START-GALAXY.cmd из новой папки.
- Не переносить старую БД; Galaxy 0.4 создаёт отдельную.
- На глобальной карте должны быть **8** звёздных систем и **8 реальных**
  межзвёздных коридоров (не автоматический полный граф).
- Genesis начинает в Sol, Ceti — Alpha Centauri, пираты — в Nadir.
- Все три системы имеют собственные источники Ore, Ice и Gas.
- Ресурсные уровни I–V отображаются; фактический множитель добычи
  по-прежнему x1.0. Природные месторождения неисчерпаемы.

## Контрольные точки

### 500–1000 тиков: старт
- Нет аварии сервера и ошибок JavaScript при выборе корабля, станции,
  планеты и стройплощадки.
- У корабля видны фракция, задача, маршрут/назначение, фактический груз.
- При недостатке данных отображается «—», а не выдуманный прогресс.
- Стартовые корабли могут двигаться по существующим коридорам и не
  телепортируются по отсутствующим рёбрам.
- Экспортировать Diagnostics, если обнаружена странность.

### 3000 тиков: автономность
- Для каждой фракции записать выбранную стратегическую задачу, состояние
  строительства, общий запас продуктов и воды, платежеспособность населения.
- Если есть жизненный дефицит, проверить, появился ли оплаченный договор
  снабжения, назначен ли конкретный перевозчик, завершена ли доставка.
- Зафиксировать долю отвергнутых сделок и причины; особенно
  insufficient_buyer_credits, embargo, stock_short.
- Ceti не должна вынужденно колонизовать Марс из-за жесткого требования
  одновременного наличия Ore+Ice; при доступном домашнем варианте должна
  иметь основания выбрать его (это не железный скрипт).
- Для строительных объектов проверить материалы, транспорт, рабочую силу
  и почему они стоят, а не просто статус waiting.

### 10 000 тиков: устойчивость (только после нормального этапа 3000)
- Есть работающие производственные цепочки и подтверждённые реальные
  доставки; экономика не застряла в бесконечном цикле отказов.
- Финансовая поддержка реально списывает кредиты фракции; нет
  необъяснимой эмиссии CR в логике помощи.
- Запасы продуктов и воды на освоенных колониях не держатся на нуле
  бесконечно, если внутри фракции физически доступно снабжение.
- Сравнить долю завершённых заказов и причины needs_replan,
  stuck/budget/stock_short относительно предыдущих диагностик.

## Что отправить для анализа
1. Сначала **один файл Diagnostics** после 3000 тиков.
2. Если всё достаточно стабильно — файл после 10000 тиков.
3. Если появилась авария, прикрепить конец серверного лога и номер тика.

Запрещено утверждать, что финансовая или стратегическая задача
«вылечена», только потому что Rust CI прошёл или сервер прожил 240 тиков.
