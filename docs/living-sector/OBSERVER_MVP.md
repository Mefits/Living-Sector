# Observer MVP — наша собственная 2D-карта поверх работающей симуляции

**Статус:** экспериментальная реализация в ветке feature/strategy-observer-mvp. Не проверена полноценным Windows runtime до первого smoke test. **Не путать с прежним PR #1**, который добавлял дополнительную панель в исходный 3D-клиент.

## Выбранный способ интеграции

- **Rust sim_core + sim_db + sim_server** — единственный источник истины. Никакой клиентской симуляции торговли/действий фракций.
- Используем **существующий режим** client_bevy --headless, который поднимает Axum на 127.0.0.1:8080 и пишет изменения в SQLite.
- **Наш собственный интерфейс** (observer/) — HTML/CSS/Canvas/JavaScript без внешних зависимостей. Встроен в бинарник через include_str! и открыт по http://127.0.0.1:8080/observer.
- Веб-клиент — прагматичный способ получить независимую 2D-карту без 3D-моделей. Это не окончательное решение по движку будущей игры.
- В Windows preview лежат Living-Sector.exe, priv/, assets/, Start-Living-Sector.cmd. Последний запускает **именно существующий Rust бинарник** в --headless и открывает страницу.

## Сопоставление экрана с исходным кодом

| Что отображаем | Откуда берём | Оговорки |
|---|---|---|
| Системы, координаты | GET /api/report → systems[].offset_x/offset_y | Реальные координаты WorldRegistry |
| Планеты, позиции, биомы | systems[].bodies[] | В BodySnapshot добавлено system_name из BodyIdentity; устранено ошибочное сопоставление по округлённым координатам |
| Контроль территории | bodies[].controlling_faction, contested | **НЕ** system_control: общий цвет системы производный и обозначает присутствие на телах, не официальную границу |
| Врата | facilities[].gate_link.paired_gate_id | Линии только при обнаружении пары объектов в *разных* системах; нет синтетических дорог |
| Позиции кораблей | /api/report → ships[].position + WS positions.entities[] | Приоритет WS; плавное приближение к полученной позиции, без придуманного маршрута |
| Корабль: задача, груз, топливо | ships[].current_goal, cargo, fuel, transit, crew | Не называть «конвоем» без механики конвоя |
| Станции | facilities[]: position, type, condition, faction_id, reserves, abandoned | Показываем только там, где определена система по body_id |
| Экономика | markets[]: supply, demand, shortage_ticks, prices | Количество нехваток — только позиции с shortage_ticks > 0 |
| Население | populations[].facility_location, population_count | Привязка через facilities[].location |
| Фракции | factions[]: id, name, colors.primary | Оригинальные цвета из исходного JSON |
| Журнал | WS type=events → events[] | Только настоящие события из потока; нет заглушек и сгенерированных историй |
| Пауза / скорость | POST /api/sim/pause, /resume, /speed | Значения скорости — реальные world_speed |
| Связь/отладка | GET /api/health | Если сервер отключён — показывать ошибку, не демонстрационную вселенную |

HTTP /api/report опрашивается раз в 18 секунд для сверки полного набора объектов; позиции кораблей приходят через WS значительно чаще. Полноценной временной истории нет; события хранятся только в открытой вкладке.

## Первые функции клиента

- Два уровня: обзор сектора и просмотр выбранной системы.
- Реальные корабли показываются треугольниками цветом своей фракции; без 3D-моделей.
- Планеты, станции и звёзды показаны простыми программно нарисованными значками.
- Drag / mousewheel / click / double-click для карты, поиск и список систем.
- Инспектор корабля, станции, планеты и системы; фракции, товары, запасы, кредиты, цель ИИ.
- Живой журнал событий, пауза и регулировка world_speed.
- Портативный Windows ZIP и запуск через CMD.

## Чего ещё НЕТ

- Настоящих конвоев / эскорта / боёв / добычи на карте отдельными сценариями сверх того, что уже умеет симуляция.
- Политических полигонов, распознавания официального system_control, исторических графиков, сохранения настроек карты.
- Подтверждённой независимой игры и принятой модели игрока.
- Системы персонажа, 3D-моделей, коллизий.
- Доказанного детерминизма, гарантии отсутствия runtime-багов в исходном sim.
- Безопасной удалённой публикации: режим рассчитан на **локальный сервер 127.0.0.1**; админ API upstream не требует авторизации. Не открывать порт в интернет.

## Проверки до слияния

1. На CI: node --check observer/app.js, node --test observer/model.test.mjs.
2. cargo test --locked -p sim_core.
3. cargo check --locked -p client_bevy (включает sim_server и новые встроенные static assets).
4. Windows preview: cargo build --locked --release -p client_bevy; пакет с CMD+EXE+data+assets.
5. На Windows: старт с чистой БД; /api/health даёт 200, /observer открывается, WS соединяется.
6. Выбор Sol/Alpha Cen/Tau Ceti, приближение, корабли/планеты/станции; не рисуем ложные маршруты.
7. Работа на паузе, 1×/4×, обновление запасов, журнал событий, смена выделения.
8. Длительная симуляция и перезапуск с той же БД без потери состояния (отдельный тест, не только UI).

**Критерий приёмки:** можно открыть 2D-карту, увидеть реальные движущиеся корабли и изменения хотя бы одной экономической величины, изучить выбранные объекты и управление временем, без запуска старого 3D-клиента.
