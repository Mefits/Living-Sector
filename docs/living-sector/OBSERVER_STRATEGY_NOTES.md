# Observer UI-1 — стратегия фракций (отдельная ветка)

**Ветка:** `feature/observer-strategy-ui1`, создана от проверенного коммита
`94af279f54b87ceb732910b0a8574758b60014ee` в
`integration/genesis-strategy-prototype` (PR #16).

**Зона ответственности:** только `observer/**`, собственные тесты и этот документ.
Rust/ECS/SQLite/API/STATUS/ASTRA_START_HERE не менялись. Создание и объединение
других PR, миграция базы, режим симуляции — вне задачи.

## Что видно в интерфейсе

- В верхней панели **«Стратегия»** открывает боковой просмотр главы;
  фракцию можно также выбрать нажатием на её имя в боковом списке.
- API `GET /api/strategy` v1 опрашивается каждые 6 секунд **только когда
  панель открыта и вкладка активна**. При сетевой ошибке предыдущий снимок
  остаётся видимым, явно с пометкой «Ошибка получения данных».
- Селектор фракции использует `faction_id` из API; отображаемое имя берётся из
  уже полученного Observer `GET /api/report`, если оно доступно.
- Текущий режим `shadow` / `execute` **только показан**, его нельзя менять из UI.
- Последнее состояние главы: статус, причина (код + человекочитаемая подпись),
  казна, число видимых целей/проектов, тик принятия решения, возраст отчёта.
- Ранжированные кандидаты: категория, товар, пункт назначения, длительность
  нехватки, числовая **оценка алгоритма**. Оценка НЕ является показателем развития
  и не является измеренным результатом проекта.
- Проекты: записи `projects[]` из API, идентификатор native-контракта, статус,
  источник, назначение, товар, количество, исполнитель, текущий резерв оплаты.
  Статус «Опубликован» не означает ни доставку, ни получение товаров.
- Локальная история: разница последовательно наблюдавшихся API-снимков. При
  первом чтении прошлые события не выдумываются; при откате `snapshot_tick`
  локальная история сбрасывается. Между опросами возможны пропущенные статусы.
  Перезагрузка страницы стирает локальную историю. Это НЕ server-side audit log.
- Неизвестные будущие коды статуса, причины и типа цели показываются как есть;
  новая версия схемы отклоняется с явной ошибкой вместо ложного отображения.

### Ограничения текущего API

Из PR #16 доступны только три категории целей: `sustain_population`,
`secure_fuel`, `supply_industry`; один администратор `logistics`.
Реальный портфель пока описывает приоритеты хронических дефицитов, а не
долгосрочные независимые цивилизационные амбиции. История решений и
планы других администраторов в v1 отсутствуют. Возвращается не более
32 последних стратегических проектов на фракцию. UI не дорисовывает
неизвестные объекты, не делает запросы на изменение мира и не генерирует
фиктивные события.

### Почему новые файлы не раздаются напрямую

Исходный `sim_server` регистрирует только `/observer/`, `/observer/app.js`,
`/observer/styles.css`, `/observer/model.js`. Мы намеренно НЕ меняем
`crates/sim_server/src/runtime.rs` и `http/api.rs`: это зона Astra.

Поэтому `observer/strategy-model.js` (чистые функции) и
`observer/strategy-ui.js` (DOM-контроллер) поддерживаются как
**исходники**; `observer/strategy.css` — отдельный исходник стилей.
`observer/build-strategy.mjs` автоматически встраивает их в существующие
`app.js` и `styles.css`. В браузере нужен только обычный `/observer`.

Обновление UI-источников:
`node observer/build-strategy.mjs --write`.
Проверка, что в репозитории сохранён актуальный сгенерированный код:
`node observer/build-strategy.mjs --check`.

## Проверки

Локально с Node 22+:
`node --test observer/model.test.mjs observer/strategy-model.test.mjs`
`node --check observer/app.js`
`node observer/build-strategy.mjs --check`

CI: `.github/workflows/observer-strategy-ui.yml`. Он проверяет только
фронтенд/контракт данных и согласованность бандла, без тяжёлых Rust-тестов.
**Эти тесты не доказывают, что в настоящем мире состоялся рейс.**

### Приёмка вручную (после интеграции)

1. Запустить сервер с чистой тестовой SQLite БД и `DATA_DIR=priv/genesis/data`.
2. Открыть `/observer` в браузере; нажать **«Стратегия»**.
3. Убедиться, что режим по умолчанию — `SHADOW`, фракции можно менять,
   а список целей и причин отражает API.
4. Перезапустить тестовый сервер с `LIVING_SECTOR_STRATEGY_MODE=execute`.
   При реальном долгом shortage может появиться проект; проверять, что
   визуальный статус совпадает с `GET /api/strategy`, а не с текстом UI.
5. Сверить постройку/снабжение и исполнение контракта через реальные API.
6. Отключить сервер: панель должна обозначить ошибку, сохранив последние
   известные данные. Изменить ширину окна; проверить Escape, кнопки,
   выбор фракции, навигацию с клавиатуры и отсутствие горизонтального скролла.

### Дальнейшая интеграция

Если Astra изменит API, сначала согласовать schema_version и смысл полей по
`docs/living-sector/PARALLEL_DEVELOPMENT.md`. Не добавлять скрытых
состояний, придуманных глав/лидеров или визуальной «готовности к развитию».
Спрос на графику и временные PNG/спрайты — отдельный блок, не часть UI-1.
