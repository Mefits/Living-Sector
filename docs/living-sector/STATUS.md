# STATUS — фактическое состояние Living Sector

**Последнее обновление документа:** 2026-11-03.

## Что реально есть

- Форк `Mefits/Living-Sector` от `Kalcode/spaceprojectsim`.
- На момент начальной сверки `main` совпадал с upstream по коммиту `967b9b6`.
- Исходный проект на Rust/Bevy содержит код экономической симуляции, автономных кораблей, фракций, производств, контрактов, базы SQLite, HTTP/WebSocket и визуального клиента.
- Статически изучены выбранные файлы: `client_bevy/src/sim/mod.rs`, `sim_core/src/simulation/spawner.rs`, `sim_core/src/agents/faction_relations.rs`, `sim_core/src/agents/celestial_body.rs`, `client_bevy/src/ui/minimap.rs`, `sim_server/src/http/api.rs`, `sim_db/src/persistence.rs` и другие.
- Ветка `living-sector-dev` содержит только перенесённую документацию Living Sector, если после этого коммита не появлялись другие изменения.

## Что не проверено

- `cargo build`, `cargo check`, `cargo test`, headless smoke и реальная работа приложения на Windows.
- Производительность и стабильность после тысяч дней симуляции.
- Корректность текущих сохранений оконного клиента.
- Полная воспроизводимость результатов при одинаковом seed и действиях.
- Возможность бесконфликтной синхронизации наших будущих изменений с автором.

## Статически замеченные риски (не подтверждённые runtime-баги)

- `client_bevy` и `sim_server` имеют не полностью общую последовательность выполнения тиков.
- Оконный клиент не подключает стандартный фоновый persistence-worker так же, как сервер; `Save As` не равен сохранению актуальных ECS-состояний без отдельного sync.
- Некоторые комментарии и документы описывают этапы разработки, уже изменённые в коде.
- Внутренние события ограничены журналом, полноценный причинный replay не показан.
- Наличие `world_seed` не равно доказанному детерминизму.

## Прототип политической карты (отдельная feature-ветка)

- Добавлен read-only экран Sector с координатами звёздных систем, подписями и цветовой маркировкой контролирующих фракций.
- Соединения отображаются только для реальных пар межсистемных врат, не по близости точек.
- Панорамирование, масштабирование, выбор системы, переключение камеры, закрытие по Esc.
- Никаких изменений экономической, транспортной и фракционной логики.
- ВАЖНО: исходники только статически подготовлены; Rust toolchain недоступен в текущей среде. Компиляция, проверка интерфейса и тесты НЕ выполнялись. До merge обязательна сборка клиента.

## Последняя работа

Ветка документации living-sector-dev содержит видение, идеи, аудит архитектуры, план и handoff. В отдельной feature-ветке добавлен **первый экспериментальный экран стратегической карты**, включая интеграцию с UI. **Системы расчёта мира, экономика, ИИ, CI и конфигурация сборки не менялись.** Компиляция и запуск нового экрана пока не проводились.

## Следующий рекомендуемый шаг

Прогон базовых тестов на фиксированном upstream-коммите, затем отдельный технический эксперимент по запуску и сохранению мира. Не начинать с полной перезаписи визуального клиента.

**Формат обновлений:** дата, изменённые файлы, реально выполненные тесты/проверки, подтверждённые проблемы, открытые риски, следующий минимальный шаг. Не выдавать статический анализ за запуск.
