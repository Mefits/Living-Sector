## Что реально есть

- Форк `Mefits/Living-Sector` от `Kalcode/spaceprojectsim`.
- На момент начальной сверки `main` совпадал с upstream по коммиту `967b9b6`.
- Исходный проект на Rust/Bevy содержит код экономической симуляции, автономных кораблей, фракций, производств, контрактов, базы SQLite, HTTP/WebSocket и визуального клиента.
- Статически изучены выбранные файлы: `client_bevy/src/sim/mod.rs`, `sim_core/src/simulation/spawner.rs`, `sim_core/src/agents/faction_relations.rs`, `sim_core/src/agents/celestial_body.rs`, `client_bevy/src/ui/minimap.rs`, `sim_server/src/http/api.rs`, `sim_db/src/persistence.rs` и другие.
- Ветка `living-sector-dev` содержит нашу рабочую документацию. Ветка `feature/sector-political-map` и черновой PR #1 содержат экспериментальную политическую карту и CI, но не слиты в dev.

## Что не проверено

- Для PR #1 в GitHub Actions **успешно прошли** `cargo test --locked -p sim_core` и `cargo check --locked -p client_bevy` ([первый успешный запуск](https://github.com/Mefits/Living-Sector/actions/runs/41695120507)). Это тесты кода feature-ветки, не самостоятельный Windows smoke.
- `cargo build`/запуск приложения на Windows, headless smoke и реальная работа новых UI-механик не подтверждены.
- Производительность и стабильность после тысяч дней симуляции.
- Корректность текущих сохранений оконного клиента.
- Полная воспроизводимость результатов при одинаковом seed и действиях.
- Возможность бесконфликтной синхронизации наших будущих изменений с автором.

## Статически замеченные риски (не подтверждённые runtime-баги)

- `client_bevy` и `sim_server` имеют не полностью общую последовательность выполнения тиков.
- Оконный клиент не подключает стандартный фоновый persistence-worker так же, как сервер; `Save As` не равен сохранению актуальных ECS-состояний без отдельного sync.
- Некоторые комментарии и документы описывают этапы разработки, уже изменённые в коде.
- Внутренние события ограничены журналом, полноценный причинный replay не показан.
- Наличие `world_seed` не равно доказанному детерминизму.

## Новый Observer MVP (отдельная feature-ветка)

- `feature/strategy-observer-mvp`: собственный 2D-клиент с двумя масштабами карты, движущимися кораблями, выбором реальных объектов и журналом WS-событий.
- Использует исходный headless Rust-сервер через /api/report, /api/health и /ws; HTML/CSS/JS встроены в бинарник по /observer.
- В BodySnapshot добавлено существующее `BodyIdentity.system_name`; сервер распределяет планеты по системам по имени, а не по совпадению координат.
- Добавлена проверка Node тестов адаптера и Windows preview packaging; результаты CI будут отражены в PR.
- Текущая работа **не подтверждена Windows-запуском**; не считать её завершённым интерфейсом.
- PR #1 с ранней картой внутри 3D остаётся отдельным экспериментом; изменения оттуда не переносились автоматически.
