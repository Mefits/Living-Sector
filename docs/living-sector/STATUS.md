# STATUS — фактическое состояние Living Sector

**Последнее обновление документа:** 2026-11-04.

## Что реально есть

- Форк `Mefits/Living-Sector` от `Kalcode/spaceprojectsim`.
- На момент начальной сверки `main` совпадал с upstream по коммиту `967b9b6`.
- Исходный проект на Rust/Bevy содержит код экономической симуляции, автономных кораблей, фракций, производств, контрактов, базы SQLite, HTTP/WebSocket и визуального клиента.
- Статически изучены выбранные файлы: `client_bevy/src/sim/mod.rs`, `sim_core/src/simulation/spawner.rs`, `sim_core/src/agents/faction_relations.rs`, `sim_core/src/agents/celestial_body.rs`, `client_bevy/src/ui/minimap.rs`, `sim_server/src/http/api.rs`, `sim_db/src/persistence.rs` и другие.
- Ветка `living-sector-dev` содержит нашу рабочую документацию. Ветка `feature/sector-political-map` и черновой PR #1 содержат экспериментальную политическую карту и CI, но не слиты в dev.

## Что не проверено

- Для PR #1 в GitHub Actions **успешно прошли** `cargo test --locked -p sim_core` и `cargo check --locked -p client_bevy` ([первый успешный запуск](https://github.com/Mefits/Living-Sector/actions/runs/41695120507)). Это тесты кода feature-ветки, не самостоятельный Windows smoke.
- `cargo build`/запуск приложения на Windows, headless smoke и реальная работа новых UI-механик не подтверждены.
- Производительность и стабильность после тысяч дней симуляции.
- Корректность текущих сохранений оконного клиента.
- Полная воспроизводимость результатов при одинаковом seed и действиях.
- Возможность бесконфликтной синхронизации наших будущих изменений с автором.

## Статически замеченные риски (не подтверждённые runtime-баги)

- `client_bevy` и `sim_server` имеют не полностью общую последовательность выполнения тиков.
- Оконный клиент не подключает стандартный фоновый persistence-worker так же, как сервер; `Save As` не равен сохранению актуальных ECS-состояний без отдельного sync.
- Некоторые комментарии и документы описывают этапы разработки, уже изменённые в коде.
- Внутренние события ограничены журналом, полноценный причинный replay не показан.
- Наличие `world_seed` не равно доказанному детерминизму.

## Новый Observer MVP (отдельная feature-ветка)

- `feature/strategy-observer-mvp`: собственный 2D-клиент с двумя масштабами карты, движущимися кораблями, выбором реальных объектов и журналом WS-событий.
- Использует исходный headless Rust-сервер через /api/report, /api/health и /ws; HTML/CSS/JS встроены в бинарник по /observer.
- В BodySnapshot добавлено существующее `BodyIdentity.system_name`; сервер распределяет планеты по системам по имени, а не по совпадению координат.
- Добавлена проверка Node тестов адаптера и Windows preview packaging; результаты CI будут отражены в PR.
- Текущая работа **не подтверждена Windows-запуском**; не считать её завершённым интерфейсом.
- PR #1 с ранней картой внутри 3D остаётся отдельным экспериментом; изменения оттуда не переносились автоматически.

## Последняя работа

**2026-11-03 — продуктовый курс уточнён:** The Space Project используется как готовое симуляционное ядро, а Living Sector получает собственную стратегическую 2D-карту и Observer-интерфейс. 3D остаётся необязательной диагностической оболочкой. PR #1 с картой внутри старого интерфейса — технический эксперимент, не конечный дизайн. Документы обновлены; в этой ветке симуляционный код не менялся.

## Genesis 0.1 — update 2026-11-04 (Codex handoff)

- Текущий отдельный малый seed: 1 система, 1 фракция, 3 корабля, 6 объектов, 2 рынка. Это **не** завершённая автономная экономика Genesis.
- Подготовлен [полный продуктовый диздок Genesis 0.1](GENESIS_0_1_DESIGN_SPEC.md) с этапами и тестами, а также [короткое поручение Codex](CODEX_GENESIS_BRIEF.md). Значимые открытые решения требуют короткого обсуждения, а не догадок.
- Observer: исправлена визуальная классификация кораблей. Только `transit` отображается движущимся кораблём; `docked`/корабли с `location` без транзита видны в хабе по имени и в инспекторе. Удалено искусственное окружное разведение значков; станции продолжают использовать **свои** данные позиции, в том числе положение орбитального тела.
- Добавлены Node-тесты `shipMapState` и `shipsAtHub`. Отдельная CI проверка Node и seed должна проходить; не считать это подтверждением реалистичности рейсов или полной замкнутой экономики.
- Не реализовано: энергосеть, несколько видов руды, построение нового корпуса и планирование фракцией с проектами. Порядок реализации см. в дизайне.


## Genesis 0.1 — проверенная логистика и передача Codex (2026-11-04)

- Изменения **на GitHub** в `feature/genesis-0-1`. PR #4: https://github.com/Mefits/Living-Sector/pull/4 (draft, база `feature/observer-focused-ui`). Не трогать базовые PR #2/#3 и не делать merge без пользователя.
- Разобран застой стартовых судов: по текущей архитектуре `comms_t1` узнаёт рыночные цены только в пределах одного небесного тела, а рынки Земли и пояса разнесены. Двум грузовикам Genesis seed выдан настоящий `comms_t2`, позволяющий сравнивать рынки одной системы; курьер остаётся на исходной связи. Не «рисовать рейс» в UI.
- `Start-Genesis.cmd` использует новое изолированное сохранение `genesis-logistics-v1.db` и начальную скорость `WORLD_SPEED=1.0`; старые `genesis.db`/`sim.db` сохранены. Launcher всё ещё ставит симуляцию на паузу до открытия Observer: нажать «Продолжить».
- Локализация `food` — «Продовольствие», обобщённый товар; в `Passenger` это техническая заглушка и не показывается как груз. Аналогично `CrewMission` использует placeholder `Tools`. В событиях указаны тип контракта и истинный груз.
- **Подтверждено CI:** Windows run https://github.com/Mefits/Living-Sector/actions/runs/41757573804 завершился `success`; прошёл `Verify real autonomous cargo ship departure at 16x world speed`, помимо Node-тестов и нативной компиляции. То есть **реальный грузовик с собственным AI начал перелёт**. Тест не доказывает успешную разгрузку, выполнение контракта, устойчивый производственный цикл, рентабельность и долгосрочную автономию.
- **Рекомендуемая первая работа Codex:** P0-аудит + end-to-end тест `план → вылет → прибытие → погрузка/разгрузка → проверка дельты остатков и контракта → перезапуск`; найти реальные случаи `idle`, `contract_expired`, ошибки повторного списания. Только потом P1 инварианты ресурсов и P2–P5 по дизайну. Не возвращаться к косметике карты вместо этого.
- **Важное:** seed и `comms_t2` применяются к **новой БД**, уже сохранённый `genesis.db` не перезаписывается и автоматически не мигрирует.

## Genesis Observer — компактная рабочая карта (2026-11-04)

- `observer/index.html`, `styles.css`, `app.js`: один экран вокруг карты. Список систем, слои и журнал открываются по запросу. В малом мире Genesis корабли доступны с нижней полосы; карточка показывает состояние, маршрут, прогресс и груз. В хабе видны корабли, инфраструктура и таблица местного рынка с отмеченными дефицитами.
- Проверки: `node --check observer/app.js`, `node --test observer/model.test.mjs tests/genesis-seed.test.mjs` (24/24). Браузерный smoke с тестовыми ответами HTTP и WebSocket прошёл на 1920×1080, 1280×720, 390×844 и 320×640. Проверены открытие и поиск систем, выбор корабля, обновление транзита, переходы хаб ↔ объект, журнал, пауза и 16×.
- Риск: ручной запуск Windows-билда с этим интерфейсом ещё не проверен. Следующая проверка — на действующем Genesis с реальным потоком состояний и событий.

## Genesis — масштаб объектов и локальные орбиты (2026-11-04)

- На карте уменьшены корпуса кораблей и станций, добавлены разные промышленные силуэты и процедурная поверхность небесных тел. Припаркованные корабли доступны из карточки хаба и полосы флота, а на карте рисуются корабли в транзите.
- Движок считает координаты станции на короткой орбите вокруг родительского тела. Общая формула используется в снимках, транзите, стыковочных координатах и Bevy. Фаза выводится из сохранённого угла тела, отдельная миграция SQLite не нужна.
- Проверены JS (24 теста), Chromium на четырёх размерах и `cargo check --locked -p sim_server` на Rust 1.95. В Windows smoke добавлена проверка радиуса и движения станции относительно Земли. Для движения по орбите нужен обновлённый исполняемый файл. Патч Observer можно применить отдельно.
