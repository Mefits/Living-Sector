# HANDOFF — перенос контекста между чатами и агентами

## Рабочий проект

- https://github.com/Mefits/Living-Sector
- Исходный репозиторий: https://github.com/Kalcode/spaceprojectsim
- Рабочая ветка: `living-sector-dev`.
- Технологический стек **уже существующего проекта**: Rust + Bevy (+ SQLite/egui/API). Не создавать вместо него отдельный Godot-каркас.

## Принятый общий вектор

В настоящее время интереснее строить симулятор живого космического сектора: фракции, экономика, экспедиции, постоянная история, стратегическая карта. **Подтверждено 2026-11-03: использовать существующий код прежде всего как симуляционный движок, а не брать текущий 3D-клиент за основу нового UI.** Главный интерфейс планируется собственный — 2D Strategy/Observer с полноэкранной картой. PR #1 (Sector window) — исключительно технический прототип. Человеческий персонаж внутри корабля/станции остаётся важной возможностью будущего развития, не отвергнутой идеей. Референсы SS13, Stellaris, Starsector, Kenshi, FTL; конкретные детали см. VISION/DESIGN.

## Как начать новому агенту

```text
Продолжаем Living Sector — форк The Space Project на Rust/Bevy.
Рабочая истина — GitHub-репозиторий Mefits/Living-Sector и документы
docs/living-sector, не переписка или устаревший Godot-прототип.
Прочитай AGENTS.md, docs/living-sector/README.md, STATUS.md, VISION.md,
DESIGN.md, ARCHITECTURE.md, UPSTREAM.md и существующий CLAUDE.md.
Сверь ветку, коммит и реальные исходники. Отдели согласованные
направления от идей и непроверенных технических гипотез.
Ничего не переписывай без конкретной задачи. Предпочитай небольшие
модульные изменения, тесты и экономное расходование контекста.
После работы запиши, что реально проверил.
```

## Что особенно легко перепутать

- Старые документы отдельного прототипа на Godot содержали ранние обсуждения; они *не являются* структурой этого форка.
- Раннее архитектурное исследование предлагало C# как вариант нового проекта; **после выбора форка это предложение утратило актуальность**.
- Заявленные тесты/бенчмарки автора не заменяют наши проверки.
- В GitHub публичный fork: не включать секреты, личную информацию или непредназначенный для публикации текст.
