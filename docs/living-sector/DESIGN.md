# DESIGN — направления, по которым есть согласие

**Статус:** документ о намерениях, НЕ утверждённая спецификация механик.

## Подтверждённые направления обсуждения

| Тема | Текущее решение / предпочтение |
|---|---|
| Основа | Использовать существенную часть кода и механик The Space Project, если проверка показывает пригодность |
| Текущий приоритет | Автономная симуляция сектора важнее немедленной разработки персонажа |
| Рендер вне поля зрения | Полноценные модели вдали не обязательны; мир рассчитывается абстрактно |
| Постоянство | Состояние и существенные последствия изменений мира должны сохраняться |
| События | Причинно связаны с состоянием мира, а не просто случайные заголовки |
| Фракции | Самостоятельная деятельность, ограниченные ресурсы и знание мира |
| Окна возможностей | В духе Starsector: другие фракции могут первыми занять объекты, если игрок откладывает решение |
| Карта | Интересна карта в духе Stellaris: системы, соединения, политические зоны |
| Личный режим | Не отбрасывать возможность будущего управления персонажем |
| Экипаж | Автономные специалисты с базовыми физиологическими потребностями, без глубокой социальной симуляции на старте |
| Архитектура развития | Сохранить оригинальную Rust/Bevy основу и возможность интеграции новых систем |
| Процесс | Вести документацию в GitHub; ограничивать расходы лимитов Codex, использовать локальные / автоматизированные проверки |

## Чего этот документ НЕ утверждает

- Создание боевой или дипломатической механики с конкретными формулами.
- Немедленное внедрение полного 2D/3D-режима персонажа.
- Отказ от Godot навсегда: для самостоятельного форка сейчас выгоднее Rust/Bevy, а будущий клиент можно обсудить позже.
- Конкретный технический механизм фракционного ИИ, таймеры, число звёзд, ресурсные модели.
- Полный автоподхват каждого upstream-изменения без проверки.
- Завершённые тесты или готовый билд; их пока нет.

## Правило согласования

В VISION может быть согласован широкий вектор. В IDEAS — любые предложения. Конкретные правила механики добавляются сюда только после согласования с владельцем; после реализации фиксируются проверенные результаты в STATUS.

Главный открытый дизайн-вопрос: **что делает пользователь в секторе как участник, когда управление персонажем ещё не существует?**
