# Observer V5 — модульные станционные комплексы

Дата: 2026-11-07. Отдельная UI-ветка поверх Observer V4 / PR #27. Не меняет ECS, контракты, экономику, SQLite и данные стартовой системы.

## Принцип
**Одна существующая физическая location — один видимый комплекс.** Если по фактическому API на ней есть объект `station`, рисуется станционное ядро + прикреплённые модули реально существующих `Facility`. Никаких новых фиктивных предприятий или станций. Самостоятельные платформы добычи по-прежнему отображаются как самостоятельные физические объекты.

- T1: ядро ромб, 4 слота.
- T2: пятиугольник, 5 слотов.
- T3: шестиугольник, 6 слотов.
- **Сейчас T1/T2/T3 — только визуальное решение по числу реально существующих модулей**, а не апгрейд, новая механика вместимости или утверждённый игровой статус.
- Цвета приглушены, формы унифицированы. Пиктограммы означают функции, а не доказательство, что производственная смена состоялась.
- Развёртка слотов — непрерывный `smoothstep` от приблизительно 1.55× до 3.7×. Размер клика не уменьшается при увеличении зума; метки доступны на ближнем масштабе.
- Клик по ядру открывает все объекты location; по модулю — реальную Facility. Стройка с `site.location=hub.location` присоединяется только к **действительной станции**; при отсутствии станции её значок не скрывается.
- Если число построек больше слотов, лишние остаются доступны в инспекторе и показываются счётчиком `+N`. Это НЕ удаление объектов.

## Ассеты
`observer/assets/station-kit/`: 3 ядра, 16 самостоятельных SVG модулей, 3 состояния слотов, manifest. Отдельный `station-kit.js` — Canvas-компоновщик: он не загружает PDF/изображения в момент рисования и позволяет менять стили без миграции игровых данных. Согласованные формы можно заменить отрисовкой SVG без правок симуляции.

Состав файлов см. `observer/assets/station-kit/manifest.json`. Не реализованные типы ассетов (жильё, оборона, исследования) остаются только библиотекой на будущее.

## Следующий отдельный этап
- Реальный `station_tier` и лимиты слотов/строительств должны появиться в симуляции только после утверждения механики, с миграцией старых объектов.
- Для корректной физики новых станций нужна орбитальная привязка **location** вместо нынешнего хеша каждого `facility.id`; синхронизировать маршруты, docking, construction, snapshots, SQLite. Пока новые location искусственно не создаются.
- Доработать UI на ближнем зуме: полная раскладка слотов, пустые места и текущие стадии строительства; сохранять читабельность около Юпитера при нескольких независимых реальных локациях.
