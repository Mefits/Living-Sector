# Genesis Core — возвращение к универсальному симулятору

**Статус:** первая интеграционная вертикаль, не готовая большая экономика.
**Ветка:** `feature/genesis-core-reuse` от `feature/genesis-0-1`.
**Исходная проблема:** в Genesis Clean коммит `00c2451e03` удалил модули исходного симулятора в пользу нового `src/sim.rs`, после чего разработка повторно создавала независимые корабли, склады, контракты и фракции.

## Архитектурное решение

Genesis — **набор начальных данных + ограничений мира + отдельный Observer**, а **не отдельная реализация экономики**.

```
Start-Genesis.cmd
    | BIND_ADDR / DATA_DIR / DATABASE_PATH / WORLD_SPEED
    v
Genesis-Server.exe                (sim_server/src/bin/genesis_server.rs)
    |
    +-- sim_server::runtime::run()    HTTP/WS, tick loop, authoritative world
    +-- sim_core                     Bevy ECS, ship AI, planning, contracts,
    |                               facility work, markets and factions
    +-- sim_db                       SQLite migrations and persistence
    |
    +-- /observer                   existing 2D browser UI, read-only
    +-- /api/report                 authoritative state
    +-- /ws                         world events / ship positions
    v
priv/genesis/data                 small test seed; never compiled into AI logic
    +-- factions.json
    +-- worlds/sol.json
    +-- tuning.json                world policy, not a special Genesis state machine
```

Исполняемый файл компилируется **из пакета `sim_server`**, без зависимостей `client_bevy` и Bevy GPU/3D, через `cargo build --locked --release -p sim_server --bin genesis_server`. Это тот же tick loop, что вызывается `client_bevy --headless`, а не копия алгоритмов. Сам старый клиент остаётся в репозитории и доступен отдельной сборкой, но не входит в лёгкий архив.

## Выполнено и проверяется

| Возможность | Движок | Реальность / ограничение |
|---|---|---|
| Независимые корабли | `sim_core/src/agents/ship` | ECS agents + GOAP/BT, сохраняются через `sim_db`; корабль летает на основании реальных рыночных возможностей |
| Рынки и контракты | `sim_core/src/economy` | Общие `MarketPricing`, `ContractBoard`; не гарантируют положительную прибыль каждого рейса |
| Объекты и производство | `sim_core/src/agents/facility` | Процессы/рецепты существуют; нет проверенного производства новых **корпусов** за материалы |
| Фракции | `sim_core/src/agents/faction` | Общие финансы, отношения и фракционные правила, **не готов** автономный губернатор развития |
| Сохранение | `sim_db` | SQLite и migrations; данные Genesis Clean JSON не являются совместимым сохранением |
| UI | `observer` + `sim_server/http/api.rs` | 2D карта на живых API; 0.13 Clean имела другой интерфейс, который отдельно потребует адаптации (в ZIP нет её исходников) |
| Автовозврат погибших кораблей | `WorldTuning::auto_replace_retired_ships` | В Genesis **false**: `fleet_loss_unreplaced`, нет бесплатного спавна. У большой тестовой галактики default=true |
| Регенерация небесных ресурсов | `WorldTuning::regenerate_body_resources` | В Genesis **false**: истощённые рудные тела не восстанавливают богатство по таймеру; старый стресс-мир не меняется |
| Выделение мира | `DATA_DIR` + `DATABASE_PATH` | `genesis-core-v1.db` не затрагивает старые DB и JSON-сейвы. Старт — одна система, одна фракция, 3 корабля |
| Windows-доставка | `.github/workflows/genesis-core-reuse.yml` | Отдельная нативная сборка `sim_server`, без музыки, моделей, старого `priv/data` и 3D клиента |

## Что НЕ считать выполненным

1. **Новые корпуса.** `shipyard` в оригинале умеет производить **модули**; нужен общий `HullBuildOrder` (уникальный ID, верфь, фракция, рецепт, резервирование, доставка, длительность, потребление, spawn только после завершения, сохранение). Никакого альтернативного `Sim.phase` для конкретного грузовика.
2. **Общая автономная экономика фракций.** Исходный `faction` занимается бюджетом и политикой, а не полной стратегией распределения добычи/транспорта/снабжения. Нужен planner, одинаковый для всех `faction_id`, политики различаются весами и возможностями.
3. **Пираты.** В первом seed по-прежнему одна фракция: пираты из Clean 0.13 не перенесены. Вторую фракцию вводить через обычный `factions.json`, свои производственные узлы/рынки/корабли, единые правила, а не `PirateScenario`.
4. **Истинная конечность всех сырьевых источников.** Запрет free-respawn решает только корабли. Регулярная регенерация богатства тела через `tick_bodies_regen` теперь также выключена для Genesis. Но **не проверены** `market::tick_markets`, `facility::tick_facilities`, рыночное `production`, денежные трансферы и seed-ресурсы: возможные скрытые инъекции ещё требуют аудита.
5. **Энергетика и комплексная боёвка.** Ещё нет согласованной сети мощности и универсальной модели боевых взаимодействий.
6. **Совместимость сейвов.** SQLite Genesis Core и JSON Genesis Clean 0.13 принципиально различны. Не подменять файл сохранения и не объявлять миграцию выполненной.
7. **CI vs gameplay.** Успешный smoke доказывает сборку, старт оригинальных ECS агентов и реальный первый вылет, но не многодневный устойчивый цикл. Дополнительные integration и soak-тесты ещё нужны.

## Что дальше передавать Astra / Sol / Codex

**P0 (в этой ветке):** единый оригинальный движок, минимальный headless EXE, раздельная БД, маленький seed, предохранитель от бесплатного respawn, тест реального вылета, 2D Observer. Не объединять с веткой Clean автоматически.

**P1: физические инварианты.** Установить единый авторитетный учёт товара по месту: где находится руда — в `MarketPricing.supply`, `FacilityStorage` или в `ShipCargo`; проверить все входы/выходы (добыча, перевозка, контракты, плавка). Взять 2 корабля и 2 независимых места, assert `source_delta + cargo_delta + destination_delta`; запретить появление товара без перечисленного разрешённого процесса.

**P2: общий shipyard workflow.** Расширить существующие модули `facility`, `construction`, `sim_server::engine`, `sim_db` одной механикой заказов корпуса. Любая верфь, любой `faction_id`, любой выбранный класс при наличии рецепта; инвариант `spent materials + consumed fuel + elapsed time => one persisted hull`.

**P3: универсальный faction planner.** Получает реальные shortage/bottleneck от компаний/объектов, предлагает новые перевозки и строительство через общую очередь задач и проверяемые бюджеты. Две идентичные фракции с различными ID обязаны иметь одинаковые возможности; различия поведения — в предпочтениях, активных знаниях и ресурсах.

**P4: два разных стартовых уклада.** Добавить пиратскую фракцию и объективную нехватку ресурса в отдельный seed; заставить оба мира использовать **те же** типы рынков, помещений, топлива и обслуживания. Различие агрессивности — стратегическое правило, не закрытая пиратская экономика.

**P5: ограничения.** Истощение месторождений, энергобаланс, ремонт, топливо, логистика; наблюдаемая цепь причины → задачи → траты → результат / застревание.

**P6: combat.** Только после общих кораблей и снабжения — единые средства обнаружения, вооружение, повреждения, выбор цели, риск и расход боезапаса.

## Тесты принятия архитектуры

- Новый грузовик создаётся только через общий заказ верфи и использует **тот же** AI, что начальные; не меняем `src/ship.rs` под имя конкретного корабля.
- Два `faction_id` с одинаковой инфраструктурой способны выполнять равные экономические действия.
- Указание 2 одинаковых складов/шахт не требует отдельного кода и создаёт два разных состояния.
- Ни одна сторона не может одновременно забрать один зарезервированный физический ресурс.
- Деактивация free-respawn относится только к данному миру (policy), не ломает старую галактику.
- Новый корпус, снабжение и логистика переживают shutdown/restart без удвоения.
- Интерфейс получает только авторитетные данные от API; нет сценариев, генерируемых фронтендом.

## Как разворачивать

Распаковать Windows ZIP в **новую** папку и запустить `Start-Genesis.cmd`.
Все данные лежат в `genesis-core-v1.db`. Не переносить в неё `genesis-clean-v1.json` или старый `genesis.db` вручную.
Для продолжения прогресса той же ветки использовать сохранённый `genesis-core-v1.db` после корректного закрытия сервера (Ctrl+C).
