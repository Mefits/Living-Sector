# Living Sector — единая интеграционная база (07.11.2026)

## Зачем
Временный билд «6 систем» включал актуальное ядро Astra F4, но **не содержал Observer V5 и экономического hotfix**. Визуально это выглядело как откат. Здесь код и данные сведены в **единую тестовую ветку**, не изменяя исходные ветки команд или main.

## База и интегрированные изменения
- Astra стратегия S1–S7, экономика F1–F4, из ветки `feature/genesis-construction-executor`, PR #34 и цепочка родителей;
- Observer V4/V5 и стратегическая панель — `integration/genesis-f2-observer-v5-windows-test-20261107`, PR #31, через PR #36;
- Hotfix платёжеспособности населения, частичных продаж и расхода воды — `fix/f2-liquidity-population-sales-20261107`, PR #33, через PR #36;
- Исправление орбитального следования стройплощадок — PR #28, влито через PR #37;
- Минимальный мир из 6 систем + утверждённые решения по T1/T2/T3 — `feature/genesis-six-systems-start-preview-20261107`, PR #35.

## Состав новой чистой базы
- 6 систем: Sol, Alpha Centauri, Tau Ceti, Vega, Barnard's Star, Lalande; 36 тел из исходного набора (к Sol также добавлен Callisto из Genesis).
- Фракции: Терраны (Земля), Пираты (Юпитер), Ceti Freeholds (Alpha Centauri).
- Каждая: 1 станция + 2 отдельных native объекта-представителя примитивных модулей, 50 жителей, 1000 еды и 1000 воды, 1 грузовик-**заменитель будущего шахтёра**.
- Запускается через `Start-Genesis.cmd`; **новый** файл `genesis-six-systems-preview-v1.db`, `LIVING_SECTOR_STRATEGY_MODE=execute`, после старта симуляция стоит на паузе.
- Observer V5 с ассетами станций и модулей, масштабированием и стратегическим инспектором. Эти изображения отражают реальные native facilities, но визуальные T1/2/3 ещё **не являются игровой системой апгрейда**.
- **Торговые межзвёздные маршруты пока не созданы.** Добыча фракциями из тел, доступность ледяных ресурсов и производственных циклов на таком минимальном старте пока не проверены полноценным длительным тестом.

## Критически незавершённое (не маскировать под готовое)
1. Иерархия «глава задаёт вектор → самостоятельный **администратор каждой станции** выбирает модули, рабочие смены и производство». Нынешние «логистический/строительный администраторы» работают на уровне фракции.
2. Реальная система станционных модулей, предельных слотов 4/5/6 и населения 100/200/300, запас 5000 каждого товара, неполная мощность производства.
3. Сбор астероидных/планетарных ресурсов независимыми шахтёрскими кораблями. Freighter не должен считаться уже реализованным шахтёром.
4. Прирост/сокращение населения от потребностей; полноценная стартовая замкнутая экономика, требующая food/water/fuel/metals и строительства новых судов без торговли.
5. Возможность физического перехода между системами: карта содержит тела, но навигационные ворота в тестовых seed не настроены.
6. Правильное долгосрочное экономическое поведение при расширении до десятков станций, контроль денежной массы и отсутствие скрытого бесплатного spawn.

Полная договорённость по дизайн-решениям: [GENESIS_START_6_SYSTEMS_PREVIEW.md](GENESIS_START_6_SYSTEMS_PREVIEW.md).

## Правила дальнейшей разработки
- Эта ветка — точка сборки/тестов **единого проекта**, а не автоматический merge всех черновых PR в main.
- Новые изменения Astra и Observer вливать сюда отдельными проверенными небольшими PR; сохранять native ECS и SQLite, не начинать второй симулятор.
- Не передвигать прежние рабочие ветки. Переходить к статусу «стабильная» только после тестов и ручной проверки Observer + симуляции с чистым сохранением.
- При ревью проверять соответствие между **визуально представленными** модулями и **реально работающими** предприятиями.
