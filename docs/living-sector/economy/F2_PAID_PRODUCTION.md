Проверенный код: `c8cdf69dd94eb42963529f5e2c404ccd984d1936`.
[CI 42316233684](https://github.com/Mefits/Living-Sector/actions/runs/42316233684) — success.
Это база для новых независимых экономических инструментов. Уже существующий
Observer не перебазировать автоматически; PR не слиты.

## Реализованный результат

1. Native рецепты, добыча, самостоятельный ремонт и производство модулей требуют
   оплаченной смены до изменения запасов. Нехватка работников, денег или сырья
   блокирует работу; диагностическая причина доступна в snapshot.
2. Работники — существующее агрегированное население той же локации и фракции.
   `FacilityCrew.crew_count` означает число рабочих мест, а не отдельных людей.
   Их питание учитывается населением один раз; мораль предприятия следует
   удовлетворённости питанием работников последней смены.
3. Зарплата переносит реальные CR в `PopEconomy.total_wealth`. Потребление
   возвращает деньги владельцу рынка. Тест показывает повторную смену после
   продажи продукции населению без дополнительного денежного вливания.
4. Один житель не занимает две смены в одном тике. Оплаченная смена хранится
   в native crew JSON вместе с денежными изменениями через EconomicFrame/SQLite.
5. Общий склад сохраняет своего владельца. Для переработки его ресурсов он
   оплачивает труд и маржу производителя; готовый товар остаётся владельцу склада.
   Верфь, выпускающая собственные модули, сама покупает входные материалы и платит
   зарплату. Скрытой передачи права собственности на общий рынок нет.
6. Legacy MarketFlow больше не создаёт и не расходует товары в обход предприятий.
7. Свежий Genesis получает шесть групп населения и явный стартовый капитал
   1000 CR на группу. Это только seed, не периодическая эмиссия/спасение предприятия.
8. Занятость сохраняется в существующем столбце SQLite. Новых таблиц нет.

## Прототипные правила и интерфейсы

- Доступная рабочая сила: floor(60% населения). Зарплата: 1 CR за работника/смену.
  Требуется полный штат; частичная загрузка пока не реализована.
- Порядок работодателей и групп населения детерминирован по ID, а не результат
  конкурса зарплат. Это техническая первая модель найма, не завершённый рынок труда.
- Саморемонт использует смену и может отложить производство этого объекта.
- При обработке чужого местного склада маржа — ceil(10% зарплат). Поле
  `processing_fee` содержит весь платёж склада (зарплата + маржа), не только маржу.
- Нормы потребления населения теперь задаются на 1000 жителей за цикл.
  Старые значения seed/сохранений необходимо оценивать с этой семантикой.
- `/api/facilities`: добавлены `crew.work_shift` (nullable) и
  `crew.work_blocked_reason` (nullable строка). Смена содержит `tick`,
  `workers: [[population_id, count], ...]`, `wages`, `input_payment`, `processing_fee`.
  Это последняя успешная смена, не журнал всех операций и не обещание занятости
  в текущем тике. Причина отказа может описывать более позднюю попытку.
- `/api/populations`: добавлено `employed_fraction` — доля доступной рабочей силы,
  занятой на последнем рабочем тике, не доля всех жителей и не постоянный контракт.
- `/api/strategy` не менялся. Observer читает поля, но не вычисляет payroll сам.

## Проверки и пределы доказанного

CI: четыре core workforce-теста, два теста модулей, 26 тестов transaction-модуля,
включая реальный payroll → PersistenceWorker → SQLite → новый World.
Checkpoint также запускался отдельным фильтром: не считать этот повтор новым тестом.
Сборка genesis_server прошла. Свежий execute-мир: на тике 41 шесть групп населения,
десять предприятий с оплаченной сменой, обе фракции представлены. Smoke ограничен
35 секундами / 160 тиками, длинного балансового прогона не было.

Тест локального оборота денег не доказывает устойчивость всей экономики, окупаемость
каждого производства или полный цикл торговли с автономным перелётом. F1 отдельно
проверяет реальную продажу корабля и checkpoint. Windows/Observer не собирались.

## Совместимость и следующая работа

Старый crew JSON читается благодаря serde defaults. Пользовательские БД не менялись.
Сохранение Genesis без населения загрузится, но производство остановится с
`insufficient_workers`. F2 не добавляет жителей/деньги скрытой миграцией в старую БД.
Для воспроизведения F2 нужен отдельный новый мир; старое сохранение сохранять отдельно.
Это совместимость формата, а не обещание прежнего экономического поведения.

Следующий содержательный блок: строительные трудозатраты и выплаты после доставки
материалов; затем кадровые требования сервисных объектов. Док/заправка/ворота пока
не требуют оплаченной смены. Жильё, траты экипажей кораблей, полноценные трудовые
контракты и управляемая эмиссия не реализованы. Нет оснований объявлять экономику
или стратегический ИИ полностью завершёнными.

## Границы параллельной разработки

Владелец ядра: `agents/facility/**`, `agents/population.rs`, `agents/market.rs`,
`economy/**`, `sim_db/src/persistence.rs`, `sim_server/src/engine/**`,
`priv/genesis/data/worlds/sol.json`, общий workflow и верхние handoff/status документы.
Не редактировать эти файлы одновременно из независимых веток.

Можно независимо делать Observer-карточки работников/зарплат/отказов,
визуализацию целей и offline-анализ `money_accounts` в `tools/economy-diagnostics/`.
Диагностические fixtures размещать в `tests/economy-diagnostics/`, без изменений
ядра/общего CI. Риск конфликтов: изменение shared DTO, семантики рабочих мест,
порядка tick, seed и общей документации. Новые поля API обсуждать перед реализацией.
