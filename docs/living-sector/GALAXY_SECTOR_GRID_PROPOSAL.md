# Предложение: галактическая сетка 100 св. лет в Living Sector

**Статус:** концепция для будущего масштабирования, не часть уже работающего Genesis seed. Пользователь предложил переиспользовать подход из Elite Dangerous BioAtlas.

## Источник идеи

В BioAtlas была сетка районов поиска (уровни 500/250/100 св. лет) и каталог галактических объектов. Размер `atlas.sqlite` около 500 МБ был связан прежде всего с каталогом систем и планет, а не с геометрией сетки. Отдельная предварительно агрегированная heatmap могла быть на порядки меньше (в одном из экспериментов ~1.2 МБ для конкретной выборки); эти объёмы **не следует экстраполировать** как постоянную стоимость всех карт.

## Разделить масштабы

- **Галактика / секторная карта:** реальные для *нашей симуляции* координаты звёзд, границы и известность секторов, влияние фракций, логистические/политические зоны. Клетки сетки — вычисляемая геометрия, а не отдельная текстура на диске.
- **Система:** планеты, орбиты, станции, шахты, корабли и физические поставки. Сетка 100 св. лет здесь **не применима** — она огромна относительно локальной системы. Можно использовать лёгкую декоративную навигационную сетку без заявленных физических единиц.
- **Объект/производство:** проекты, запасы, энергия, ресурсы, доступность технологического оборудования.

## Схема данных без загрузки гигантского каталога

Для 3D координат `x,y,z` в световых годах, вычислять `sector_x = floor(x / 100)`, `sector_z = floor(z / 100)` и, по необходимости, `sector_y = floor(y / 100)`. Для двумерной галактической карты показывать X/Z, а Y — высота/фильтр. Осмысленно поддержать LOD 500/250/100 ly (на сетке 250 не обязательно является кратным 100; вычислять уровни отдельно).

Хранить **только заполненные или открытые** фракциями ячейки, с небольшой агрегированной статистикой: реальные системы, известные источники сырья, владелец/спорность, количество пунктов добычи, инфраструктура, время/качество наблюдения. Не создавать миллионы пустых строк и не переносить весь каталог планет из BioAtlas.

Пока в Genesis одна Sol, отображение большой галактической сетки почти ничего не добавит. Предусмотреть архитектуру координат и будущий экран; заполнять реальные сектора по мере расширения мира. Никаких случайных точек, выдаваемых за настоящие звёзды.

## Обновление/подгрузка и размер

- Область интереса + уровень детализации → ограниченный диапазон ячеек/данных; не сериализовать всю галактику в `/api/report`.
- При масштабировании сначала выводить компактные агрегаты, затем реальные системы; информацию о планетах загружать только при входе в систему.
- Добавить измерения ZIP и памяти на реальном тестовом наборе, а не обещать фиксированный объём.
- Если будет решено использовать координаты/каталоги из Elite Dangerous/Spansh, **отдельно проверить лицензию, происхождение и ограничения распространения**. Для самостоятельной вселенной достаточно собственного мира и тех же геометрических принципов.

## Отношение к текущему UI-патчу

В Genesis-map UX обновляются узнаваемость планет, хабов, кораблей и сдержанное оформление. Это не внедрение галактической сетки из BioAtlas и не импорт `atlas.sqlite`. Данные симуляции остаются из Rust/SQLite, фоновые звёздные точки исключительно декоративные и не кликабельные.
