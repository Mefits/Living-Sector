# S2 — подхват существующего заказа предприятия диспетчером

## Основание

Реальный Genesis x16, чистая SQLite, Windows workflow 43011866774 и cached WS/API triage 43018334495. На Earth Station у Genesis Initiative (`terran-authority`) газ = 0 к тику 1806, не принят ни один из пяти газовых контрактов из Alpha Station. Подтверждённый T2 Hauler (`ship-terran-authority-hauler-5`) занят другим реальным оплачиваемым контрактом: `contract-8`, 100 металлов Earth → Alpha; фактический ETA ~1970, после конца окна S1.

Вывод из фактов: дефицит не означает зависание дальнего корабля; свободные T1 суда не могут видеть межзвёздные обычные контракты. Простой статус Posted не означает исполнения.

## Исправление — только имеющиеся средства

1. После 180 native тиков неисполненный `Delivery`, **реально предоплаченный предприятием** (`FundingSource::Facility`, escrow reserved > 0), допускается к выбору штатным station dispatcher. Это не новый контракт и не новый кошелёк. У существующих private pilots до этого периода доступ к рынку остаётся прежним.
2. Диспетчер ищет свободный корабль **той же фракции**, проверяет дипломатические запреты, необходимый грузовой объём, фактический запас/цену источника, существование маршрута, личные средства корабля, положительную маржу, платёж по настоящему контракту и право предприятия оплатить escrow top-up из реального счёта. Для межзвёздных обычных заявок **не обходит sensor gate T1/T2**.
3. Если нет корабля, order показывает причину. При отсутствии назначенного исполнителя рыночный контракт **остаётся открытым** частным перевозчикам; при назначении только этот корабль имеет право принять заказ в течение нормального lease. Если не принял — lease освобождает заявку.
4. Глава получает точный read-only `GoalAssessment.pending_delivery` и различает unassigned, stale, assigned и accepted. `options::alternatives` больше не заменяет реальный blocker бессодержательным `administrator_busy`. Duplicate/credits/stock controls продолжают работать.

## Границы

- Не изменены модули/пороги сенсоров, сама экономика/цены, дальности, орбитальные станции, интерфейс или планеты.
- Не назначаем корабли, которые сейчас выполняют другие контракты; не отменяем `contract-8` до ETA.
- Невыполненный заказ **не считается успешной поставкой**. Нельзя объявлять Golden-v1 пройденным без native `Accept → Buy → Deliver` на конкретном газовом контракте и отдельного causal relief.
- Не разворачиваем изменения в `main`, стабильные ветки или пользовательские базы SQLite. Отдельная рабочая ветка плюс draft PR.

## Принцип для будущего планетарного слоя

Здесь не появилось ни `planet`, ни второй экономики. Диспетчер работает на уровне существующих `location/market/owner` — это позволяет в будущем обсуждать планетарные узлы отдельно, после стабилизации.
